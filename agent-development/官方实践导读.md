# 官方实践导读：学习教法，也学习工程判断

核对日期：2026-11-12。本系列参考官方教程与工程文章，但按“已会 Web 全栈和模型 API”的起点重新设计。下面分清参考了什么、怎样落地，以及没有照搬什么。

## 先看优秀教程怎样安排学习顺序

| 资料 | 值得借鉴的教法 | 本系列如何采用 |
|---|---|---|
| [Hugging Face Agents Course](https://huggingface.co/learn/agents-course/en/unit0/introduction) | 基础概念之后再接框架、案例与最终项目；练习检验理解 | 00～07 先弄懂原理并亲手实现；10 才接框架，13 整理作品 |
| [Microsoft AI Agents for Beginners](https://microsoft.github.io/ai-agents-for-beginners/) | 围绕学习目标、使用场景和配套代码组织主题 | 每章用一个问题推进，配能运行的小实验；不把全部主题与平台变成前置 |
| [OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling) | 将模型请求、应用执行和结果回传按步骤展开 | 03 先完成一次往返，04 再把同一机制扩成循环 |
| [Anthropic Building effective agents](https://www.anthropic.com/research/building-effective-agents) | 区分预设工作流与动态决策，从可解释的简单结构出发 | 01 比较同一任务的三种实现，基础项目保持单 Agent |

我们借鉴的是递进方式，不按教程章节数量、框架清单或证书流程原样复制。微软和 HF 的课程涉及更广的生态，本系列先用 TS 与一个熟悉的小项目降低语言和业务切换成本。

Anthropic 的较早文章适合学习架构判断；其中当时的模型能力和工具状态不能直接当作今天的接口说明。具体代码以当前核对的 API 和章节明确的依赖版本为准。

## 工程文章要变成项目中能检查的行为

| 当前问题 | 官方参考 | 采用的做法与位置 |
|---|---|---|
| 工具说明不清，参数容易出错 | Anthropic：[Writing effective tools](https://www.anthropic.com/research/writing-tools-for-agents) | 03 明确工具用途、Schema、结果和错误；程序单独校验 |
| 资料越来越多，模型仍答不好 | Anthropic：[Effective context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) | 05 按需检索与读取，区分上下文和程序状态；09 再分析检索环节 |
| 回答流畅，怎样判断真的完成？ | Anthropic：[Demystifying evals](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) | 07 同时看结果、轨迹和资源最终状态，不要求唯一工具顺序 |
| 改完之后如何比较？ | OpenAI：[Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) | 07 固定任务和评分，12 留出独立题；小样本不包装成泛化结论 |
| 怎样防止资料变成越权命令？ | OpenAI：[Safety in building agents](https://developers.openai.com/api/docs/guides/agent-builder-safety) | 05 把外部正文当资料，06 由程序校验并由用户确认写入 |
| 分支与状态变复杂怎么办？ | LangGraph：[Quickstart](https://docs.langchain.com/oss/javascript/langgraph/quickstart) | 10 用真实框架复现已懂的固定流程，再判断是否值得引入 |
| 工具怎样跨进程提供？ | MCP TypeScript SDK：[Server](https://ts.sdk.modelcontextprotocol.io/server)、[Client](https://ts.sdk.modelcontextprotocol.io/client) | 10 实际发现并调用只读工具，明确协议不代替模型选择与权限 |

采用这些方法，不意味着所有能力已经得到真实模型验证。例如，参数边界可以离线测试，模型是否更会选词和忠实回答，仍需另做模型评估。文档中的实现练习与真实效果证据分别记录。

## 怎样继续读原文？

先完成 03 的一次工具往返，再看 Function calling 对照请求字段。遇到选工具问题，读工具设计文章；遇到资料与状态问题，读上下文文章；开始比较质量，再读评估文章。不必先读完所有来源才动手。

阅读时分三层：可迁移的工程原则、案例成立的条件、会变化的产品操作。核对时，OpenAI 上述评估与安全页面带有相关产品迁移或停用提示；这里使用评估和数据边界的原则，不依赖旧平台界面或旧模型推荐。

本系列的“先通识、后岗位补强”和费曼式解释，是针对你的起点作出的教学选择，不是声称这些机构使用同一个课程模板。课程以亲手完成、能够复述和留下证据为完成标准。
