# Web 开发者的 Agent 工程实践

你已经会开发 Web 应用，也会调用大模型 API。接下来要学的，是让模型参与一条可以检查、可以停止、可以交付的执行流程。

这个系列使用一个独立项目：**本地学习笔记助手**。它搜索和读取 Markdown，回答问题、整理资料，并生成需要确认的修改建议。它不依赖 Mini CMS，也不要求先读旧的 `ai/` 笔记。

## 一条项目主线，两种 Agent

```text
你提出需求
  → 开发 Agent 帮你实现、测试和交付软件
  → 得到一个“笔记助手”程序
  → 笔记助手调用模型与文件工具，帮助用户处理笔记
```

后文用“开发 Agent”指帮你写代码的工具，用“笔记助手”指正在开发的应用。多个开发 Agent 协作，不意味着笔记助手内部也必须有多个模型角色。

## 怎样学：讲明白，再动手，再复述

每章先从一个问题出发，用熟悉的事物建立直觉，再落到实际文件和数据流。类比是梯子，理解后还要能说出真实机制。

例如，把工具调用理解成“值班员填写取书单”后，还应能解释：**模型只返回工具名和参数，Node.js 才会执行读取，结果还要再次交给模型。**

动手后，合上文档，用两三句话向一个没学过的人解释本章。卡住时回到对应的输入、执行代码和输出，不用背术语。

涉及分工、循环和状态判断的章节配有 Mermaid 流程图。矩形表示动作，菱形表示条件，回箭头表示反馈；时序图从上往下读时间。图用于解释现有实现，条件与上限以代码为准。

想对照官方资料，按[官方实践导读](./官方实践导读.md)查 OpenAI、Anthropic、Google Cloud 和 Microsoft 的对应主题。它说明本系列采纳了什么，以及哪些内容暂时不引入。

## 先看到一次完整结果

从学习笔记仓库根目录执行：

```bash
cd agent-development/code/note-agent
npm ci
npm run demo
```

环境是 Node.js 24.14+ 的 24.x 版本。演示用模拟回复代替云端模型，但搜索、阅读、生成建议和写入临时副本都真实执行，不需要 Key。

真正调用模型的方法见[项目 README](./code/note-agent/README.md)。模型使用云端 API；“本地笔记助手”不等于本地模型，笔记内容会随请求发送给模型。

## 项目边界与完成标准

第一轮只做 CLI、顶层 Markdown 文件、关键词搜索、一次任务内的连续执行和确认修改。代码使用 TypeScript + Node 内置模块；没有登录、数据库、向量数据库、多 Agent 产品架构和 Web 后台。

核心完成标准：

1. 有资料时能读到来源并据此回答；没有资料时能说明缺少证据。
2. 可以根据多篇笔记整理答案，而不是只复述一篇。
3. 修改先生成建议；只有人明确确认后，程序才写回原文件。
4. 参数错误、工具失败、过期建议与轮次耗尽都有可观察的结果。
5. 能用测试证明程序约束，用评估样例检查模型行为。

配套代码已经包含这些功能的实现路径。前两项涉及真实模型质量，必须由[评估表](./evals/用例与记录.md)验证，不能仅靠代码存在或离线测试通过来宣布完成。

本系列提供开发协作练习与 CI 模板，不声称已在你的账号上运行多 Agent、创建 PR 或完成云端 CI。Git 操作练习在复制出去的独立项目进行，学习笔记仓库仍按根目录约定维护。
