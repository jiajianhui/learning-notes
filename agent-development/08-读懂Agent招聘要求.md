# 08. 读懂招聘要求：你要进入哪一类 Agent 岗位？

## 先看工作内容，再看“Agent 工程师”这个名字

完成前面的项目后，你可能打开招聘网站，看到 Python、RAG、MCP、强化学习、Kubernetes 一起出现，又觉得自己需要从头学一遍。

先别把不同岗位的要求合成一个人。餐厅里的厨师、店长和厨具工程师都与“做饭”有关，但训练路线不同。Agent 应用、运行平台和模型算法也有这样的分工；一家小团队可能兼任几项，大团队则可能拆得更细。

下面是 2026-11-12 查阅的公开样本。它用于说明工作差异，不是岗位数量统计，也不保证岗位仍在招聘。原始招聘链接和样本限制放在本章末尾，按需查看。

| 方向与样本 | 招聘内容体现的重点 | 对你目前的意义 |
|---|---|---|
| 应用工程：百度大模型研发校招、Juro AI Engineer | 模型接入、工具与业务系统、检索、交付与质量 | 最接近现有 Web 全栈经验；Juro 是有经验岗位，不能当初级门槛 |
| 平台工程：百度 Agent Infra 高级研发 | 云原生、执行环境、分布式系统、稳定性 | 可作为后续方向，不需要先学完这一套才做应用 |
| 算法与模型：百度 Agent 算法实习、智元机器人 Agent 算法 | 训练框架、模型优化，或机器人多模态规划 | 必须补相应算法与领域知识，基础笔记项目不能替代 |
| 框架工程：Mastra AI Engineer | 已上线 Agent、调优与评测、框架能力 | 值得参考“拿证据说明效果”，不要求初学者自己造框架 |

## 哪些能力要现在补，哪些按岗位选？

我们选择**Agent 应用工程**作为主方向。原因很具体：你已经能把用户需求变成页面、接口和数据流，现在需要把“会出错的模型决策”纳入这个系统。

| 能力 | 你已有的起点 | 本系列补强位置 | 完成后能拿出的证据 |
|---|---|---|---|
| 模型与工具协作 | 调用 API、校验请求 | 02～04 | 自己写的工具往返与循环 |
| 上下文与资料检索 | 查询与数据处理 | 05、09 | 搜不到的例子，以及改进前后结果 |
| 权限与可靠执行 | 鉴权、事务、异步任务 | 06、11 | 拒绝过期写入、去重与恢复实验 |
| 框架与协议 | 路由、状态、客户端/服务端 | 10，按技术栈需要 | 普通函数与图工作流对照、MCP 往返 |
| 评估与诊断 | 测试、日志 | 07、12 | 逐题证据、失败原因、留出组结果 |
| 项目表达 | 需求拆解与交付 | 13 | 可复现项目说明与取舍记录 |

这些行的优先级不是招聘频率统计。例如，百度应用样本明确要求 Python；Juro 样本强调 TypeScript/Node.js。本系列全程沿用 TS/Node.js，不要求学习 Python。以后只有目标岗位明确需要时再补语言；这份样本不能推出“做 Agent 都得先学 Python”。

同理，掌握一个框架不等于需要学齐框架列表。面试官问“为什么使用它”，你至少要能指出它承担了哪段状态或执行逻辑，以及不用它会怎样实现。

## 用一份真实 JD（职位说明），决定自己的下一步

选一个你愿意投递的岗位，把原文要求分成三列：**明确要求、加分项、岗位特有要求**。保留原句链接和查阅日期；没有写明的内容，标成自己的推断。

然后为其中三项填写：

| 岗位原文要求 | 我已经有的证据 | 最小补强任务 |
|---|---|---|
| 例如：熟悉 RAG | 做过关键词搜索，但没测召回 | 跑第 09、12 章，记录一个漏检与改进 |
| 例如：生产实践 | 只有本地 CLI | 先做第 11 章，后续再完成真实部署与运行观察 |

“看完一章”不是证据。把完成状态写成“能解释”“自己实现”“离线验证”“真实环境验证”，比一个笼统的“熟悉”更能找到差距。

后续 09～13 继续使用你自己创建的 TS 练习项目，按目标岗位选学检索、框架、可靠执行与评估，不需要维护另一套项目。

合上文档解释为什么“Agent 算法工程师”和“AI 应用工程师”可能需要不同作品。先看日常职责，再看标题。
