# 06. 穿过三道门：公网 IP、安全组、防火墙与 HTTPS

你在浏览器敲下域名，请求并不会一下跳进 Express。它更像一个访客，要先穿过云平台的大门，再穿过 Linux 的门，最后还要找到真正营业的柜台：

```text
互联网
-> 云安全组
-> Linux 防火墙
-> 监听地址和端口
-> 应用进程
```

阿里云控制台和 Linux 终端都能看到“端口”，正是因为它们分别看守其中一层。

## 云控制台管院子，Linux 管屋里

| 云控制台 | Linux 终端 |
|---|---|
| 创建、停止、重装实例 | 用户、文件和软件 |
| CPU、内存和磁盘规格 | 进程、服务和日志 |
| 公网 IP、私网和安全组 | 防火墙和监听端口 |
| 快照和云备份 | 应用数据和数据库备份 |

安全组位于实例外部。即使 Linux 内部防火墙关闭，安全组仍可能拦住流量。

---

## 给第一台学习服务器挑个小房间

用于 Next.js、Express、PostgreSQL 和 Docker 的单机练习，先用：

- Ubuntu LTS 公共镜像。
- x86_64 架构。
- 2 个 CPU 核心、4 GB 左右内存作为容易起步的基线。
- 系统盘预留镜像、构建缓存、数据库和日志空间。
- 地域选择靠近主要访问者且网络条件合适的位置。

这不是永久规格。上线前用 `free -h`、`df -h`、容器统计和真实请求再决定是否调整。

不要忽略公网流量、磁盘、快照、托管数据库等持续费用。

---

## 哪几扇门真的需要朝全世界打开

| 端口 | 用途 | 推荐来源 |
|---|---|---|
| 22 | SSH | 只允许自己的可信公网 IP |
| 80 | HTTP、证书验证和 HTTPS 跳转 | 公开网站可允许所有来源 |
| 443 | HTTPS | 公开网站可允许所有来源 |
| 面板端口 | 服务器管理面板 | 只允许自己的可信公网 IP |
| 3000 / 3001 / 3002 | Next.js 和 Express | 只在服务器内部，由反向代理访问 |
| 5432 | PostgreSQL | 不公开，只允许应用需要的内部连接 |

改变 SSH 默认端口可以减少部分扫描噪声，但不能替代密钥登录、来源限制、更新和最小权限。

## 在 Ubuntu 里再设一道门

UFW 是 Ubuntu 常见的防火墙管理工具。

远程服务器启用前，先允许当前 SSH 端口：

```bash
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status verbose
```

如果 SSH 使用其他端口，要替换 22。操作前确认云安全组、网页终端和回滚方式可用，保留现有 SSH 会话。

云安全组和 UFW 都要符合预期，不能只配置其中一个就认为完成。

---

## 让域名带着 HTTPS 找上门

```text
域名 A / AAAA 记录
-> 公网 IP
-> 80 / 443
-> 反向代理
-> HTTPS 证书
-> 内部应用端口
```

DNS 只负责把名字解析到地址，不负责启动网站。证书证明域名身份并加密 HTTP；证书申请通常要求 DNS 或 HTTP 验证可用。

## 1Panel 是控制台，不是另一套魔法

1Panel 这类面板可以帮助管理：

- Docker 和 Compose。
- OpenResty 网站与反向代理。
- SSL 证书。
- 防火墙规则。
- 日志、备份和计划任务。

它仍然运行在 Linux 上，不会替代：

- 云安全组。
- SSH 救援能力。
- 应用自己的 Dockerfile 和 Compose。
- 数据库迁移、环境变量和恢复验证。

面板端口也属于管理入口，必须限制来源、使用强密码和 MFA，并保留 SSH 恢复能力。

## 搬进去之前巡视一圈

```text
1. 确认实例、地域、镜像和架构
2. 绑定 SSH 公钥
3. 安全组只开放必需端口
4. 用普通管理用户登录
5. 更新软件索引并检查更新
6. 配置 UFW，先保证 SSH 可继续连接
7. 确认时间、磁盘和内存
8. 再安装 Docker、面板或应用
```

检查：

```bash
cat /etc/os-release
uname -m
timedatectl
free -h
df -h
ss -lntp
```

## 开门前的最后巡视

拿出一张纸，只画允许进入的箭头：

```text
自己的公网 IP -> 22 和面板端口
所有访客 -> 80 / 443
反向代理 -> 3000 / 3001
应用 -> 5432
```

如果你没有画出“互联网 → 5432”，也能说清安全组与 UFW 各守哪一层，这台学习服务器的门禁设计就合格了。
