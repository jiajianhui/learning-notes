# 04. Linux 旅馆：文件住哪里，谁有钥匙，软件从哪来

第一次遇到这句话，很多人会觉得 Linux 在故意拦路：

```text
Permission denied
```

其实它更像旅馆前台在问：你是谁，要进哪间房，手里的钥匙允许做什么？

Linux 初学者最容易形成的坏习惯是：

```text
遇到 Permission denied
-> 在命令前加 sudo
```

这一站先逛楼层，再看工牌和门禁。等关系看清以后，`sudo` 才不会沦为万能通行证。

## 先看楼层，不背整栋大楼

| 目录 | 现在怎样理解 |
|---|---|
| `/home` | 普通用户的主目录 |
| `/root` | root 用户的主目录，不是整个文件系统根目录 |
| `/etc` | 系统和服务配置 |
| `/var` | 会持续变化的数据，例如日志 |
| `/var/log` | 常见文本日志位置 |
| `/opt` | 可选或第三方软件常用位置 |
| `/srv` | 服务提供的数据或项目可以放在这里 |
| `/tmp` | 临时文件，不能依赖长期保留 |
| `/usr` | 大量程序和共享资源 |
| `/proc` | 内核提供的进程与系统状态视图 |

这些是职责约定，不要求第一次背完整文件系统标准。

查看：

```bash
ls -ld /home /root /etc /var /opt /srv /tmp /usr /proc
df -h
```

## 你现在戴着谁的工牌

```bash
whoami
id
groups
```

- 用户表示谁在执行操作。
- 用户组让一组用户共享权限。
- `root` 是最高权限用户。
- `sudo` 让被授权的普通用户以更高权限执行一条明确命令。

`sudo` 不是“重试按钮”。运行前先问：

```text
为什么普通用户没有权限？
这个文件本来应该属于谁？
当前动作真的需要系统权限吗？
```

## 三组门禁灯：`r / w / x`

```bash
ls -l ~/linux-playground
stat ~/linux-playground/topics.txt
```

例如：

```text
-rw-r--r--
```

可以拆成：

```text
-       普通文件
rw-     文件所有者可读写
r--     同组用户只读
r--     其他用户只读
```

目录的 `x` 表示能否进入和访问内部路径，不只是“执行目录”。

常用操作：

```bash
chmod 600 ~/.ssh/config
chmod 700 ~/.ssh
```

`chown` 改变所有者，通常需要 sudo。只在确定项目应该属于哪个用户时使用，不对大目录随意递归修改。

## Web 应用不该拿着万能房卡

一套 Node.js 服务可以这样分工：

```text
部署用户
-> 拉取和更新代码

应用进程用户
-> 读取构建结果和配置
-> 只写日志、上传目录等明确位置

root
-> 安装系统软件、管理服务和网络
```

不要为了省事让 Node.js 应用长期以 root 运行。

## 去 Ubuntu 的软件仓库取工具

```bash
sudo apt update
apt list --upgradable
apt search tree
sudo apt install tree
tree --version
```

主线：

```text
apt update 更新软件索引
-> apt search 查找包
-> apt install 下载并安装
-> 命令进入系统 PATH
```

`apt update` 不等于升级所有软件。正式服务器升级前要看变更、备份和维护窗口，不机械执行一串命令。

macOS 的 Homebrew 和 Ubuntu 的 APT 都能安装软件，但管理的目录、包版本和系统关系不同。

## 亲手锁上一份“小秘密”

```bash
mkdir -p ~/linux-playground/permissions
printf "secret\n" > ~/linux-playground/permissions/private.txt
ls -l ~/linux-playground/permissions/private.txt
chmod 600 ~/linux-playground/permissions/private.txt
ls -l ~/linux-playground/permissions/private.txt
```

说清改变前后，所有者、用户组和其他用户分别能做什么。

## 再遇到 `Permission denied`

先别加 `sudo`，按这个顺序自问：

```text
我是谁？
目标是谁的？
现在的 r / w / x 是什么？
应该改权限、改所有者，还是这件事本来就不该做？
```

能走完这四问，再确认自己能区分 `/` 与 `/root`、APT 与 npm，这一站就结束了。
