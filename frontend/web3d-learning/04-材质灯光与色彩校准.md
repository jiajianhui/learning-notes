# 04. 找到 Blender 与网页画面不一致的原因

模型成功加载后，先固定相机与环境，再逐项校准材质。不要同时改贴图、灯光强度、曝光和后处理，否则无法判断哪一步解决了问题。

## 先分清三个位置

```text
Blender 源资产
    ↓ 导出
GLB 的实际内容
    ↓ 加载与渲染
网页最终画面
```

| 现象 | 先检查哪里 |
|---|---|
| 重新导入 Blender，贴图就丢了 | 节点连接、图片保存、导出范围 |
| 查看器与自己网页都出现图案拉伸 | UV 和模型数据 |
| 查看器正常，自己网页只有金属黑成一片 | 网页环境贴图、材质覆盖和灯光 |
| 形状正确，整体色调不同 | 环境、曝光、色彩与 tone mapping |

查看器是排查工具，其默认灯光不是你必须复制的审美标准。

## 材质参数不是“质感强度”

Three.js 的 `MeshStandardMaterial` 使用金属度与粗糙度描述 PBR 表面。环境贴图对效果很关键，尤其是金属。[官方材质说明](https://threejs.org/docs/pages/MeshStandardMaterial.html)

| 参数 | 它在控制什么 | 常见误用 |
|---|---|---|
| Base Color / `color` | 表面的基础颜色；对金属还影响反射颜色 | 用很亮的颜色补偿缺少环境 |
| `metalness` | 金属与非金属的响应差异 | 为了“高级”给塑料增加金属度 |
| `roughness` | 微表面粗糙程度，影响反射清晰度 | 当成单纯亮度开关 |
| `normalMap` | 细小表面方向变化 | 用强法线代替真实倒角 |
| `emissive` | 表面自身显示的发光贡献 | 认为它自动把周围物体照亮 |
| `clearcoat` | 基础表面上额外的反光涂层 | 给所有材质叠满涂层 |

Physical 材质可以提供清漆、透射等扩展，但开启效果会增加计算成本。本路线先用 Standard 做塑料和金属，需要屏幕表面涂层时才用 Physical。[MeshPhysicalMaterial 文档](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)

## 第一轮：去掉特效，锁定观察条件

1. 选正面三分之四视角，记录相机位置、FOV 和物体占画面的比例。
2. 关闭自动旋转、Bloom、景深和调色滤镜。
3. 保留中性背景，锁定一套棚拍环境。
4. 网页先固定曝光为 1，并明确使用的 tone mapping。
5. 每次只改一个参数，保存对照截图和参数值。

第 03 章使用的是程序生成的灯牌环境，不能直接在 Blender 中选择同名预设来匹配。需要跨软件对照时，下载同一份 HDRI，分别在 Blender World 与网页使用。

在项目中放置你下载的 `public/hdri/studio.hdr`，把 `Studio` 函数中的 `Environment` 连同其 Lightformer 子节点替换为以下局部片段，并移除未使用的 Lightformer 导入：

```tsx
<Environment files="/hdri/studio.hdr" background={false} />
```

HDRI 需要异步加载，在 `Canvas` 里把调用 Studio 的那一段包进已有的 `Suspense`，或新增 `<Suspense fallback={null}>…</Suspense>`。首次校准时两边都只保留这份环境，先关掉网页的直接灯与 ambientLight，减少差异。

`background={false}` 让背景继续使用纯色，但物体仍然接收环境照明与反射。环境和背景可以分别设置。[Drei Environment](https://drei.docs.pmnd.rs/staging/environment)

同一张 HDRI 只是起点：还需要校准旋转方向、强度、相机和显示变换。不要假定 Blender 与 Three.js 的角度参数、曝光数字或映射曲线可以直接一一照抄。

### 双球校准：用同一张 HDRI 找到差异来自哪里

暂时收起产品，在 Blender 和第 03 章的实验台中各放两个光滑着色、大小相同的球。左边是白色金属球（metalness 1、roughness 0.05），右边是中性灰球（metalness 0、roughness 0.5）。两端用相同的基色和观察方向，保持上一步的环境与曝光设置。

1. **先看金属球。** 找 HDRI 里最好辨认的一条亮带。若 Blender 里在左、网页里在右，只转网页的环境图，直到亮带落在球面同一侧。曝光会改变亮度，无法把亮带从右移到左。
2. **再看灰球。** 亮带位置对齐后，比较灰球中间调和亮部过渡。先核对两边的显示变换与曝光，再一次只改一个值，记下哪一步使差距缩小。
3. **换回产品。** 如果两球都接近，银框单独发黑，就沿产品自身查：外框拿到哪张环境图、粗糙度贴图和倍率怎样组合、倒角与法线能否形成连续亮带。若两球仍明显不同，先保留测试场景继续校准。

记录结果时写明“哪一个球、哪一部分不同、改了哪个值”。这比记录“整体更像了”更容易在换模型时复用。[Next.js 材质实验台](./03-Nextjs材质实验台.md)

## 第二轮：修正贴图的读取方式

颜色图与数据图必须区分。

| 图片用途 | Blender 读取 | Three.js 常用标记 |
|---|---|---|
| Base Color，常见 PNG/JPEG | sRGB | `SRGBColorSpace` |
| Emissive，常见 PNG/JPEG | sRGB | `SRGBColorSpace` |
| Roughness / Metalness / AO | Non-Color | `NoColorSpace` |
| Normal | Non-Color，再接 Normal Map | `NoColorSpace` |

颜色信息需要进入线性空间后参与光照计算，粗糙度等数据不应经过同样的颜色转换。屏幕输出再转换到合适的显示空间。[Three.js 色彩管理](https://threejs.org/manual/pages/color-management.html)

通过 GLTFLoader / `useGLTF` 读取正常 GLB 时，先保留加载器的处理。只有自己加载、替换贴图时才检查额外设置，不能遍历所有贴图统一设成 sRGB。

下面是给 **glTF 模型手动替换颜色图** 的关键语句，属于局部示意，不是独立组件：

```ts
// texture 是 TextureLoader 加载出的替换图片。
texture.colorSpace = SRGBColorSpace;
texture.flipY = false;
texture.needsUpdate = true;
material.map = texture;
material.needsUpdate = true;
```

这里的 `SRGBColorSpace` 从 `three` 导入。`flipY = false` 用于与 glTF UV 约定匹配；普通 Plane 的纹理不应该机械照抄这个设置。替换前也要确认图片对应同一套 UV。

## 第三轮：把反射摆到正确的位置

如果没有高光和明暗层次，先看灯的形状与位置，再加亮度。

在第 03 章的实验台里，每次修改后刷新环境捕获，做下面三个对照：

1. 把左侧灯牌从宽面变成窄条，观察边框高光的宽度。
2. 保持灯牌形状，只改位置，观察亮条是否落在能说明轮廓的地方。
3. 保持灯光，只改 roughness，观察高光扩散与细节清晰度。

如果金属表面只反射到大面积黑暗区域，即使 Base Color 很亮也可能很暗。环境中要有能让表面“看见”的亮面，但也要保留暗面，才能形成层次。

用几种问题判断下一步：

| 画面问题 | 优先动作 |
|---|---|
| 塑料像涂蜡 | 检查 roughness 是否过低、clearcoat 是否过强 |
| 金属像灰塑料 | 确认 metalness，再检查环境中有无清晰的亮暗结构 |
| 金属像镜子但不像原物 | 提高适量粗糙度，核对真实材质是否是喷涂或拉丝 |
| 边缘没有细亮边 | 检查倒角尺度、平滑法线和灯牌入射方向 |
| 全部物体都灰白 | 检查曝光、环境强度、颜色图标记和重复输出转换 |
| 细纹特别脏 | 暂时关闭法线和粗糙度纹理，确认是不是强度或尺度过大 |

## 第四轮：处理显示变换差异

Blender 中看到的结果受 AgX、Filmic、Standard、曝光等设置影响。第 03 章明确使用 ACES tone mapping；即使原始颜色和环境相同，两种显示变换也可能让高光与饱和度不同。

R3F 的 WebGL Canvas 默认采用 sRGB 输出和 ACES tone mapping；本例再次写出 ACES 是为了记录基线。不要根据旧教程再随手添加一次 Gamma 校正。[Canvas 默认配置](https://r3f.docs.pmnd.rs/api/canvas)

校准顺序：

1. 先用中灰塑料、白色非金属和一块金属检查明暗关系。
2. 明确两边的显示变换，先避免一边额外调色、另一边没有。
3. 先调整环境方向与强度，再调曝光，最后微调材质。
4. 只在有明确需要时改变网页 tone mapping，然后重新保存对照基线。

Three.js 也提供其他 tone mapping，但换成同名方法也不保证复制 Blender 的完整显示流程。目标是建立视觉一致的交付结果，而不是承诺任何 Cycles 场景都能像素一致。

## 第五轮：完成屏幕和细节

第一版关闭的屏幕可以用深色、低粗糙度的 Physical 材质表现。做亮屏后，显示内容与表面反光可以先合并到一个可控制材质，再按效果需要拆成两层。

开始时不要给整个屏幕加高透射、厚玻璃、景深和强 Bloom。先确保内容清楚、黑位合理、反光不遮挡交互。

图标模糊先检查 UV 中分到了多少像素、图片压缩、最近观察距离和倾斜采样；模型轮廓锯齿则检查画布分辨率、DPR 与抗锯齿。两者不能用同一种办法解决。

## 本章交付

保存正面、侧面、背面和近景四张网页截图，写一份简短对照记录：

```text
现象：金属边框过暗。
排除：GLB 的 metalness 和 roughness 没丢，查看器能正常反射。
只改一项：在侧面环境中加一条长亮面。
结果：转动时能看到连续亮边，深色部位仍保留。
保留设置：记录灯牌位置、尺寸、强度与当前曝光。
```

至少能解释三次这样的修改，再进入 [交互部分](./05-按键屏幕与机械交互.md)。
