# 02. 让 Blender 资产可靠地进入网页

目标是得到一份在独立查看器和自己网页里都能正确读取的 GLB。先迁移材质信息，再在网页建立灯光与显示效果。

## 为什么不能一键搬走最终画面

GLB 可以保存网格、UV、支持的材质参数、贴图与动画，但不会把 Cycles 的完整渲染过程搬进浏览器。

| Blender 里影响画面的东西 | 网页端怎样处理 |
|---|---|
| 网格、UV、法线 | 通过 GLB 导出并检查 |
| Principled BSDF 的常用 PBR 通道 | 按导出器支持的连接方式导出 |
| Noise、ColorRamp 等程序计算 | 需要的结果烘焙成贴图，或以后在网页重写 |
| World 环境、棚拍灯光布置 | 本路线在网页重新配置 |
| AgX / Filmic、曝光、合成器效果 | 在网页选择并校准自己的输出流程 |
| 多次光线反弹和复杂反射 | 实时渲染通常采用近似方案，不能默认等同 Cycles |

导出器按可识别的节点结构构造 glTF 材质，而不是保存任意 Blender Shader 图。以 [Blender glTF 材质文档](https://docs.blender.org/manual/en/latest/addons/scene_gltf2.html) 中的连接方式为准；在文档版本选择器中切换到自己安装的版本。

## 第一步：做一台适合检查的手机

先只保留机身、边框、屏幕和一个按钮。按自己的建模习惯制作，但交付结构保持清楚：

```text
PhoneRoot
├── Body          材质 M_Plastic
├── Frame         材质 M_Metal
├── Screen        材质 M_Screen
└── PowerButton   材质 M_Button
```

这些是我们自己约定的名称，不是 glTF 的保留词。后面会依靠它们找到要修改的部件。

1. 用真实尺寸建模。例如先约定机身高度约 `0.12 m`；整套资产使用相同单位。
2. 在安排父子关系和动画之前处理缩放，避免带着不均匀缩放设置轴心。
3. 给主要外轮廓适当倒角。完全锋利的边没有足够的曲面形成连续亮边。
4. 检查面朝向与平滑法线。需要时重新计算朝外法线，并保留设计需要的硬边。
5. 给材质命名。不要为了换色而把所有部件合成同一个材质。
6. 保存源文件后，在用于交付的副本上处理必须落实的修改器；导出后再看结果。

GLB 的坐标约定与 Blender 不完全一样，导出器会处理坐标转换。导入后先检查朝向；不要一开始就凭印象对每个部件额外旋转 90 度。

**检查点**：只用灰色材质看模型，正面、侧面、背面的比例成立；边角高光连续，没有意外黑面。

## 第二步：先做不用烘焙的材质

先在 Principled BSDF 中使用纯色和数值，建立可导出的基线。以下值只是实验起点，不能作为所有手机的标准。

| 部件 | Base Color | Metallic | Roughness | 先观察什么 |
|---|---|---:|---:|---|
| 磨砂塑料 | 中灰或有色 | 0 | 0.45–0.65 | 宽而柔和的高光 |
| 裸露金属边框 | 浅灰 | 1 | 0.15–0.35 | 明确的环境反射和亮暗变化 |
| 橡胶按钮 | 深灰 | 0 | 0.65–0.9 | 较弱的反光 |
| 关闭的屏幕 | 很深的灰 | 0 | 0.08–0.2 | 在黑色底面上仍能看到反射 |

“看起来像金属”的涂层不一定等于裸金属。先确定真实材料，再选 metalness；不要给所有表面填 0.5 来追求高级感。

第一次导出就停在这里。如果纯参数材质都不对，应先查灯光、法线与色彩流程，增加纹理只会增加变量。

## 第三步：给需要细节的位置准备 UV

UV 是把三维表面展开到二维图片上的对应关系。

1. 为机身和按钮等需要贴图的部件展开 UV。
2. 放一张棋盘格检查拉伸，尤其注意圆角和侧面。
3. 屏幕文字与按键图标需要更多像素，隐藏的底面可以少一些。
4. 要烘焙不同细节的 UV 岛不要重叠；刻意共用同一图案时才复用。
5. UV 岛之间留间距，并给烘焙设置边缘扩展，减少缩小显示时的接缝。

第一版以 1K 或 2K 图片试做。是否需要更高分辨率，由网页里的最近观察距离决定。

**检查点**：棋盘格在主要表面大小接近，按键图标位置明确，接缝避开最显眼的正面。

## 第四步：把程序材质烘焙成可以交付的图片

本步先对一个机身对象、一套材质完成流程。确认成功后再扩展到多材质。烘焙要求有效 UV，并把目标 Image Texture 节点设为活动节点。[Blender Render Baking](https://docs.blender.org/manual/en/latest/render/cycles/baking.html)

### 先烘焙 Base Color

假设机身原来是 `Noise → ColorRamp → Principled Base Color`。

1. 在源文件副本中切到 Cycles，选中机身。
2. 新建一张 `body-basecolor.png` 对应的图像，例如 2048 × 2048，颜色空间选 sRGB。
3. 在材质中新增 Image Texture 节点并选中这张图像。保持该节点为活动节点，暂不连接到材质输入，避免读取正在写入的图。
4. 将要保存的颜色结果临时接到 Emission 着色器的 Color，Strength 设为 1，再连到 Material Output。
5. Bake 类型选 Emit，先设约 16 px 的 Margin，执行烘焙。
6. 在 Image Editor 中保存图片。仅保存 `.blend` 不等于已经把新图片另存到磁盘。
7. 恢复 Principled，将新图片的 Color 接到 Base Color，比较烘焙前后表面图案。

这里临时使用 Emission，是为了只写入颜色函数的结果，避免把场景灯光也混进去。它不代表最终机身应该发光。对于普通非金属，也可以使用 Diffuse 烘焙且只勾选 Color，关闭 Direct 和 Indirect；本路线先用同一种 Emit 方法处理程序颜色。

### 再烘焙 Roughness

如果粗糙度本来是一个常数，就保留常数，不必为它生成整张图。

如果粗糙度由 Noise / ColorRamp 控制：

1. 新建 `body-roughness.png`，图像和读取节点使用 Non-Color。
2. 将输出给 Roughness 的那条灰度结果临时接到 Emission Color，Strength 为 1。
3. 选中新的目标 Image Texture 节点，执行 Emit 烘焙并保存。
4. 恢复原材质，把新图片接回 Roughness，保持 Non-Color。

这张图存储的是数值：较亮区域更粗糙，较暗区域更光滑。不要把带灯光的渲染截图当成粗糙度图，也不要对数据图应用显示用的调色结果。可以先烘焙一块恒定 0.5 的小区域，回读检查数值，排除错误的颜色转换。

### 需要时才补法线

法线贴图改变光照计算时的表面方向，适合细小凹凸，不能代替改变轮廓的倒角。

先做同一个模型的切线空间 Normal 烘焙：创建 Non-Color 目标图，选择 Normal、Tangent，再烘焙并保存。读取时使用 `Image Texture → Normal Map → Principled Normal`，Normal Map 使用对应 UV。

glTF 使用切线空间、+Y 的法线约定。外部素材若提供 DirectX / OpenGL 两种，先选 OpenGL；不要在未确认约定时随意反转绿色通道。高模到低模的 Selected to Active、Cage 与射线距离属于下一轮练习，当前不必同时引入。

### 导出材质最后应该足够简单

```text
Base Color 图片（sRGB） ──────────────────→ Base Color
Roughness 图片（Non-Color） ──────────────→ Roughness
Metallic 常数或图片（Non-Color） ─────────→ Metallic
Normal 图片（Non-Color） → Normal Map ───→ Normal
                                         Principled → Output
```

AO 表示缝隙等位置的环境遮蔽。先不用 AO 跑通主线；之后再按导出器的 Baked Ambient Occlusion 说明连接。glTF 常把 AO、Roughness、Metallic 分别放在 R、G、B 通道中，但你不必在第一版手工打包；导出后检查它们是否正确即可。

## 第五步：导出并做一次往返检查

1. 保存源 `.blend` 和全部贴图。
2. 选择要交付的对象，执行 `File → Export → glTF 2.0`，格式选 GLB。
3. 使用选择对象导出，确认模型所依赖的父级也在导出范围内；保留材质、UV 和法线。
4. 第一轮先关闭几何压缩，减少解码器带来的变量。没有做动画就不导出动画。
5. 将文件命名为 `phone.glb`，拖到 [glTF Report](https://gltf.report/) 检查。
6. 在一个新 Blender 文件中导入同一份 GLB，检查部件、材质参数与贴图是否还在。

查看器里的灯光不必和 Blender 一样，所以此时检查的是资产内容、UV、材质分区和法线；不要要求两个默认环境生成完全相同的截图。

记录这一轮的交付信息：

```text
源文件：phone.blend
导出文件：phone.glb
Blender 版本：填写实际值
机身高度与正面朝向：填写实际值
对象与材质名称：记录 Body / M_Plastic 等
贴图：名称、尺寸、通道用途
环境与曝光：记录用于对照的设置
当前问题：例如边框反射正常，按钮图标还有接缝
```

**检查点**：所有图片存在；新导入的文件没有丢材质；查看器能正确旋转模型。接下来进入 [Next.js 实验台](./03-Nextjs材质实验台.md)。
