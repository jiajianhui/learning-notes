# 01. Web3D 的目标、工具与开发流程

你现在最需要补的是一条完整的资产与渲染流程：知道哪些效果能随模型导出，哪些必须在网页重新建立，以及差异出现后先检查哪里。

## 先知道一帧画面是怎么来的

一个 mesh（网格物体）把 geometry（形状数据）与 material（表面规则）放在一起。texture（纹理）是材质读取的数据，可以描述颜色，也可以描述每个位置的粗糙度或法线。

scene（场景）组织这些对象；camera（相机）决定从哪里看；renderer（渲染器）把场景与相机变成屏幕像素。灯光和 environment（环境）提供照明与反射。网页里的白色背景不会自动成为金属能反射的棚拍环境。

```text
资产文件 → 加载器 → 场景中的网格、材质、骨骼
                          ↓
网页输入 → 目标状态 → 每帧更新对象 → 相机 + 灯光 + 渲染器 → 画面
```

这条流程里有两个节奏。React 状态处理“用户选了合拢”；渲染循环处理接下来每帧应该显示哪个中间姿态。`useFrame` 就是 R3F 提供的逐帧更新入口。连续旋转不需要每帧触发 React 重渲染。[R3F 性能说明](https://r3f.docs.pmnd.rs/advanced/pitfalls)

## 把“很真”写成能修改的东西

面对产品展示，按下面顺序观察。第一阶段用 iPhone Duo 做对照，第二阶段再选择自己的旧手机、播放器或手柄。

| 观察点 | 在画面里寻找什么 | 对应练习 |
|---|---|---|
| 轮廓 | 厚度、圆角、按键间隙和镜头凸起 | 调比例、倒角、部件分层 |
| 表面 | 塑料和金属是否只是颜色不同 | 分开 roughness、metalness，建立各自的高光 |
| 反射 | 金属边框上的亮条宽不宽，随转动如何移动 | 调环境中的亮面位置、面积和材质粗糙度 |
| 微细节 | 文字是否清晰，磨损是否符合使用位置 | UV、贴图密度、局部粗糙度变化 |
| 屏幕 | 关闭时像玻璃，开启后能看清内容 | 分清显示内容与表面反射 |
| 镜头 | 是否变形，物件占画面多大 | 焦距、构图、旋转范围 |
| 交互 | 哪个部件能按、能转，是否有反馈 | 对象命名、状态、轴心和动画 |

第一次练习先做干净的新设备。指纹、灰尘和划痕要等基本材质成立后再加，否则很难知道问题来自哪里。

## Next.js 生态怎么选

### 先使用这一组

| 工具 | 负责什么 | 在本路线的位置 |
|---|---|---|
| Blender | 建模、UV、材质制作、烘焙、机械结构与动画 | 资产制作 |
| glTF / GLB | 保存可交换的模型、PBR 材质、纹理和动画数据 | Blender 与网页之间的交付格式 |
| Three.js | 场景、相机、材质、纹理、渲染器 | 理解画面为什么这样生成 |
| React Three Fiber，简称 R3F | 用 React 组件表达 Three.js 场景 | 与 Next.js、React 状态结合 |
| Drei | 提供模型加载、相机控制、环境等常用组件 | 减少重复搭建代码 |
| Next.js | 页面、路由、内容和客户端组件边界 | 组织最终网站 |

R3F 让场景更容易接入 React，但仍要理解 Three.js。它与 React 主版本存在配对关系：React 19 对应 R3F 9，React 18 对应 R3F 8。不要照搬旧教程中的 RC 或 alpha 安装命令。[R3F 官方安装说明](https://r3f.docs.pmnd.rs/getting-started/installation)

GLB 是 glTF 的二进制容器，适合把本练习的模型与贴图打包交付。后缀改成 `.glb` 并不会让任意 Blender 节点自动得到支持。

### 遇到具体问题再加工具

| 当前问题 | 工具或方法 | 什么时候加入 |
|---|---|---|
| 不知道 GLB 是否正常 | [glTF Report](https://gltf.report/) | 第一次导出就用 |
| 需要精确控制模型里的按钮与屏幕 | [gltfjsx](https://github.com/pmndrs/gltfjsx) | 第 05 章，把模型转换为可编辑组件 |
| 缺少可用的环境素材 | [Poly Haven](https://polyhaven.com/) | 第 04 章，下载同一份 HDRI 做对照 |
| 文件太大 | [glTF Transform](https://gltf-transform.dev/cli) | 外观和交互正确后，先分析再优化 |
| 不停改源码才能调参数 | 普通 HTML 滑块，之后可加调参面板 | 第 03 章开始记录变量 |
| 想加 Bloom、景深 | 后处理库 | 基础画面过关后，逐项对照性能与收益 |

Poly Haven 的资产采用 CC0，可用作练习素材；记录具体资产页和文件版本，方便再次取得同一份素材。[资产许可](https://polyhaven.com/license)

你已有 Blender 基础，本路线继续沿用它。先不引入第二套场景编辑器，也不把 Substance Painter、物理引擎或自定义 Shader 设为必修。只有出现「需要绘制复杂磨损」「物体确实需要碰撞」「标准材质表达不了某种效果」时，再补对应工具。

## 两种常被混淆的烘焙

**烘焙材质信息**：把程序节点算出的颜色、粗糙度或法线写进图片。网页仍根据当前灯光和视角计算表面。这是可旋转产品的主线。

**烘焙最终光照**：把光照与阴影也固定进图片。它适合部分静态场景，但如果把金属高光也烘进颜色图，高光可能粘在物体上；再用 PBR 灯光照它，还可能重复着色。

| 目标 | 建议从哪条路开始 |
|---|---|
| 可以近看、转动、翻盖的手机 | PBR 贴图 + 实时环境反射 + 必要的动态光照 |
| 固定布光的静态小房间 | 可以研究烘焙光照，单独管理动态物体 |
| 手机放在固定的展示空间 | 手机使用 PBR；背景以后按需要做烘焙 |

这也解释了为什么“我已经烘焙了”还不够：先说清烘焙的是哪种信息，以及网页拿它当什么使用。
