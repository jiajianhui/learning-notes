# 01. 从参考展示到可用资产

本步结束时，你应该能在本地看到真正的 iPhone Duo 模型，并说清加载了哪些文件、哪些效果需要网页重建。

## 先固定第一阶段的范围

2026-11-26 实际打开 [Apple iPhone Duo 页面](https://www.apple.com/iphone-duo/)，在 Take a closer look 中观察了姿态切换和拖动。页面提供 Foldable design、Landscape、Portrait、Closed、Seated、Standing、Durability 等展示项。

你的“丝滑、跟手”可以拆成下面这些可检查的行为。这里区分参考中看到的功能和我们准备采用的实现，不据此断言 Apple 使用 Next.js、R3F 或某种动画库。

| 参考中的体验 | 本项目先练什么 | 后续对照什么 |
|---|---|---|
| 产品能连续转动 | 指针位移驱动旋转 | 开始拖动是否及时，掉帧时是否忽快忽慢 |
| 按钮切换展开、合拢等形态 | 目标姿态 + 动画时间采样 | 动作能否中途反向，是否从当前位置继续 |
| 金属边缘有连续亮条 | 环境反射 + 粗糙度 | 转动时高光是否随角度移动 |
| 形态变化仍保持清楚构图 | 朝向、中心、模型尺度 | 是否裁切、突然跳位、过度透视 |
| 展示区与页面融为一体 | HTML 操作区 + 一个 Canvas | 手机滚动与拖动是否争抢手势 |

第一版只做横向展开、纵向展开、合拢、半折叠和复位。Standing、Durability、动态壁纸、整页滚动叙事放到这条链路稳定之后。先建立一套能解释、能替换资产的实现。

## 模型文件为什么不等于整个展示

在本次页面实际加载的资源中，主模型是 `vroIlOhiWPzmavg.gltf`，不是单个 GLB。其来源与依赖校验值完整记录在 [asset-manifest.json](./asset-manifest.json)。

| 检查结果 | 对我们的意义 |
|---|---|
| 98 个节点、62 个 mesh 定义、36 个材质 | 不能假定只有 Body 和 Screen 两个节点，也不能把 mesh 数直接当 draw calls |
| 1 个约 3.89 MB 的 `.bin` | JSON 只描述结构，顶点与动画等数据在外部二进制文件中 |
| 33 张源纹理 | 只下载 `.gltf` 会缺少几何或材质；要递归检查明确引用的依赖 |
| 1 套 skin，`Intro` 与 `Slider` 两段动画 | 已有骨骼与动画可用，第一阶段不用自己重建铰链 |
| 两段动画时间范围都是 0–2 秒 | `Slider` 可以按时间采样折叠程度，而不是不断从头播放 |
| 节点名多数不表达业务含义 | 单独维护配置，先检查模型，不能照教程凭空写 `nodes.Hinge` |

另外，页面还加载了 `.lsd` 场景描述、独立壁纸模型、EXR 及其他纹理。这些说明官网展示还依赖模型文件以外的设置。`.lsd` 不是 GLTFLoader 支持的 glTF 输入，不能把它改后缀就交给 `useGLTF`。

模型内部有 `KHR_materials_clearcoat`、`KHR_materials_specular`，也有本基线 Three.js 不支持的 `KHR_materials_coat` 和嵌套的 `EXT_materials_specular_edge_color`。不支持的扩展需要适配或自行重建效果，不能因为“加载没有报错”就认为材质完全一致。[GLTFLoader 支持列表](https://threejs.org/docs/pages/GLTFLoader.html)

## 从交付资产进入代码工程

本项目从“模型与图片已准备好”开始。素材制作、特殊纹理转换、壁纸合成可以使用 Blender、图片软件或外部工具完成；这些工具不属于网页源码，也不是运行项目的前置依赖。

`public/models/iphone-duo/` 是本次交付目录，`asset-manifest.json` 记录来源和交付前的适配。接入链路是：

`手机 glTF + bin + PNG → useGLTF → 材质适配 → 场景与交互`

此外，交付目录包含两张 EXR 和 studio 子目录的棚拍 glTF、bin、渐变遮罩；lib/asset-materials.ts 记录 glTF 以外的分层与混合设置。这些输入怎样进入代码，见第 02、04 篇。复制模型时不要遗漏它们。

### 先检查格式兼容

这版源纹理虽然使用 `.ktx` 后缀，文件头实际是 **KTX2 容器，内部为 ASTC 6×6 GPU 压缩数据**。容器、压缩格式、文件后缀是不同概念；固定硬件格式不等于可跨设备转码的 Basis 数据。[KTX2Loader 文档](https://threejs.org/docs/pages/KTX2Loader.html)

这次交付前已完成以下适配，应用只消费结果：

- 保留模型几何、节点、skin、动画及外部 bin。
- 将材质纹理的最高分辨率层转换成 PNG；运行时生成 mipmap。颜色图和数值数据图分别处理，未把所有图片统一提亮。
- 保留加载器支持的标准材质扩展，省略不支持的部分。
- 交付内外屏各自比例的静态 PNG；它们由公开图层合成，未包含原站动态壁纸的 Shader、LUT 和视差。

这是针对当前素材的交接记录，不是每个 Web3D 项目必须重复的流程。正常 GLB 如果已包含加载器支持的图片与材质，可直接接入。8 位 PNG、缺失的专用扩展、静态壁纸以及重新布光都会造成外观差异。

### 接收资产的检查顺序

1. 打开 `phone.gltf`，确认 buffers、images 引用的文件都在交付包内，路径和大小写一致。
2. 确认 extensionsRequired 中的能力有加载器支持；有压缩扩展时再配置相应解码器。
3. 查看真实材质名、动画名、时间范围和节点层级，再写代码映射。
4. 启动网页，检查 Network 中模型及依赖成功返回；最后比较外观。加载成功只是第一道检查。

图片用途由材质字段决定，例如 baseColorTexture、emissiveTexture 是颜色，normalTexture、metallicRoughnessTexture 是数值数据。不要根据文件后缀统一设置色彩空间。

### 哪些问题需要回到 Blender

模型已经做好的情况下，先检查交接契约：

- 包含目标零件、法线、UV、可读取的材质与已保存的图片。
- 动画有可辨认的名称，骨骼和层级完整，轴心与实际运动一致。
- 能说明单位、初始朝向，以及打开/合拢等关键姿态。
- 确认哪些程序材质或专用扩展需要烘焙、替代或在网页重建。

路径、加载器、色彩标记、网页布光通常在代码侧处理。UV 错误、缺少几何、轴心不正确才应回源资产修复，再重新交付。第一阶段关注这次交接，不要求重新学习整套建模。

### 换成自己的模型时怎么做

先把正常 GLB 放到 public/models，修改 phone-scene.tsx 的 useGLTF 路径，观察原始加载结果。然后依次调整：材质名称映射、动画名称与时间范围、坐标修正与取景、姿态配置。复用 UI、Canvas、输入事件和运动计算。

如果资源使用 Draco、Meshopt 或 Basis KTX2，按实际扩展配置对应解码器；不能只看文件后缀判断，也不需要先把所有解码器都装上。支持范围以 [GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html) 与当前依赖版本为准。

## 初次读资产时动手做三个检查

在项目根目录执行，用 Node.js 自带模块查看结构：

```bash
node --input-type=module <<'JS'
import { readFileSync } from 'node:fs';
const g = JSON.parse(readFileSync('public/models/iphone-duo/phone.gltf', 'utf8'));
console.log('动画：', g.animations.map(a => a.name));
console.log('屏幕：', g.nodes.filter(n => /screen/i.test(n.name ?? '')).map(n => n.name));
console.log('外部几何：', g.buffers);
JS
```

应该能找到 `Slider`，以及内屏 `skeleton_0_3_screenTexture_geo`、外屏 `skeleton_0_7_outerDisplayScreenTexture_geo`。这一步建立“先检查，再按真实结构写代码”的习惯。

然后打开 `phone.gltf`，从一个 mesh 的 `material` 索引找到对应材质，再从材质的纹理索引找到 texture 和 image。读懂这条引用链，就能理解为什么某一张图片丢失会影响某一块表面。

最后对照 `asset-manifest.json` 的适配说明，明确哪些效果仍需网页重建。第一阶段不需要把所有节点重命名；只有要操作某一部件时，再建立业务名称到源节点的映射。
