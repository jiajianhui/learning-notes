# 02. 沿真实工程串起页面、模型与动画

这一篇按实际文件跟读：模型已经准备好，接下来怎样组织 Next.js 工程，把资源变成画面，再把按钮变成动作。读完应能自己定位加载、材质、灯光和输入代码，并替换其中一环。

先按 README 启动，完成一次“合拢 → 展开 → 拖动 → 复位”，再沿下面的调用关系读。完整源码就在本目录，不需要另建一套教学空壳。

## 先认清模块各自负责什么

```text
app/page.tsx                      普通页面内容
└── components/viewer.tsx          浏览器加载边界
    └── product-demo.tsx           HTML 操作区 + Canvas + 业务状态
        ├── use-product-drag.ts   DOM 指针事件 → ref 中的连续输入
        │   └── lib/drag-motion.ts 角度目标、速度、阻尼与限位计算
        └── phone-scene.tsx       组织模型、变换层级与每帧更新
            ├── useGLTF           URL → 场景、材质、骨骼、动画
            ├── use-studio-maps.ts 将交付的棚拍场景烘成环境图
            ├── lib/asset-materials.ts 本模型的分层与混合规则
            ├── lib/model-materials.ts 复制并适配模型材质
            └── studio.tsx        可见背景

lib/poses.ts                      每个按钮对应的姿态数据
lib/viewer-config.ts              渲染、灯光、材质和运动的调节值
public/models/iphone-duo/         接收已经制作、适配完成的网页资产
```

| 想改什么 | 先打开哪个文件 | 它的职责边界 |
|---|---|---|
| 展示标题、控件与布局 | [product-demo.tsx](./components/product-demo.tsx)、[globals.css](./app/globals.css) | 普通网页内容与 CSS |
| 按钮、选中状态、加载失败提示 | [product-demo.tsx](./components/product-demo.tsx) | 网站 UI 与场景入口 |
| 相机、清晰度、曝光、拖动参数 | [viewer-config.ts](./lib/viewer-config.ts) | 保存调节值，不加载资源、不监听输入 |
| 新增一种展示姿态 | [poses.ts](./lib/poses.ts) | 目标数据，不执行动画 |
| 模型 URL、坐标修正、骨骼动画 | [phone-scene.tsx](./components/phone-scene.tsx) | 把已准备的资产和状态组成场景 |
| 某块表面的粗糙度或屏幕亮度 | [model-materials.ts](./lib/model-materials.ts) | 识别材质角色并应用配置 |
| 可见背景、分层环境 | [studio.tsx](./components/studio.tsx)、[use-studio-maps.ts](./components/use-studio-maps.ts) | 前者设置画布底色；后者生成静态金属环境以及两套分层棚拍环境 |
| 资产的特殊材质规则 | [asset-materials.ts](./lib/asset-materials.ts) | 保存 glTF 之外的分层、透明度和混合配置 |
| 输入事件或运动手感 | [use-product-drag.ts](./components/use-product-drag.ts)、[drag-motion.ts](./lib/drag-motion.ts) | 分别负责浏览器事件与运动计算 |

这样拆分是因为每一部分有独立的修改理由。新增姿态只改数据；调灯不碰手势；换模型主要调整加载与材质映射。小项目不需要额外加入全局状态库、物理引擎或场景编辑器。

## 第一步：建立 Next.js 与三维渲染的边界

`app/page.tsx` 保持普通页面，导入 `Viewer`。它不需要知道模型里有哪些 mesh，也不需要访问 WebGL。

`components/viewer.tsx` 是完整的客户端入口：

```tsx
'use client';

import dynamic from 'next/dynamic';

const ProductDemo = dynamic(() => import('./product-demo'), {
  ssr: false,
  loading: () => <p role="status">正在准备 3D 展示…</p>,
});

export default function Viewer() {
  return <ProductDemo />;
}
```

`'use client'` 声明客户端组件边界，但客户端组件仍可能参与服务端预渲染。这里再用 `ssr: false`，让整个 3D 模块在浏览器加载；这个选项放在 Client Component 中。[Next.js Lazy Loading](https://nextjs.org/docs/app/guides/lazy-loading)

`product-demo.tsx` 的 Canvas 创建场景、相机与 WebGL 渲染器。Canvas 内的 `<group>`、`<primitive>` 是 R3F 对 Three.js 对象的描述；外侧的 `<button>`、`<label>` 仍是 DOM。

**动手**：改页面介绍，再在 `viewer-config.ts` 中把 `fov` 从 20 改为 30。前者改变文案，后者改变透视；代码会按姿态 bounds 重新适配取景大小。恢复数值，确认你能区分网站内容和场景配置。

## 第二步：沿 URL 找到模型实际加载的位置

`phone-scene.tsx` 中：

```tsx
const gltf = useGLTF('/models/iphone-duo/phone.gltf');
const model = useMemo(() => clone(gltf.scene), [gltf.scene]);
```

这是实际源码的局部片段。`public/models/iphone-duo/phone.gltf` 在网站中对应 `/models/iphone-duo/phone.gltf`，URL 不包含 `public`。这里是浏览器资源请求，不是 TypeScript 的源码 import。

加载过程是：

```text
读取 phone.gltf 的 JSON
→ 解析节点、材质和资源引用
→ 请求同目录中的 .bin 与 PNG
→ 建立几何、纹理、材质、骨骼与动画对象
→ useGLTF 返回 gltf.scene、gltf.animations 等结果
→ <primitive object={model} /> 挂入当前场景
```

主 glTF 返回 200 不代表模型完整：任何一个依赖缺失，都可能造成加载失败或材质异常。资源兼容和依赖检查见 [第 01 篇](./01-参考拆解与资产接入.md)。

`useGLTF` 会缓存结果。这里的 `clone` 来自 `SkeletonUtils`，让场景层级和骨骼能够作为独立实例运动；普通的共享几何和材质仍会被引用。不要把同一个 Object3D 同时挂到两个父节点，也不要随意修改加载缓存里的材质。

`useMemo` 的用途是避免普通 React 重渲染时不断重建模型实例。它不替代资源清理。后面的 `primitive` 使用 `dispose={null}`，明确由我们管理复制出来的资源，源加载缓存仍保留。

### 等待和失败分别在哪里处理

| 状态 | 代码位置 | 用户看到什么 |
|---|---|---|
| 3D 模块尚未加载 | `viewer.tsx` 的 dynamic loading | “正在准备 3D 展示” |
| 模型及纹理正在请求 | `useGLTF` + Suspense；外层 `useProgress` | “正在加载模型” |
| 加载或场景初始化抛错 | `ViewerError` | 失败说明与重新加载按钮 |
| WebGL 不可用 | Canvas 的 fallback | 无法显示 3D 的说明 |

`useProgress` 的 active 是加载管理器状态，本项目没有把它伪装成按字节统计的下载百分比。场景等待时 Suspense 暂不显示模型，但页面标题和 HTML 按钮仍存在。

**检查点**：在 Network 中确认 glTF、bin、PNG 请求成功。以后改变模型路径时先检查这里，不要先在 Blender 重做模型。

当前还加载两张 EXR 和两套棚拍 glTF。它们都是交付资产。useStudioMaps 在 effect 中建立 CubeCamera 和 PMREM；phone-scene 每帧提供观察角度和开合，布光变化时才更新环境图；结果通过 prepareMaterials 分配给对应材质。原始模型缓存保持不变，实例材质和生成的渲染目标由各自模块清理。

## 第三步：理解材质适配为什么是独立的一步

模型加载器已经建立了材质。网页可以先使用它们，再对明确的材质角色做适配；不必全部换成手写材质。

`phone-scene.tsx` 保留每个 mesh 的原始材质引用，在 effect 中调用：

```tsx
const dispose = prepareMaterials(model, gl.capabilities.getMaxAnisotropy());
```

`prepareMaterials` 来自 `lib/model-materials.ts`，内部完成三件事：

1. **按源材质去重后复制**：多个 mesh 共用一个材质时，仍共用一份本实例材质，避免为每个零件重复创建。
2. **复制要调整采样的纹理对象**：`material.clone()` 仍引用原纹理，因此还要复制纹理对象再设置 anisotropy。图片像素可以共享；colorSpace、UV 通道和 flipY 等元数据保留。
3. **按角色应用配置**：识别指定金属和内外屏，读取 `materialConfig`。未被选中的材质保留源参数与贴图。

复制对象、设置属性都发生在加载后，不发生在每一帧。effect 清理时先恢复原材质引用，再释放自己创建的材质与纹理对象。开发模式会重复建立和清理 effect，这个流程也必须成立。

想调哪个材质、如何确认没有改错，见 [材质灯光与清晰度调校](./04-材质灯光与清晰度调校.md)。该篇直接对应这两个模块，不要求先回 Blender。

## 第四步：理解场景为什么要分几层 group

这份源模型的屏幕主要朝向 Y，当前相机朝向模型的 Z 面，因此用固定 X 轴旋转 `Math.PI / 2` 修正朝向。这是这份资产的适配，不是 glTF 的通用操作。

```text
turn                    用户拖动产生的 yaw / pitch
└── preset              按钮设定的展示朝向
    └── 固定坐标修正 + scale
        └── offset      将当前形态移到画面中部
            └── model   原节点与骨骼层级
```

骨骼动画修改原模型关节；拖动修改 `turn`；按钮过渡修改 `preset`。把不同职责放在不同变换层，可以避免两段代码反复覆盖同一个 rotation。

`renderConfig.frameFill` 与相机共同决定物件占画面的大小；窄画布再按宽高比收小模型。`offset` 修正不同折叠形态的中心。它们不改变源模型零件之间的尺寸关系。

**动手**：把 `frameFill` 降低 10%，观察构图，再恢复。不要逐个修改零件的 scale 来修整件产品的取景。

## 第五步：一个按钮如何驱动骨骼动画

打开 `lib/poses.ts`。每个姿态保存：

| 字段 | 含义 | 使用位置 |
|---|---|---|
| `label` | 按钮文字 | DOM 按钮列表 |
| `time` | Slider 动画要显示到哪一秒 | AnimationAction 的时间 |
| `rotation` | 整件产品的目标朝向，单位弧度 | preset 的四元数插值 |
| `center` | 当前形态的源坐标包围盒中心 | offset 的平移 |

实际链路是：

```text
按钮 onClick → selectPose('closed')
→ poseName 状态变成 closed，拖动偏移开始复位
→ PhoneScene 收到 poses.closed
→ 每帧让当前 time、朝向、中心接近目标
→ AnimationMixer 把该时刻的骨骼姿态写进模型
→ 渲染器画出新的形状
```

`time.current` 是当前采样时间，`pose.time` 是目标。`Slider` 在该资产中长 2 秒，0 对应合拢，2 对应展开。播放器的 action 设置为 paused；代码主动指定时间，再 `mixer.update(0)` 应用采样，不让自动播放同时推进时间。[AnimationMixer](https://threejs.org/docs/pages/AnimationMixer.html)

源码中的核心片段：

```tsx
move.elapsed = Math.min(transitionSeconds, move.elapsed + delta);
const eased = poseEase(move.elapsed / transitionSeconds);
time.current = scrub === null ? MathUtils.lerp(move.time, pose.time, eased) : 2 * scrub;
if (player.current) {
  player.current.action.time = time.current;
  player.current.mixer.update(0);
}
```

每次选择先记下当前帧，再用经过的秒数计算 1.15 秒过渡的进度。开合、居中、缩放与旋转共用同一条缓动曲线。

朝向用 `Quaternion.slerp` 插值。四元数是表达旋转的方式，当前只需要理解：从当前朝向连续走向目标朝向。不要把它与屏幕像素位移混在同一套数值里。

播放器在 effect 中建立，在清理时停止并解除缓存；下一次 effect 建立新播放器，避免复用已经释放绑定的 action。

**动手**：复制半折叠配置为 `quarter`，设 `label: '四分之一展开'`、`time: 0.5`。按钮会自动出现。先确认动画时间生效，再调该项的 center 和 rotation。你正在添加一份配置，不需要复制整个 Canvas。

## 最后核对谁负责每一种更新

| 数据 | 存放位置 | 更新节奏 |
|---|---|---|
| 当前选中的姿态、环境开关 | React state | 用户点击 |
| 拖动目标、速度、当前角度 | ref 中的 DragState | 指针事件与逐帧计算 |
| 当前骨骼动画采样时间 | ref | useFrame |
| 渲染与材质的基础参数 | viewer-config.ts | 开发时调校 |
| 模型实例、已加载资源 | useMemo / useGLTF 缓存 | 资源改变时 |
