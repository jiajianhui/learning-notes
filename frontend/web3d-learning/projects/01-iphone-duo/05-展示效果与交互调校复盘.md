# 05. 从能显示到好看、跟手：调校复盘

前四篇已经把模型接入、每帧更新、交互和材质串起来。这一篇回看实际遇到的问题：看到一种现象，如何找到负责的模块，再用一个具体动作判断改动是否有效。

主线是：**先固定姿态和取景，再调动作连续性，最后分开检查资产细节、采样和反射。** 模型加载成功，只完成了这条流程的起点。

## 一、这几轮到底在优化什么

| 环节 | 遇到的问题 | 当前处理与关键认识 | 主要入口 |
|---|---|---|---|
| 默认角度与取景 | 初始歪斜、模型偏小，某些姿态可能裁切 | 默认合拢正面；产品预设与用户旋转分层；按姿态宽高适配画布 | poses.ts、phone-scene.tsx |
| 拖动跟手与限位 | 拖尾明显，上下旋转缺少约束 | 指针位移换成目标角度；追随速度独立调节；鼠标俯仰限制在 ±15° | use-product-drag.ts、drag-motion.ts |
| 松手惯性 | 一松手就停，或停稳后又突然转动 | 记录最近的水平速度并随时间衰减；停稳后释放清除旧速度 | moveDrag、endDrag、stepDrag |
| 上下回正 | 松手后需要恢复直立 | 垂直方向独立使用阻尼弹簧回到零，不把水平方向也拉回正面 | stepDrag、pitchReturnRate |
| 角度吸附 | 希望转到一定范围后稳定停靠 | 预测惯性落点，选最近的预设角度；减速后交给吸附弹簧 | endDrag、snapStep、snapThreshold |
| 材质与灯光 | 灰蒙、塑料感、镜头黑、金属侧框黑 | 保留原材质特征，恢复分层反射和混合规则；接回原金属灯棚与视角状态 | studio-lighting.ts、use-studio-maps.ts、model-materials.ts |
| 清晰度 | 屏幕糊、边缘不精致、细节看不见 | 分开检查几何、源图、DPR、倾斜采样和取景；用反射显现已有细节 | viewer-config.ts、模型与图片资产 |

配置集中在 [viewer-config.ts](./lib/viewer-config.ts)。找参数后仍要追到使用者：配置只保存数值，组件和运动函数才会让数值产生效果。

## 二、角度正确与动作顺滑，是两条控制链

[phone-scene.tsx](./components/phone-scene.tsx) 的变换层级是：

```text
turn：用户拖动、惯性与吸附
  → preset：姿态按钮指定的朝向
    → modelFrame：资产坐标系转换、取景缩放
      → offset：将当前姿态移到展示中心
        → 模型与骨骼动画
```

默认正面由初始姿态决定。上下回正只把 turn 的 pitch 回到 0，因此仍允许“纵向展开”预设自身旋转。相机 FOV 为 20°，frameFill 为 0.84；FOV 调整透视，取景适配决定模型在画面中有多大。

交互则沿下面的链运行：

```text
指针事件 → useProductDrag → DragState → 每帧 stepDrag → turn.rotation
```

这里有三种不同的“阻尼”，不能用一个数解决：

- **按住时追随目标**：followRate 控制跟手程度，值越大追得越紧。
- **松手后衰减速度**：inertiaDecay 控制惯性长度，值越大停得越快。
- **最后回正或吸附**：弹簧让角度连续地收敛到目标，pitchReturnRate 与 snapRate 分别控制两种收敛。

当前水平停靠间隔为 45°，捕获范围为 25°。选点依据是预测落点，减速后才进入吸附；再次按住立即接管。因为最近停靠点最多相距 22.5°，这组参数实际上覆盖整圈，正常释放最终都会停靠。若希望保留不吸附的区间，需要把阈值调小。这是练习版规则，不能把参数表当成官网控制器源码。

运动公式和逐步实验见 [第 03 篇](./03-跟手交互与项目验收.md)。

## 三、灰蒙和发黑为什么会先后出现

金属主要通过反射环境呈现形状。页面上的白色背景与金属采样的环境是两个设置，改网页底色不会自动把侧框照亮。

早期环境偏亮、金属粗糙度被抬高，反射缺少锐利的明暗结构，容易呈现塑料感。恢复原粗糙度、压暗环境后，窄灯牌覆盖不足的问题又显现出来：一些方向只有很暗的底色可反射，于是侧框整片发黑。

之后把环境改成中灰底、扩大纯色灯牌，虽然提高了亮度，却出现大片纯白、硬边和扁平的银灰描线。用户的正侧面和机背对照图说明这一版仍未达到目标：消除“黑”并不等于恢复金属质感。

当前接入原场景的三套灯棚及渐变遮罩，由 [studio-lighting.ts](./lib/studio-lighting.ts) 根据观察方向与开合插值，再由 [use-studio-maps.ts](./components/use-studio-maps.ts) 捕获独立环境图。金属不再使用简化纯色灯牌，背板也不再永远固定为 backLeft 布光。

[model-materials.ts](./lib/model-materials.ts) 按资产角色分配环境，材质环境朝向随产品变换同步。全局曝光与金属粗糙度倍率保持 1；背板环境强度由 1.5 回到 1，保护玻璃由 6 回到 1，内部光学层用独立的 1.5 倍环境强度。保护玻璃和内部镜片分开控制，避免用一个亮点掩盖内部层次。这些倍率是练习版设置，不是从截图测得的官网参数。

仍有明确边界：原机身/细节环境采用结果 crossfade，本练习采用节点变换与发光插值；上下方向专门布光和专用材质 Shader 未完整复现。具体调节入口见 [第 04 篇](./04-材质灯光与清晰度调校.md)。

## 四、这次更清晰，不等于重新做了模型

源模型几何保持不变，变化主要发生在展示端：

- **取景更充分**：模型占用更多画布像素，按钮、倒角和镜头更容易看清；缩小 FOV 本身不会创造细节。
- **DPR 下限从 1 提到 1.5**：原来按 1 倍渲染的设备，绘制像素数变成 2.25 倍；原本已经是 2 倍的设备不因此增加像素。
- **屏幕输入已经升级**：较早的 512×512 示意图换成内外屏各自比例的高分辨率合成图；源图层本身的细节仍是上限。
- **采样与反射各司其职**：anisotropy 改善斜看纹理时的采样；保留较低粗糙度让反射更锐利；屏幕 toneMapped=false 避免显示图再次受到 ACES 压缩。

检查顺序是：轮廓缺几何看模型，文字模糊看源图与采样，整体锯齿看画布像素，表面没有层次看反射。增加 DPR 会增加渲染成本，不能代替资产优化或手机真机测试。

## 五、怎样判断这次真的改善了

每次固定画布尺寸、姿态和观察角度，避免把放大取景误认为材质变好了：

1. 刷新确认默认正面；横向、纵向和合拢姿态都检查边缘是否裁切。
2. 快拖后松手观察惯性，再按住停稳后释放，确认没有沿用旧速度。
3. 上下拖到边界再反向，确认能立即离开边界；松手只让俯仰回正。
4. 观察惯性到吸附是否连续；吸附过程中再次按住，应从当前角度接管。
5. 在正面、斜角和纯侧面检查反射；允许局部暗面，但不能只剩一整片黑或一整片白。

前一版虽然做过本地预览，但用户后续对照图仍暴露出明显差距，不能沿用“已经调好”的结论。本轮依据用户提供的三组图片修改，不追加浏览器截图。交互数值检查位于 [check-interaction.ts](./scripts/check-interaction.ts)，布光与资源检查位于 [check-studio.ts](./scripts/check-studio.ts)；它们验证工程正确性，不替代画面验收。

## 六、2026-11-27：修改记录与疑难点

| 迭代 | 处理 | 暴露的问题 / 这次的结论 |
|---|---|---|
| 角度与交互 | 默认正面、俯仰限位、松手惯性、回正、45° 吸附 | 已形成分开的控制链；本轮保留，继续跑数值回归 |
| 清晰度 | 提高 DPR 下限、扩大合理取景、换内外屏素材 | 锯齿和可见细节改善，但不能补足错误材质与构图 |
| 深色底、窄灯牌 | 保留抛光粗糙度，增强反射对比 | 缺少覆盖的角度整片黑；不是增加面数可以解决 |
| 中灰底、宽灯牌 | 扩大反射亮面 | 又变成大片白与硬边；纯色灯牌不能替代原灯棚渐变 |
| 本轮反射 | 三套原灯棚、渐变遮罩、八方向与开合插值 | 把缺失的资产交接补齐；仍保留 crossfade、上下布光和专用 Shader 的差异记录 |
| 本轮屏幕 | 原山丘/沙丘几何离线投影，重映射裁切 UV，合成原 UI | 去掉矩形拉伸和淡入造成的横向亮带；当前仍是静态取景近似 |

### 疑难点 1：为什么原模型加载后仍不像参考

手机 glTF 不包含整个展示系统。独立灯棚、渐变遮罩、视角配置、镜头混合规则和壁纸场景也是输入。先检查交付是否完整，再判断是否需要修改模型本身。来源与转换记录保存在 [asset-manifest.json](./asset-manifest.json)。

### 疑难点 2：固定相机与固定产品能直接互换吗

参考用相机绕产品，本练习旋转产品。观察方向需要换算，环境朝向也要转换；只复制灯光角度、却让环境始终停在旧的世界坐标，会使同一个产品角度看到另一组反射。当前从 turn 与 preset 的组合旋转求观察方向，再同步材质 envMapRotation。

### 疑难点 3：拿到图片为什么壁纸还会错

原山丘纹理配合网格轮廓，图片本身是裁切后的矩形。之前直接铺矩形并淡入，造出了参考中没有的水平亮带。离线投影时还发现网格 UV 保留原图区域：必须重映射到裁切图的范围，并处理 V 轴方向，否则山丘会被拉成长条。当前使用原网格和透视校正采样，保留原 UI 分辨率；相机与天空映射仍是构图近似，没有恢复 LUT、视差和动态壁纸。素材处理程序留在工程外，网页只接收 PNG。

### 疑难点 4：动态环境会不会拖慢交互

每次 PMREM 更新包含离屏渲染，不能无限制地每帧创建纹理。当前保留渲染目标，只有角度或开合变化时更新，上限 15 次/秒；静止后停止。三个 256 像素半浮点立方体及 PMREM 都在卸载时释放。这个策略限制工作量，实际 GPU 时间仍需真机测量。

### 本轮检查范围

运行 `npm run check:studio`、`npm run check:interaction`、`npm run typecheck`、`npm run build`。布光检查覆盖八方向索引、角度跨圈连续性、开合插值、共享缓存不被修改、119 项 glTF 依赖及缓冲区长度。另检查 Markdown 链接和代码块。

结果：上述代码检查与生产构建通过，48 个本地文档链接有效；恢复的本地页面与新增 metal.gltf 均返回 HTTP 200。

本轮没有重新截图，也没有完成真机性能或浏览器视觉验收。保留用户提供的正面、斜前方、背面对照作为验收依据；不能把构建通过写成已经与官网一致。

## 七、局部收尾：内屏缺口、屏幕强光与 Logo

- 内屏左下角出现三角形色块：内外屏共用偏左的壁纸相机，展开后的宽视野超出了原沙丘网格边界，露出了合成底色。将内屏壁纸相机横向位置改为 0，外屏保留 -15；重新交付内屏 PNG，保持 UI 尺寸不变。离线检查内外屏底部四分之一全部被网格覆盖，无缺失像素。
- 屏幕出现一道强光：上一轮给 PracticeScreen 材质接入 EXR，又保留玻璃镜面与 clearcoat。现在该材质 envMap=null、envMapIntensity=0、specularIntensity=0、clearcoat=0，只显示原发光贴图；边框和镜头反射保留。
- Logo 对比太低：找到了原 Logo 几何及其独立底色材质 ZgMnqnyPATyacDv；通过 logoBaseColorScale=0.78 单独调整。Logo 上方 LDcHeENovRXWVxD 的 Max 混合覆层依赖未移植的专用 Shader，当前隐藏这块覆层，避免冲淡底色；共享同一材质的相机底座不受影响。清理时恢复原可见性，兼容重复挂载。
