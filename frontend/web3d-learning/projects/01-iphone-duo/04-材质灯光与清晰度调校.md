# 04. 材质、灯光与清晰度在哪里调

模型已经加载成功，接下来把网页画面调好。这一篇只讲代码侧：每个设置由哪个模块读取、改变了什么、怎样做一次有效对照。Blender 的资产制作流程仍放在通识与第二阶段。

## 先固定调节入口

| 文件 | 负责的事情 | 典型修改 |
|---|---|---|
| [lib/viewer-config.ts](./lib/viewer-config.ts) | 集中保存参数 | DPR、曝光、环境强度、屏幕亮度、粗糙度 |
| [components/studio.tsx](./components/studio.tsx) | 设置可见背景 | 改变画布底色，不改变反射 |
| [components/use-studio-maps.ts](./components/use-studio-maps.ts) | 将三套棚拍网格生成 PMREM 环境图 | 分离机身、细节和金属的照明 |
| [lib/asset-materials.ts](./lib/asset-materials.ts) | 保存交付资产的分层和透明混合规则 | 找到某块表面使用的反射环境 |
| [lib/model-materials.ts](./lib/model-materials.ts) | 找到正确材质并应用参数 | 给某一类金属或某块屏幕设置不同响应 |

配置文件的值不会自己产生效果。要沿 import 和读取位置查到真正使用者：`renderConfig.exposure` 被 Canvas 的渲染器使用；`studioConfig.resolution` 被离屏 CubeCamera 的渲染目标使用；`materialConfig.screenBrightness` 被屏幕材质使用。

## 第一步：分清“不清晰”发生在哪一层

| 看到的现象 | 应该检查 | 本项目的入口 |
|---|---|---|
| 外轮廓锯齿、整体像低分辨率画面 | 画布像素数与抗锯齿 | renderConfig.dpr；Canvas 的 antialias |
| 图案或文字糊，但机身轮廓正常 | 源图片分辨率、UV 分配、纹理过滤 | 资产准备输出；model-materials 的 anisotropy |
| 正面清楚，斜看纹理变糊 | 倾斜采样 | maxAnisotropy |
| 反射亮条粗糙或模糊 | 环境分辨率、粗糙度 | studioConfig.resolution；相应材质 |
| 没有真实倒角、镜头细节 | 模型几何本身 | 检查资产，需要时回 Blender |
| 细节存在，但看不出来 | 取景太小、明暗层次不足 | frameFill、相机、环境 |

`dpr: [1.5, 2]` 将绘制像素比限制在此范围，普通 1 倍屏也会以 1.5 倍绘制，减少细边锯齿。较弱设备可以把下限恢复为 1。宽高相同的画布从 DPR 1 提高到 2，像素数量约变为四倍，GPU 成本也可能显著增加。

当前保留源模型几何和原始贴图分辨率；没有用增加顶点数伪装“精细”。屏幕已改用内屏 2048×1441、外屏 1398×2034 的静态合成图，替换原来的 512×512 示意图。图层本身的分辨率不同，因此背景与 UI 的细节上限也不同，不能把合成输出尺寸当成所有图层的真实细节。

`maxAnisotropy: 8` 用于改善倾斜观察时的采样，并取显卡实际支持的上限。它不会恢复源图不存在的像素。[Three.js Texture](https://threejs.org/docs/pages/Texture.html)

**对照操作**：固定姿态，先只改变 DPR 上限，然后恢复；再在斜看屏幕时把 maxAnisotropy 从 8 改为 1。分别观察轮廓和纹理，不要把两种模糊混为一谈。

取景由相机 fov、各姿态 bounds 与 frameFill 共同决定。默认合拢姿态朝向为零；frameFill 为 0.84，模型按可用画布宽高的较小约束缩放。纵向展开使用自己的宽高，避免单纯放大模型后裁切。

## 第二步：让金属能够反射到亮暗结构

当前由三套资产提供灯棚：`studio/body.gltf`、`details.gltf`、`metal.gltf`。其中包含灯光网格、渐变遮罩，以及写在 scene extras 中的具名视角参数。`studio.tsx` 只设置用户看到的白色背景。

实际调用链是：

`phone-scene.tsx` 计算观察方向和开合比例 → `studio-lighting.ts` 插值灯棚节点与发光参数 → `use-studio-maps.ts` 用 CubeCamera 捕获环境 → PMREM → `model-materials.ts` 分配给材质。

以前的纯色 Lightformer 已移除：窄灯牌会留下大片黑区，扩大后又会出现大片纯白和硬边。当前保留参考灯棚的渐变遮罩和空间布置，正常黑色反射带仍然需要保留。

### 按这个顺序调环境

1. 固定合拢姿态，分别查看正面、斜角、侧面和背面。
2. 确认三个 glTF 及其依赖、lightingStates 都已交付，先排除缺失资源。
3. 从 materialConfig 分别调整 bodyEnvironmentIntensity、metalEnvironmentIntensity，观察指定表面，不同时修改曝光。
4. 镜头内部用 lensOpticsIntensity；保护玻璃用 lensReflectionIntensity。前者控制内部光学层，后者控制玻璃表面的反光。

`studioConfig.resolution: 256` 是半浮点立方体捕获尺寸，与 DPR 无关。观察角度或开合变化时，最多每秒更新 15 次；静止后停止捕获，复用已有 PMREM 渲染目标。调节数值可以改变成本，但性能要用真机实测，不能凭频率判断达标。

当前按八个水平方向及闭合/展开状态插值，尚未使用上下观察的专门布光。节点旋转使用 quaternion.slerp，避免跨越角度边界时绕远路。产品旋转还会同步材质环境朝向，避免把固定模型、旋转相机的参考直接搬进旋转产品的工程。

### 为什么镜头、背板要分开布光

官网主场景除了手机 glTF，还定义了材质分层、透明混合、两张 EXR 和几套随角度变化的棚拍场景。忽略这次交接，镜头可能变成黑圆片，背板和金属也容易被同一组灯照得灰平。

当前代码的链路是：

| 资产配置 layer | 环境来源 | 接入位置 |
|---|---|---|
| 0、1 | studio/body.gltf、studio/details.gltf：网格、渐变遮罩、视角配置 | useStudioMaps → CubeCamera → PMREMGenerator.fromCubemap → 材质 envMap |
| 2 | studio/metal.gltf：原金属灯棚及视角配置 | 同样生成独立 PMREM → 材质 envMap |
| 4、5 | lens-reflections.exr、surface-reflections.exr | useEnvironment → 材质 envMap |

这些数字是本资产的角色映射，不是 Three.js 规定的层号。model-materials 根据 asset-materials 中的 layer 选择贴图，并修正环境朝向。bodyEnvironmentIntensity 只调第 0 层，不再通过提高全局曝光来照亮背板。

asset-materials 还保存透明度与混合模式。例如镜头内部的 FVyIOhmektXDyZR 使用叠加混合；只保留 glTF 中的普通透明混合会改变层叠后的效果。后摄保护玻璃 hkSmvYqlDNAQojv 使用标准 specularColor 替代尚未接入的边缘反射扩展，lensReflectionIntensity 单独调节保护玻璃反射；它不会把镜头内部的所有材质一并提亮。

棚拍网格只在离屏场景中被捕获，不会作为手机旁边的白板显示。PMREM 提供不同模糊程度的环境采样，让粗糙表面与抛光表面能使用合适的反射。变化时更新、静止时复用，卸载时释放渲染目标。机身与细节层当前也采用节点插值；参考对这两层使用的是环境结果 crossfade，二者不是同一种实现。

## 第三步：找到你真正要改的材质

原 glTF 的材质名多数不表达业务含义。`model-materials.ts` 中的 polishedMetal 是本资产核对过的名称集合，属于资产适配信息。换模型时应重建这个映射，不要把这些字符串当通用名称。

函数先 `source.clone()`，再按角色修改，其他表面保留来源参数。以下是实际逻辑：

```ts
if (polishedMetal.has(material.name)) {
  material.roughness = Math.min(1, Math.max(0, material.roughness * materialConfig.metalRoughnessScale));
}
```

`metalRoughnessScale` 是选定材质粗糙度的倍率，当前为 1，保留源材质的抛光程度。不同零件仍有各自的粗糙度；把倍率升到 2，可以观察亮条变宽、变模糊，再恢复。不要为所有金属强设同一个粗糙度下限。

如果材质还有 roughnessMap，最终粗糙度还受贴图通道影响。单改数值没有预期变化时，应检查材质与贴图的共同作用。glTF 的 metallic-roughness 贴图通常把粗糙度放在 G、金属度放在 B；不要把一张灰度图随意塞到所有通道。

### 新增一个材质规则时怎样接入

这是对 `prepareMaterials` 内 `localMaterial` 函数的局部修改方法：

1. 在源 glTF 确认目标 mesh 使用哪个 material，记录其真实名称。
2. 在 `viewer-config.ts` 的 materialConfig 新增一个有意义的参数名。
3. 在 `material instanceof MeshStandardMaterial` 分支里，用真实材质名称匹配，只修改需要的属性。
4. 刷新后观察目标部件，同时确认其他部件没有跟着变化。

例如，在已确认名称的前提下，可以使用这样的**模式示意**，其中字符串必须换成实际资产名称：

```ts
if (material.name === '这里填写实际材质名') {
  material.roughness = 0.35;
}
```

这是修改位置示意，不是要求往项目里加入一个匹配不到对象的分支。最初应保留原 color、normalMap、metalnessMap 等，只改一个有依据的变量。

### 为什么复制纹理对象

材质 clone 后仍可能引用共享纹理。当前要调整 anisotropy，所以另外复制 Texture 对象；它仍可复用图片像素，但拥有自己的采样设置。

不能遍历全部贴图统一设成 sRGB。颜色图和法线、粗糙度等数据图有不同含义，加载器处理过的 colorSpace、UV channel、flipY 应先保留。手动换图时才根据用途设置，详细规则见 [通识的颜色校准](../../04-材质灯光与色彩校准.md)。

## 第四步：把屏幕显示与机身照明分开调

交付资产中的内外屏图片分别是 `screen-inner.png`、`screen-outer.png`，并映射到两个 `PracticeScreen_` 材质。运行时适配器给它们设置：

| 参数 | 代码中的作用 |
|---|---|
| emissive = 白色 | 保留屏幕图本来的配色，不额外染色 |
| screenBrightness | 乘到发光贡献，控制内容亮度 |
| screenRoughness | 保留的材质参数；当前关闭屏幕反射，不承担视觉调节 |
| screenClearcoat | 当前为 0，关闭屏幕上层亮条 |
| envMap = null、specularIntensity = 0 | 屏幕显示图不叠加环境强光，金属反射不受影响 |

屏幕保留 Physical 材质类型，但现在只显示发光贴图，关闭环境和镜面反射；它并不等于原站的专用材质实现。[MeshPhysicalMaterial](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)

当前屏幕是静态合成：用原山丘、沙丘网格和 UV 离线投影，再合成天空与锁屏 UI，得到可直接加载的 PNG。已修正裁切纹理的 UV 区域和 V 轴方向；取景仍是近似，没有复现原相机、LUT、动态调色和视差；这一部分在来源清单中记录。纵向姿态会带着整张图旋转，尚未切换为重新排版的纵向 UI；产品姿态与屏幕内容布局是两条独立的控制链。

**动手**：把 screenBrightness 从 1 改为 0.8，其他设置不变。屏幕变暗而机身照明不应跟着改变。再恢复。若整个产品都偏暗，应先查环境，不应只抬屏幕亮度。

## 第五步：最后检查曝光和输出

`product-demo.tsx` 的 Canvas 明确设置 ACES tone mapping，并读取 `renderConfig.exposure`。曝光影响开启 tone mapping 的材质。屏幕采用 toneMapped=false，避免已合成的显示图再次被 ACES 压缩；屏幕亮度由 screenBrightness 独立控制。

调校顺序保持：

```text
模型比例与相机 → 纹理读取 → 环境亮暗结构 → 单个材质 → 曝光与最终对照
```

调曝光前，先确认没有错误的颜色空间、缺失的环境、反射扩展丢失或过小的取景。否则画面可能从“黑”变成“发白”，原因仍然没有解决。

## 留下能复用的调校记录

不需要写大篇报告。每次重要修改记录四件事：

```text
现象：侧框几乎整片发黑，只有很细的亮线。
位置：studio/metal.gltf 的反射输入，以及 use-studio-maps.ts 的捕获。
改动：接回原灯棚、渐变遮罩与视角状态；曝光和金属粗糙度保持不变。
验证：正面、斜角和纯侧面比较，亮面与暗条可辨，不要求每个角度都同样亮。
```

当前 demo 已改善取景、采样、环境和屏幕输入，但仍与官网有材质和动态壁纸差异。评价完成度应对照实际截图与操作，不把“代码能运行”或“参数已提高”当作视觉验收通过。

继续读 [05-展示效果与交互调校复盘](./05-展示效果与交互调校复盘.md)，把这些视觉问题与角度、惯性和吸附串起来复习。
