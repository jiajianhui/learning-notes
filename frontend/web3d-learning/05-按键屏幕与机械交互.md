# 05. 让数字手办可以操作

本章属于 [第二阶段](./projects/02-chaz-digital-toy/README.md)。第一阶段已有的骨骼动画采样见 [iPhone 工程串联](./projects/01-iphone-duo/02-从页面到每一帧.md)，不要直接给那份模型假设 `HingePivot` 或 `PowerButton` 节点。

有质感的模型解决“像什么”，交互解决“可以做什么”。本章继续使用自己的 `phone.glb`，先让一个按钮控制屏幕，再加入一个机械动作。

状态主线保持很小：

```text
点击网页按钮或模型按键
    → React 状态改变
    → 屏幕材质或部件目标角度改变
    → 下一帧显示新的结果
```

## 第一步：让模型内部可以直接编辑

第 03 章用 `<primitive object={scene} />` 整体显示 GLB。现在需要给指定部件绑定事件，使用 gltfjsx 生成组件。

在 `projects/phone-lab/` 执行：

```bash
npx gltfjsx public/models/phone.glb --types --keepnames --keepgroups --output components/phone.tsx
```

`--keepnames` 保留名称，`--keepgroups` 保留分组。机械结构需要父级轴心，所以本轮不使用自动压平、合并或激进优化。具体选项见 [gltfjsx 官方说明](https://github.com/pmndrs/gltfjsx)。

打开生成文件，完成四项核对：

1. 在文件顶部添加 `'use client';`，合并重复的 import。
2. 将 `useGLTF` 和 `useGLTF.preload` 中的模型 URL 都核对为 `/models/phone.glb`。
3. 检查 `Body`、`Frame`、`Screen`、`PowerButton` 对应的节点和材质名称。
4. 保留生成的所有局部坐标、旋转、缩放和父子关系，先原样显示一次。

生成的 TypeScript 类型和访问名称以实际文件为准。如果没有 `nodes.Screen`，先回 Blender 修名称或按生成结果定位，不凭教程强行添加一个不存在的属性。

用生成文件实际导出的组件替换第 03 章的 `PhoneModel`。例如生成的是命名导出 `Model`，可以写：

```tsx
import { Model as Phone } from './phone';
```

然后在原来的 `Bounds` 中使用 `<Phone />`。这是导出别名，不要求修改生成文件的导出名称。

**检查点**：转换前后外观和部件位置一致。gltfjsx 负责可编辑性，不负责自动提升材质。

## 第二步：用一个状态控制开关机

下面以生成组件名为 `Model` 举例，所有内容都是对现有文件的局部修改。

在 `material-lab.tsx` 的 `MaterialLab` 函数中新增状态和回调：

```tsx
const [powered, setPowered] = useState(false);
const togglePower = () => setPowered((current) => !current);
```

`current` 是 React 提供的上一次状态；用它切换，避免依赖某次渲染捕获的旧值。

在 `.controls` 中增加一个普通 HTML 按钮，并把状态传给 3D 组件：

```tsx
<button aria-pressed={powered} onClick={togglePower}>
  {powered ? '关机' : '开机'}
</button>

// 原 Bounds 内的 Phone 改成：
<Phone powered={powered} onPower={togglePower} />
```

上面是两个位置的片段，注释不是要渲染的文字。网页按钮与模型按钮共用一个回调；键盘用户也能使用普通按钮。

在 `phone.tsx` 中，导入 `ThreeElements` 类型，并将生成组件的 props 类型和函数参数改成：

```tsx
import type { ThreeElements } from '@react-three/fiber';

type PhoneProps = ThreeElements['group'] & {
  powered: boolean;
  onPower: () => void;
};

// 保留原函数体及生成的节点 JSX。
export function Model({ powered, onPower, ...props }: PhoneProps) {
  // 原来的 useGLTF、return 等继续保留。
}
```

`powered` 是要显示的状态，`onPower` 是父组件传来的操作。把这两个参数取出后，`...props` 才继续传给原根 group，避免把自定义业务属性写到 Three.js 对象上。

## 第三步：让模型按键与屏幕连起来

在生成的 `PowerButton` mesh 上增加以下属性，保留原来的 geometry、material 和变换：

```tsx
onClick={(event) => {
  event.stopPropagation();
  if (event.delta > 4) return;
  onPower();
}}
```

`event.delta` 是按下到释放的移动距离，这里用 4 像素作为起始阈值，减少旋转结束时误触开机。阈值要用真实触屏测试。

R3F 的射线事件可能传给更远的物体，`stopPropagation()` 还能阻止继续穿透。给整个模型的根 group 加 `onClick={(event) => event.stopPropagation()}`，使最近命中的机壳也能挡住后面的按钮；不要让不可见的背面按键隔着机身触发。[R3F Events](https://r3f.docs.pmnd.rs/api/events)

在 `Screen` mesh 上移除原 `material={...}`，改为给它添加子材质：

```tsx
<meshPhysicalMaterial
  color="#080b10"
  metalness={0}
  roughness={0.12}
  clearcoat={1}
  clearcoatRoughness={0.08}
  emissive={powered ? '#76bfff' : '#000000'}
  emissiveIntensity={powered ? 0.7 : 0}
/>
```

如果原 mesh 是自闭合标签，改成成对标签再放材质。这一步只让屏幕切换明暗，先证明事件和状态已经连通。

它使用独立的声明式屏幕材质，不会为了亮屏去修改所有部件共用的原始材质。其他部件继续使用导出的 PBR 材质。

**检查点**：网页按钮与机身按键控制同一块屏幕；拖动旋转不频繁误触；点击外壳不会触发背面的键；关机后仍看得到表面反光。

## 第四步：给亮屏加一张真实内容图

先准备一张自己的简单菜单图，放到 `public/textures/screen-home.png`。图片比例与屏幕 UV 一致，先写“菜单”和几个图标就够，不需要复刻整个手机系统。

在 `phone.tsx` 导入 `useTexture`、`useEffect` 和 `SRGBColorSpace`，在 `Model` 内增加：

```tsx
const screenHome = useTexture('/textures/screen-home.png');

useEffect(() => {
  screenHome.colorSpace = SRGBColorSpace;
  screenHome.flipY = false;
  screenHome.needsUpdate = true;
}, [screenHome]);
```

这是此处唯一使用的屏幕颜色纹理。`flipY` 与第 04 章讲到的 glTF 替换纹理约定一致。

给刚才的屏幕材质增加 `emissiveMap={screenHome}`，并把 `emissive` 改成：

```tsx
emissive={powered ? '#ffffff' : '#000000'}
```

白色让图片保留原有配色，黑色关闭其发光贡献。此时 `emissiveIntensity` 继续使用上一步的设置。`useTexture` 也会等待资源，所以整个 Phone 继续放在原 `Suspense` 中。

以后要显示动态时间或菜单，可研究 `CanvasTexture`；要播放自己的视频，再研究 `VideoTexture`。这些属于后续扩展，不是当前例子已经完成的功能。普通 DOM 信息面板也可以放在画布外，不必把所有文字都做成纹理。

## 第五步：先把机械结构做好，再写动画

如果第一件设备是直板手机，本步可用一个独立小盖子练习。滑盖或翻盖模型则在 Blender 里建立对应结构：

```text
PhoneRoot
├── Body
└── HingePivot       原点在铰链位置
    └── Lid          网格相对于轴心偏移
        └── Screen
```

转动的是 `HingePivot`，不是绕盖子中心旋转整个网格。先在 Blender 中转动父级，确认动作成立，再导出、重新生成组件。重新生成会覆盖手工改动，使用新文件对照合并，保留前面的状态和事件修改。

两种方式选择一种即可：

- 只有一个角度或位移：在 R3F 中控制 group，适合本章。
- 已经在 Blender 做好多部件动作：导出命名动画，再用 Drei `useAnimations` 驱动；不要同时用两套系统写同一个对象的同一属性。

下面提供第一种方式的完整组件，新增 `components/hinge.tsx`：

```tsx
'use client';

import { useRef } from 'react';
import type { ReactNode } from 'react';
import { useFrame } from '@react-three/fiber';
import type { ThreeElements } from '@react-three/fiber';
import { Group, MathUtils } from 'three';

type HingeProps = Omit<ThreeElements['group'], 'children'> & {
  opened: boolean;
  children: ReactNode;
};

export default function Hinge({ opened, children, ...props }: HingeProps) {
  const hinge = useRef<Group>(null);

  useFrame((_, delta) => {
    if (!hinge.current) return;
    const target = opened ? -Math.PI * 0.65 : 0;
    hinge.current.rotation.x = MathUtils.damp(
      hinge.current.rotation.x, target, 10, Math.min(delta, 0.05),
    );
  });

  return (
    <group {...props}>
      <group ref={hinge}>{children}</group>
    </group>
  );
}
```

外层 group 保留导出后的轴心变换，内层从零开始施加动画。示例假定活动轴是**导出后的局部 X 轴**，角度和正负方向都需要按自己的模型核对。滑盖对应改变 position 的某一分量，而不是 rotation。

接入步骤：

1. 在 `MaterialLab` 添加 `opened` 状态和开合 HTML 按钮，如同前面的 `powered`。
2. 给 Phone props 增加 `opened: boolean`，把状态传进去。
3. 在 `phone.tsx` 导入 Hinge，把生成的 `HingePivot` group 改成 Hinge，保留该 group 的 position、rotation、scale 和原有 children，并增加 `opened={opened}`。
4. 暂时将 Canvas 的 `frameloop` 改为 `"always"`，移除只捕获一帧的接触阴影，先确认运动本身正确。

`delta` 是这一帧距上一帧的秒数。使用带 delta 的阻尼，能减少高刷新率与低刷新率设备动画速度不同的问题；截断很大的 delta 可减轻切回页面时突然跳动。

`useFrame` 直接更新 Three.js 对象，不要每帧调用 `setState`。React 状态只表示“要打开还是关闭”，具体中间角度交给每帧更新。

**检查点**：开合围绕真实铰链；屏幕随盖子移动；连续快速切换不会穿过机身或绕错方向。可旋转展示的阴影与反射近似也要在开合后复查。

## 最后再处理交互细节

当前开机使用点击，先不实现长按开机。要增加长按时，再处理按下、移出、取消和释放；不能只加一个定时器就认为完成。

继续做成作品时，按顺序补：

1. 按钮的按下反馈和光标提示。
2. 重置相机视角。
3. 限制不合理的机械行程。
4. 移动端的点击与旋转冲突。
5. 开关机状态下不同按钮的行为。

不要一开始引入物理引擎模拟铰链。明确的产品机械动作，用受控状态和轴心就能先完成。最终验收见 [第 06 章](./06-数字手办项目与验收.md)。
