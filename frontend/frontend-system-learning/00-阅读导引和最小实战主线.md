# 00. 阅读导引和最小实战主线

## 问题背景

只看技术地图，容易有一种感觉：每一层都懂一点，但不知道怎么落到真实代码里。

对初级前端来说，更好的办法不是同时做很多不同项目，而是用同一个小功能，在不同技术层里反复实现。这样你能看清楚：同一个问题，用原生 DOM、Vanilla TS、Vue、React、路由、状态管理分别怎么解决。

本文属于七层体系中的第七层：学习方法层。它不是新增一个技术层，而是给你一条可动手的练习路线。

```text
前六层：告诉你技术分别是什么
本文：告诉你怎么用一个小功能把它们串起来
```

这篇建议先浏览，不要求第一次就完全看懂。它更像一张路线预告：后面每学完一层，你都可以回来对照一次。

## 核心解释

### 为什么建议用同一个小功能

如果你每学一个技术都换一个项目，很容易分不清：

- 是业务功能变了？
- 是框架写法变了？
- 是工具链变了？
- 还是项目结构变了？

用同一个小功能反复实现，变量更少，理解更稳定。

推荐从一个“计数器 + 列表”的小功能开始：

```text
功能一：点击按钮，数字加一
功能二：输入文字，添加到列表
功能三：列表项可以删除
功能四：切换两个页面：计数器页 / 列表页
功能五：多个页面共享一个简单状态
```

它足够小，但能覆盖现代前端的关键概念：

| 功能点 | 能练到什么 |
|---|---|
| 点击按钮 | 事件处理 |
| 数字变化 | 状态 |
| 添加列表 | 表单、数组、渲染 |
| 删除列表项 | 数据更新 |
| 页面切换 | 路由 |
| 共享状态 | store / 全局状态 |

## 技术关系

### 阶段一：HTML / CSS / JavaScript

目标：先用最基础方式做出来。

```text
index.html
style.css
main.js
```

你重点体会：

- HTML 负责结构。
- CSS 负责样式。
- JavaScript 负责事件和数据。
- DOM 是 JS 改页面的接口。

典型代码：

```js
let count = 0;
const button = document.querySelector("#add");
const output = document.querySelector("#count");

button.addEventListener("click", () => {
  count += 1;
  output.textContent = String(count);
});
```

这一步不要急着上框架。你要先知道框架后来到底帮你省了什么。

### 阶段二：Vite + Vanilla TS

目标：在不使用 React/Vue 的情况下，先接触现代项目结构。

```text
src/
  main.ts
index.html
package.json
vite.config.ts
tsconfig.json
```

你重点体会：

- `npm run dev` 如何启动项目。
- `main.ts` 是入口文件。
- TypeScript 如何给变量、函数、DOM 元素加类型。
- Vite 只是工程化工具，不等于 React/Vue。

典型代码：

```ts
const button = document.querySelector<HTMLButtonElement>("#add");
const output = document.querySelector<HTMLSpanElement>("#count");

let count = 0;

button?.addEventListener("click", () => {
  count += 1;
  if (output) output.textContent = String(count);
});
```

这一步特别适合理解：为什么有些项目有 Vite 和 TypeScript，但没有 React/Vue。

### 阶段三：用 Vue 重写同一个功能

目标：理解组件化和数据驱动视图。

```text
src/
  main.ts
  App.vue
```

你重点体会：

- `createApp(App).mount("#app")` 是 Vue 项目入口。
- `.vue` 文件把模板、逻辑和样式组织在一起。
- 数据变化后，界面自动更新。

典型代码：

```vue
<script setup lang="ts">
import { ref } from "vue";

const count = ref(0);
</script>

<template>
  <button @click="count++">点击 {{ count }} 次</button>
</template>
```

对比原生 DOM，你会发现：你不再手动找元素、改文本，而是改数据。

### 阶段四：用 React 重写同一个功能

目标：理解 React 的组件、JSX 和状态。

```text
src/
  main.tsx
  App.tsx
```

你重点体会：

- `main.tsx` 是 React 项目常见入口。
- JSX/TSX 是用 JavaScript 描述 UI。
- `useState` 管组件状态。

典型代码：

```tsx
import { useState } from "react";

export function App() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      点击 {count} 次
    </button>
  );
}
```

这一步要重点对比 Vue：思想相通，表达方式不同。

### 阶段五：加前端路由

目标：把“一个功能”扩展成“多个页面”。

```text
/counter
/todos
```

你重点体会：

- 路由不是 UI 框架本身。
- 路由负责 URL 和页面组件的对应关系。
- React 常见 React Router，Vue 常见 Vue Router。

项目结构可能变成：

```text
src/
  pages/
    CounterPage.tsx
    TodoPage.tsx
  router.tsx
```

或：

```text
src/
  pages/
    CounterPage.vue
    TodoPage.vue
  router.ts
```

### 阶段六：加状态管理

目标：让多个页面或远距离组件共享状态。

你重点体会：

- 组件内部状态不一定要放进 store。
- 多个组件都需要的数据，才考虑 store。
- React 常见 Zustand / Redux，Vue 常见 Pinia。

比如：

```text
计数器页修改 count
列表页也能看到 count
```

这时你就能真正理解 `props`、`state`、`store` 的区别。

### 阶段七：再看 Next.js / Nuxt.js

目标：理解应用框架为什么更上层。

当你已经知道 React/Vue、路由、状态管理和 Vite 的位置后，再看 Next/Nuxt 会清楚很多：

```text
Next.js：基于 React，额外提供应用结构、路由约定、渲染模式
Nuxt.js：基于 Vue，额外提供应用结构、路由约定、渲染模式
```

这时你再看到 `app/`、`pages/`、`next.config.ts`、`nuxt.config.ts`，就不会把它们和普通 Vite 项目混在一起。

## 学习建议

### 不要每一步都追求完整项目

每个阶段只做最小功能就够：

```text
能跑起来
能点击
能显示数据
能看出项目结构差异
```

不要一开始就加登录、权限、接口、数据库、部署。那些会把学习焦点打散。

### 每完成一版，都问三个问题

```text
这版项目的入口文件是什么？
这版项目用了哪一层技术？
同一个功能相比上一版，写法变化在哪里？
```

比如从 Vanilla TS 到 Vue，你应该能说出：

```text
入口从 main.ts 变成 createApp(App).mount("#app")
UI 从手动 DOM 操作变成 Vue 模板
状态从普通变量变成 ref
```

这比单纯“我学过 Vue”更扎实。

## 小结

这条实战主线的核心不是做一个多厉害的项目，而是让你用同一个小功能穿过现代前端的主要层级：

```text
HTML/CSS/JS
  -> Vite + Vanilla TS
  -> Vue
  -> React
  -> 路由
  -> 状态管理
  -> Next/Nuxt
```

你会慢慢形成一种能力：看到新技术时，不慌，先判断它改变的是哪一层。
