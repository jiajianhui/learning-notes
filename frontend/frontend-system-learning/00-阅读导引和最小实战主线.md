# 00. 阅读导引和最小实战主线

## 问题背景

初学者最容易犯的错误不是学得不够多，而是学得太散。

每学一个新技术就换一个新项目，结果分不清：是业务逻辑变了？是框架语法变了？还是项目结构变了？

这篇文档只做一件事：用同一个“计数器 + 列表”小功能，穿过现代前端的主要层级。

原则很简单：

```text
一个小项目，多种实现方式。
功能不变，只换技术层。
```

这样你就能看清楚：哪些变化来自业务本身，哪些变化来自 JavaScript、TypeScript、Vite、React、Vue、Router、Store 或 Next/Nuxt。

这篇建议先浏览，不要求第一次就完全看懂。它更像一张路线预告：后面每学完一层，你都可以回来对照一次。

## 核心解释

### 1. 只做一个小功能：功能不变，技术层变化

全程功能保持不变：

```text
1. 点击按钮，数字加一
2. 输入文字，添加到列表
3. 列表项可以删除
4. 切换两个页面：计数器页 / 列表页
5. 两个页面共享同一个 count 值
```

这个功能很小，但刚好覆盖前端的核心概念：

| 功能点 | 练到什么 |
|---|---|
| 点击按钮 | 事件处理 |
| 数字变化 | 状态 |
| 添加列表 | 表单、数组、渲染 |
| 删除列表项 | 数据更新 |
| 页面切换 | 路由 |
| 共享 count | 全局状态 / store |

### 2. 七个阶段：同一个功能穿过七层

| 阶段 | 技术 | 这一阶段新增什么 | 数据 / 状态放哪里 | 页面怎么更新 | 参考时间 |
|---|---|---|---|---|---|
| 一 | HTML / CSS / JS | 原生页面交互 | 普通变量 | 手动 DOM 操作 | 半天到 1 天 |
| 二 | Vite + Vanilla TS | 工程化和类型提示 | 普通变量 + 类型 | 手动 DOM 操作 | 半天到 1 天 |
| 三 | Vue 3 | 组件和响应式 | `ref()` / `reactive()` | 响应式自动更新 | 1 到 2 天 |
| 四 | React | 组件和 Hooks | `useState()` | 状态变化后重新渲染 | 1 到 2 天 |
| 五 | 前端路由 | URL 对应页面组件 | 业务状态仍在组件或 store，URL 只保存页面位置 / 参数 | 切换页面组件，不整页刷新 | 半天 |
| 六 | 状态管理 | 跨页面 / 跨组件共享数据 | store | 多组件共享更新 | 半天到 1 天 |
| 七 | Next / Nuxt | 约定式应用结构和渲染模式 | 先按框架约定拆页面、组件和数据 | CSR / SSR / SSG 按框架约定工作 | 读入门即可 |

注意：路由确实也会涉及“当前 URL、路径参数、查询参数”这类导航信息，但它不是用来管理计数器、待办列表、登录用户这类业务状态的。初学时先记住一句话：Router 管页面位置，Store 管共享数据。读完 `08` 后，可以接着看 `09`，再把这两个能力加进 demo。

从 Vanilla TS 到 Vue / React 是一次明显跳跃，卡住很正常。你不是“基础差”，而是正在从“手动操作页面”切换到“用数据描述界面”。

### 3. 先记住这些判断句：不要把所有现象都归因于框架

这些句子比记 API 更重要。后面每遇到一个项目，都可以先用它们判断“到底是谁在工作”。

| 你看到的现象 | 背后真正负责的是 |
|---|---|
| 执行 `npm run dev` | npm 读取 `package.json`，再启动对应命令 |
| 页面能在 `localhost` 打开 | Vite 或其他开发服务器在工作 |
| 修改代码后页面自动刷新 | 开发服务器的热更新在工作 |
| `.ts` 能在浏览器里运行 | TypeScript 被工具转换成 JavaScript |
| `.tsx` / JSX 能显示页面 | React 插件和构建工具先把 JSX 转成 JS |
| `.vue` 文件能显示页面 | Vue 插件和构建工具解析了单文件组件 |
| 数据变了页面自动变 | React 或 Vue 的渲染机制在工作 |
| URL 变了但页面不整页刷新 | 前端路由在工作 |
| 两个远距离组件共享同一份数据 | store / 状态管理在工作 |

所以不要把所有现象都归因于 React 或 Vue。现代前端项目是多层技术一起配合的结果。

## 技术关系

### 阶段一：纯 HTML + CSS + JavaScript，先手动操作页面

目标：先不依赖任何工具，把功能跑起来。

文件结构：

```text
index.html
style.css
main.js
```

计数器实现：

```js
let count = 0;
const btn = document.querySelector("#add");
const output = document.querySelector("#count");

btn.addEventListener("click", () => {
  count += 1;
  output.textContent = String(count);
});
```

列表实现：

```js
const input = document.querySelector("#todo-input");
const addBtn = document.querySelector("#todo-add");
const list = document.querySelector("#todo-list");

const todos = [];

addBtn.addEventListener("click", () => {
  const text = input.value.trim();
  if (!text) return;

  todos.push(text);
  input.value = "";
  renderList();
});

function renderList() {
  list.innerHTML = "";

  todos.forEach((item, index) => {
    const li = document.createElement("li");
    li.textContent = item;

    const del = document.createElement("button");
    del.textContent = "删除";
    del.addEventListener("click", () => {
      todos.splice(index, 1);
      renderList();
    });

    li.appendChild(del);
    list.appendChild(li);
  });
}
```

这一步你要感受：

- DOM 是 JavaScript 和 HTML 沟通的接口。
- 数据变化后，你要手动更新页面。
- 功能一复杂，手动 DOM 操作会很繁琐。

关键判断：

```text
这一步没有 Node、npm、Vite、React、Vue。
浏览器直接加载 HTML/CSS/JS。
页面变化来自你手动操作 DOM。
```

完成标准：能点击加一、能添加列表、能删除列表项。样式不好看没关系。

### 阶段二：Vite + Vanilla TypeScript，先接触工程化

目标：不用框架，先接触现代项目结构和 TypeScript。

初始化：

```bash
npm create vite@latest my-app -- --template vanilla-ts
cd my-app
npm install
npm run dev
```

文件结构：

```text
src/
  main.ts
index.html
package.json
vite.config.ts
tsconfig.json
```

计数器实现：

```ts
const btn = document.querySelector<HTMLButtonElement>("#add")!;
const output = document.querySelector<HTMLSpanElement>("#count")!;

let count: number = 0;

btn.addEventListener("click", () => {
  count += 1;
  output.textContent = String(count);
});
```

实际项目里也经常写成 `let count = 0`，因为 TypeScript 会根据 `0` 自动推断出 `count` 是 `number`。这里显式写成 `count: number`，是为了让你先看见“类型标注”这件事。

列表实现：

```ts
const input = document.querySelector<HTMLInputElement>("#todo-input")!;
const addBtn = document.querySelector<HTMLButtonElement>("#todo-add")!;
const list = document.querySelector<HTMLUListElement>("#todo-list")!;

const todos: string[] = [];

addBtn.addEventListener("click", () => {
  const text = input.value.trim();
  if (!text) return;

  todos.push(text);
  input.value = "";
  renderList();
});

function renderList() {
  list.innerHTML = "";

  todos.forEach((item, index) => {
    const li = document.createElement("li");
    li.textContent = item;

    const del = document.createElement("button");
    del.textContent = "删除";
    del.addEventListener("click", () => {
      todos.splice(index, 1);
      renderList();
    });

    li.appendChild(del);
    list.appendChild(li);
  });
}
```

这一步你要感受：

- `npm run dev` 背后是 Vite 在工作，不是 React 或 Vue。
- TypeScript 先从“给变量和 DOM 元素加类型”开始就够。
- Vite 和 TypeScript 可以服务于无框架项目。

关键判断：

```text
npm 负责执行 package.json 里的 dev 命令。
Vite 负责启动开发服务器。
TypeScript 负责类型提示和类型检查。
页面更新仍然来自你手动操作 DOM。
```

对比上一阶段：功能写法几乎一样，但项目结构更接近真实工程，多了类型检查。

### 阶段三：Vue 3，用响应式数据更新页面

目标：理解组件化和数据驱动视图。

初始化：

```bash
npm create vite@latest my-app -- --template vue-ts
```

文件结构：

```text
src/
  main.ts
  App.vue
  components/
    Counter.vue
    TodoList.vue
```

计数器实现：

```vue
<script setup lang="ts">
import { ref } from "vue";

const count = ref(0);
</script>

<template>
  <button @click="count++">点击 {{ count }} 次</button>
</template>
```

列表实现：

```vue
<script setup lang="ts">
import { ref } from "vue";

const input = ref("");
const todos = ref<string[]>([]);

function add() {
  if (!input.value.trim()) return;
  todos.value.push(input.value.trim());
  input.value = "";
}

function remove(index: number) {
  todos.value.splice(index, 1);
}
</script>

<template>
  <div>
    <input v-model="input" placeholder="输入待办" />
    <button @click="add">添加</button>

    <ul>
      <li v-for="(item, index) in todos" :key="index">
        {{ item }}
        <button @click="remove(index)">删除</button>
      </li>
    </ul>
  </div>
</template>
```

这一步你要感受：

- 你不再手动找 DOM、改文本。
- `ref()` 让数据变成响应式。
- `.vue` 文件把模板、逻辑、样式组织在一个组件里。

关键判断：

```text
Vite 仍然负责开发服务器。
Vue 负责把数据变化反映到页面。
@vitejs/plugin-vue 负责让 .vue 文件能被项目理解。
```

对比上一阶段：同样的功能，删除了大量 `querySelector` 和手动 DOM 更新。

### 阶段四：React，用状态和 JSX 描述页面

目标：理解 React 的组件、JSX 和 `useState`。

初始化：

```bash
npm create vite@latest my-app -- --template react-ts
```

文件结构：

```text
src/
  main.tsx
  App.tsx
  components/
    Counter.tsx
    TodoList.tsx
```

计数器实现：

```tsx
import { useState } from "react";

export function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      点击 {count} 次
    </button>
  );
}
```

列表实现：

```tsx
import { useState } from "react";

export function TodoList() {
  const [input, setInput] = useState("");
  const [todos, setTodos] = useState<string[]>([]);

  function add() {
    if (!input.trim()) return;
    setTodos([...todos, input.trim()]);
    setInput("");
  }

  function remove(index: number) {
    setTodos(todos.filter((_, i) => i !== index));
  }

  return (
    <div>
      <input value={input} onChange={(event) => setInput(event.target.value)} />
      <button onClick={add}>添加</button>

      <ul>
        {todos.map((item, index) => (
          <li key={index}>
            {item}
            <button onClick={() => remove(index)}>删除</button>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

这一步你要感受：

- JSX 是用 JavaScript 描述 UI。
- `useState` 返回“值 + 更新函数”。
- React 倾向不可变更新，比如 `setTodos([...todos, item])`。

关键判断：

```text
Vite 仍然负责开发服务器。
React 负责组件渲染和状态更新后的 UI 变化。
@vitejs/plugin-react 负责让 JSX/TSX 能被项目理解。
```

对比 Vue：React 和 Vue 都是“数据变，页面跟着变”的框架。区别是：React 更强调用 JavaScript 管理和表达 UI，更新状态时倾向创建新数据；Vue 更像写增强版 HTML 模板，语法更接近传统前端。

React 常见写法：

```tsx
function TodoList() {
  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id}>{todo.text}</li>
      ))}
    </ul>
  );
}
```

Vue 常见写法：

```vue
<template>
  <ul>
    <li v-for="todo in todos" :key="todo.id">
      {{ todo.text }}
    </li>
  </ul>
</template>
```

做完 Vue / React 两个版本后，如果卡在箭头函数、`return`、对象、数组更新、`splice` / `filter` 这些语法点，回看 `06A 做完 Vue / React 后的 JS 语法补洞`。

### 阶段五：加前端路由，让 URL 对应页面

目标：把单页面扩展成多页面。这里以 React Router 为例，Vue Router 同理。

安装：

```bash
npm install react-router-dom
```

文件结构：

```text
src/
  main.tsx
  router.tsx
  pages/
    CounterPage.tsx
    TodoPage.tsx
```

路由配置：

```tsx
import { createBrowserRouter } from "react-router-dom";
import { CounterPage } from "./pages/CounterPage";
import { TodoPage } from "./pages/TodoPage";

export const router = createBrowserRouter([
  { path: "/", element: <CounterPage /> },
  { path: "/todos", element: <TodoPage /> },
]);
```

入口文件：

```tsx
import ReactDOM from "react-dom/client";
import { RouterProvider } from "react-router-dom";
import { router } from "./router";

ReactDOM.createRoot(document.getElementById("root")!).render(
  <RouterProvider router={router} />
);
```

导航：

```tsx
import { Link } from "react-router-dom";

export function Nav() {
  return (
    <nav>
      <Link to="/">计数器</Link>
      <Link to="/todos">待办列表</Link>
    </nav>
  );
}
```

这一步你要感受：

- 路由不属于 React 或 Vue 本体，它是应用组织层。
- URL 的变化对应不同页面组件。
- SPA 中页面切换不一定触发整页刷新。

关键判断：

```text
React 仍然负责渲染组件。
React Router 负责 URL 和页面组件的对应关系。
Link 负责在前端切换页面，而不是让浏览器整页跳转。
```

### 阶段六：加状态管理，让远距离组件共享数据

目标：让计数器页和列表页共享同一个 `count` 值。这里以 Zustand 为例，Vue 用 Pinia 同理。

安装：

```bash
npm install zustand
```

创建 store：

```ts
import { create } from "zustand";

type CountStore = {
  count: number;
  increment: () => void;
};

export const useCountStore = create<CountStore>((set) => ({
  count: 0,
  increment: () => set((state) => ({ count: state.count + 1 })),
}));
```

计数器页使用：

```tsx
import { useCountStore } from "../store/useCountStore";

export function CounterPage() {
  const { count, increment } = useCountStore();

  return <button onClick={increment}>点击 {count} 次</button>;
}
```

列表页读取：

```tsx
import { useCountStore } from "../store/useCountStore";

export function TodoPage() {
  const count = useCountStore((state) => state.count);

  return <p>当前计数：{count}</p>;
}
```

这一步你要感受：

- 组件内部状态和全局状态不是一回事。
- 不是所有状态都要放进 store。
- 多个页面或远距离组件都需要的数据，才考虑 store。

关键判断：

```text
React 的 useState 适合组件内部状态。
Zustand / Pinia 这类 store 适合跨组件共享状态。
Router 管页面切换，Store 管共享数据，不要混成一件事。
```

### 阶段七：看 Next.js / Nuxt.js，理解更上层的应用框架

目标：理解应用框架为什么更上层。

当你已经亲手做过前六个阶段，再看 Next/Nuxt 会清楚很多：

```text
Next.js = React + 文件路由约定 + 渲染模式 + 应用结构
Nuxt.js = Vue + 文件路由约定 + 渲染模式 + 应用结构
```

它们不是“更厉害的 React/Vue”，而是在 React/Vue 之上又加了一层应用约定。

| 普通 Vite 项目里你要做的 | Next/Nuxt 倾向帮你约定的 |
|---|---|
| 手写或配置路由 | 用目录结构生成路由 |
| 主要是浏览器端渲染 | 可支持 SSR / SSG |
| 自己组织页面结构 | 框架提供更强页面约定 |
| 以 Vite 配置为工程入口 | 以 Next/Nuxt 配置为应用入口 |

什么时候需要 Next/Nuxt：

- 网站非常重视 SEO。
- 有大量内容页。
- 需要 SSR / SSG。
- 希望应用结构有更强约定。

什么时候不急着用：

- 只是练习前端基础。
- 做普通后台管理或交互型应用。
- 后端已经明确使用 Express，前端只需要调用 API。

你的长期后端方向是 `Node.js + Express`，所以后面选型时，不要因为 Next/Nuxt 也能写服务端能力就自动选择它。它们是否需要，主要看网站类型、SEO、内容结构和交互复杂度。

关键判断：

```text
Next.js 不是 React 的替代品，而是 React 的应用框架。
Nuxt.js 不是 Vue 的替代品，而是 Vue 的应用框架。
Next/Nuxt 负责更上层的应用结构和渲染模式。
```

## 学习建议

### 1. 每完成一个阶段，问自己三个问题

```text
1. 这个版本的入口文件是什么？
2. 同一个“添加列表”功能，这次是怎么实现的？
3. 和上一个版本相比，什么变了，什么没变？
```

比如从 Vanilla TS 到 Vue，你应该能说出：

- 入口从 `main.ts` 里手写 DOM，变成 `createApp(App).mount("#app")`。
- UI 从 `element.textContent = x`，变成 `v-model` 和 `{{ }}`。
- 状态从普通变量，变成 `ref()`。

能说清楚这些，比“我学过 Vue”扎实得多。

### 2. 什么时候算可以进入下一阶段

不需要做得漂亮，不需要加登录、权限、接口、数据库、部署。只要：

- 功能能跑起来。
- 能点击、能输入、能显示数据。
- 能说清楚这一层的入口在哪、状态在哪。

达到这三条就够了。进入下一阶段之后，如果遇到困惑，可以随时回来对照。

### 3. 不要把这条路线当考试

参考时间只是为了降低焦虑，不是进度要求。

如果你在 Vue 或 React 卡了两三天，很正常。真正重要的是：每次卡住时，能判断自己卡在语法、状态、组件、工具链，还是项目结构。

## 小结

这条路线的目的不是让你背语法，而是建立一种直觉：

```text
看到新技术，先判断它改变的是哪一层。
```

如果一个功能在 HTML/JS、Vanilla TS、Vue、React、路由、状态管理里都做过一遍，你再看现代前端项目，就不会只看到一堆名词，而是能看出每一层为什么存在。
