# 10. 现代前端推荐学习路线

## 问题背景

现代前端的难点不只是技术多，而是不知道学习顺序：

```text
先学 React 还是先学 JavaScript？
TypeScript 要不要一开始就学？
Vite 是不是必须先学？
Next.js / Nuxt.js 什么时候学？
```

本文属于七层体系中的第七层：学习方法层。它的任务不是再介绍一遍技术，而是帮你把学习顺序和项目目标对应起来。

## 核心解释

学习时建议从底层往上理解：

```text
HTML / CSS / JS / DOM
  ↓
TypeScript
  ↓
React 或 Vue
  ↓
Vite 和工程化
  ↓
路由 / 状态管理
  ↓
Next.js 或 Nuxt.js
  ↓
读项目和规划路线
```

但做项目时通常从目标倒推：

```text
我要做什么
  ↓
需要什么应用形态
  ↓
选框架和工具
  ↓
补对应基础
```

这两个方向不矛盾：学习要打地基，项目要看目标。

### 理解顺序和动手顺序不是一回事

对初级前端来说，最容易卡住的是：以为必须把一层完全学透，才能进入下一层。

更现实的方式是区分两条线：

| 线索 | 适合怎么走 | 目的 |
|---|---|---|
| 理解顺序 | 从底层往上看 | 建立技术地图，知道每层解决什么 |
| 动手顺序 | 用小项目循环推进 | 通过代码看到每层怎么落地 |

理解顺序可以是：

```text
HTML/CSS/JS -> TypeScript -> React/Vue -> Vite -> Router/Store -> Next/Nuxt
```

但动手顺序更适合这样：

```text
做一个静态页面
  ↓
加一点 DOM 交互
  ↓
用 Vite 跑一个 Vanilla TS 项目
  ↓
用 Vue 或 React 重写同一个功能
  ↓
加一个简单路由
  ↓
加一个小型共享状态
  ↓
再去看 Next/Nuxt 项目结构
```

这样你不会一直停在“补基础”的焦虑里，也不会太早进入“框架名词大乱炖”。

## 技术关系

### HTML / CSS / JS 应该学到什么程度

| 技术 | 建议掌握程度 |
|---|---|
| HTML | 能写常见页面结构、表单、语义化标签 |
| CSS | 能用盒模型、Flex、Grid、定位、响应式解决布局 |
| JavaScript | 能写函数、对象、数组、模块、异步、DOM 事件 |
| DOM | 知道浏览器如何把页面变成对象树，能写基本操作 |

不用等到基础“完全精通”才学框架，但不能完全跳过。

### 什么时候学 TypeScript

建议在 JavaScript 基础稳定后学习 TypeScript。

你至少应该先熟悉：

- 函数。
- 对象和数组。
- 模块导入导出。
- Promise / async await。
- 基本 DOM 或框架组件写法。

然后再学：

- 基本类型。
- 对象类型。
- 函数参数和返回值类型。
- 组件 props 类型。
- 接口数据类型。

### 什么时候学 React 或 Vue

当你能写基本 HTML/CSS/JS 页面后，就可以开始学一个 UI 框架。

学习重点不是 API 数量，而是：

- 组件怎么拆。
- 数据如何驱动界面。
- props 如何传递。
- 状态如何变化。
- 事件如何处理。
- 列表、条件渲染、表单怎么写。

### 什么时候学 Vite

当你开始写 React/Vue 或 TypeScript 项目时，就应该理解 Vite。

不必先深学配置，但要知道：

- `npm run dev` 为什么能启动项目。
- `npm run build` 做了什么。
- `vite.config.ts` 是工程配置。
- Vite 可以搭配 React、Vue，也可以搭配 Vanilla TS。

### 什么时候学 Next.js 或 Nuxt.js

建议在能写普通 React/Vue 项目后再学。

因为 Next.js 和 Nuxt.js 本质上是把 UI 框架放进更完整的应用框架里。如果你不理解 React/Vue 的组件和状态，学 Next/Nuxt 时会把上层约定和底层组件混成一团。

## 不同目标下的学习路线

### 目标一：做普通网页

适合目标：

- 个人主页。
- 简单展示页。
- 活动页。
- 小型交互页面。

路线：

```text
阶段 1：HTML 结构
阶段 2：CSS 布局和响应式
阶段 3：JavaScript DOM 交互
阶段 4：少量 TypeScript 或继续原生 JS
阶段 5：需要工程化时再引入 Vite
```

建议技术组合：

```text
HTML + CSS + JavaScript
或
Vite + Vanilla TS
```

不一定需要 React/Vue。

### 目标二：做后台管理系统

适合目标：

- 管理列表。
- 表单录入。
- 权限页面。
- 数据筛选。
- 多页面仪表盘。

路线：

```text
阶段 1：HTML/CSS/JS 基础
阶段 2：TypeScript 基础
阶段 3：React 或 Vue 组件化
阶段 4：Vite 项目结构
阶段 5：前端路由
阶段 6：状态管理
阶段 7：表单、表格、弹窗等常见业务组件思维
```

建议技术组合：

```text
Vite + Vue + Vue Router + Pinia
或
Vite + React + React Router + Zustand/Redux
```

重点是组件拆分、路由组织、状态管理和业务页面复用。

### 目标三：做官网 / 作品集

适合目标：

- 品牌官网。
- 产品介绍页。
- 作品集。
- 内容展示型站点。

路线：

```text
阶段 1：HTML/CSS 和视觉布局
阶段 2：JavaScript 基本交互
阶段 3：React 或 Vue 组件化
阶段 4：理解 CSR / SSR / SSG 的区别
阶段 5：学习 Next.js 或 Nuxt.js 的页面和路由组织
```

建议技术组合：

```text
Next.js + React
或
Nuxt.js + Vue
```

如果只是很简单的静态页面，也可以不用应用框架。

### 目标四：做复杂 Web App

适合目标：

- 在线设计工具。
- 协作工具。
- 复杂仪表盘。
- 多状态、多交互应用。

路线：

```text
阶段 1：扎实 JavaScript 和 TypeScript
阶段 2：深入 React 或 Vue 组件模型
阶段 3：路由、状态管理、组件通信
阶段 4：复杂表单、列表、缓存、错误状态
阶段 5：项目结构和模块边界
阶段 6：根据需求考虑 Next/Nuxt 或普通 Vite 项目
```

建议技术组合：

```text
Vite + React/Vue + Router + Store
或
Next.js / Nuxt.js
```

这类项目最重要的不是选哪个名词，而是能不能把状态、组件和页面组织清楚。

### 目标五：做现代全栈应用的前端部分

本文不讲后端、数据库、部署，但如果你的目标是参与现代全栈应用的前端部分，可以这样学：

```text
阶段 1：HTML/CSS/JS/DOM
阶段 2：TypeScript
阶段 3：React 或 Vue
阶段 4：路由和状态管理
阶段 5：Next.js 或 Nuxt.js
阶段 6：理解 CSR / SSR / SSG 对前端结构的影响
阶段 7：学会读项目目录和 package.json
```

建议先聚焦前端边界：页面、组件、状态、路由、渲染模式。暂时不要把数据库、部署、云服务一起塞进学习计划。

## 学习建议

### 不要只按热门程度学习

热门技术不一定是你当前阶段最该学的技术。

比如你连 DOM 事件都不熟，就直接学 Next.js，很容易卡在“看起来是 Next 的问题，其实是 JS 和 React 的问题”。

### 每一层都问三个问题

学任何技术时都问：

```text
它解决什么问题？
它依赖哪一层？
它和下一层怎么配合？
```

例如 Vite：

```text
解决：开发服务器和打包问题
依赖：JS 模块、Node 工具链、项目文件
配合：React/Vue/Vanilla TS 等项目
```

### 学习和项目可以交替

推荐节奏：

```text
学一点基础 -> 做一个小页面
学一点框架 -> 做一个小组件应用
学一点 Vite -> 看懂项目启动和打包
学一点路由状态 -> 做一个多页面小应用
学一点 Next/Nuxt -> 看懂应用框架结构
```

如果你不知道做什么，可以沿着 `00-阅读导引和最小实战主线.md` 走：用同一个计数器和列表功能，分别用原生 JS、Vanilla TS、Vue、React、路由和状态管理实现一遍。

## 小结

学习现代前端，最重要的是顺序感。

```text
学习时：从底层往上理解
做项目时：从目标往下组合
读项目时：从 package.json 和入口文件反推技术栈
```

当你能在这三个方向之间切换，前端技术就会从一堆名词变成一套可使用的地图。
