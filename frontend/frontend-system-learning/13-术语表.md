# 13. 术语表

## 问题背景

前端术语很多，最麻烦的是它们经常混在一个项目里出现。这个术语表不追求学院式定义，而是用更通俗的话说明：它是什么、处在哪一层、初学者该怎么理解。

本文属于七层体系中的第七层：学习方法层，因为它帮助你快速查词，并把词放回技术地图。

## 核心解释

| 术语 | 通俗解释 |
|---|---|
| HTML | 页面结构语言。告诉浏览器页面里有什么，比如标题、段落、按钮、表单。 |
| CSS | 样式语言。控制页面长什么样，比如颜色、布局、间距、字体、响应式。 |
| JavaScript | 浏览器里的主要编程语言。负责交互、逻辑、数据处理和调用浏览器能力。 |
| TypeScript | JavaScript 的类型增强版本。让你在开发阶段提前发现很多类型错误。 |
| DOM | 浏览器把 HTML 解析后得到的页面对象树。JS 可以通过 DOM API 读取和修改页面。 |
| BOM | Browser Object Model，浏览器对象模型。包括 `window`、`location`、`history` 等浏览器相关能力。 |
| React | 用组件构建界面的 UI 框架，常用 JSX/TSX 写法。 |
| Vue | 用组件构建界面的 UI 框架，常用 `.vue` 单文件组件写法。 |
| Vite | 前端工程化工具，负责开发服务器、热更新、构建打包等。 |
| Next.js | 基于 React 的应用框架，提供路由、渲染模式和应用结构等能力。 |
| Nuxt.js | 基于 Vue 的应用框架，提供路由、渲染模式和应用结构等能力。 |
| 组件 | 可复用的 UI 单元。一个按钮、一个卡片、一个页面区域都可以是组件。 |
| 状态 | 会影响界面的数据，比如登录状态、输入框内容、列表筛选条件。 |
| props | 父组件传给子组件的数据。适合父子组件之间传参。 |
| store | 集中管理共享状态的地方。适合多个页面或远距离组件共同使用的数据。 |
| 路由 | URL 和页面之间的对应关系。前端路由负责不刷新页面时切换页面组件。 |
| SPA | 单页应用。通常只加载一个入口 HTML，之后由 JS 控制页面切换和交互。 |
| CSR | 客户端渲染。页面内容主要在浏览器里由 JavaScript 生成。 |
| SSR | 服务端渲染。请求时先在服务器生成 HTML，再发给浏览器。 |
| SSG | 静态生成。构建阶段提前生成 HTML，访问时直接返回静态文件。 |
| 构建工具 | 把开发代码转换成浏览器可用代码的工具，也常负责开发服务器。Vite 是代表。 |
| 开发服务器 | 本地开发时启动的服务，比如 `http://localhost:5173`，方便预览和热更新。 |
| 打包 | 把 `src/` 里的开发源码转换成生产环境可用的文件，通常输出到 `dist/`。 |
| 依赖 | 项目需要安装的第三方包，比如 `react`、`vue`、`vite`。 |
| 入口文件 | 应用开始运行的文件。常见如 `main.ts`、`main.tsx`。 |
| package.json | 前端项目的说明书，记录 scripts、dependencies、devDependencies 等信息。 |
| tsconfig.json | TypeScript 配置文件，控制类型检查和编译相关规则。 |
| vite.config.ts | Vite 配置文件，常用来看项目是否配置了 React/Vue 插件。 |
| 框架 | 提供一套组织代码和构建功能的方式。React/Vue 是 UI 框架，Next/Nuxt 是应用框架。 |
| 库 | 提供某种能力的代码集合，通常由你主动调用。和框架的边界有时不是绝对的。 |
| 工具链 | 一组配合工作的开发工具，比如包管理、构建、类型检查、格式化。 |
| 工程化 | 让项目更适合多人协作、开发、构建和维护的一系列做法和工具。 |
| Vanilla JS | 不使用 React/Vue 等框架，直接用原生 JavaScript 写前端。 |
| Vanilla TS | 不使用 React/Vue 等框架，直接用 TypeScript 和原生 DOM API 写前端。 |
| Node.js | 让 JavaScript 能在浏览器之外运行的环境。现代前端里常用它运行 Vite、TypeScript、脚手架等开发工具。 |
| npm | Node.js 自带的包管理工具，常用来安装依赖和执行 `package.json` 里的 scripts。 |
| pnpm | 另一种包管理工具，和 npm 类似，但依赖存储方式更节省空间，很多现代项目会使用。 |
| yarn | 另一种包管理工具，作用和 npm / pnpm 类似。 |
| node_modules | 依赖安装后的目录，通常很大，不手动修改，也一般不提交到 Git。 |
| lock 文件 | 记录精确依赖版本的文件，如 `package-lock.json`、`pnpm-lock.yaml`、`yarn.lock`。 |

## 技术关系

按七层放回去：

| 层级 | 相关术语 |
|---|---|
| 第一层：基础层 | HTML、CSS、JavaScript、DOM、BOM、Vanilla JS |
| 第二层：语言增强层 | TypeScript、tsconfig.json、Vanilla TS |
| 第三层：UI 框架层 | React、Vue、组件、props、状态 |
| 第四层：工程化层 | Vite、构建工具、开发服务器、打包、vite.config.ts、工具链、工程化 |
| 第五层：应用组织层 | 路由、SPA、store、状态管理 |
| 第六层：应用框架层 | Next.js、Nuxt.js、CSR、SSR、SSG |
| 第七层：学习方法层 | package.json、入口文件、依赖判断、项目阅读方法 |

补充说明：

```text
Node.js / npm / pnpm / yarn
  不属于 UI 框架层
  更像工程化层背后的工具运行环境和依赖管理方式
```

## 学习建议

查术语时不要只背一句定义。建议同时问：

```text
它属于哪一层？
它解决什么问题？
我能在项目哪个文件里看到它？
它常和哪些技术一起出现？
```

例如 `Vite`：

```text
层级：第四层工程化层
解决：开发服务器和打包
项目线索：package.json、vite.config.ts
常见搭配：React、Vue、Vanilla TS
```

## 小结

术语表的作用不是让你背名词，而是帮你把名词放回地图。

只要能判断“它是哪一层、解决什么问题、项目里怎么看出来”，你就已经比单纯背定义更接近真实开发了。
