# 11. 如何阅读一个前端项目并判断技术栈

## 问题背景

拿到一个前端项目，先不要急着看组件代码。

更重要的是先判断：

```text
谁启动项目？
谁写 UI？
谁负责构建？
有没有应用框架？
```

本文属于第七层：学习方法层。

主线先记这一条：

```text
先看启动命令
-> 再看依赖
-> 再看入口文件
-> 最后用源码写法交叉验证
```

---

## 核心解释

### 1. 判断顺序：先入口，再技术栈

按这个顺序看，最稳：

```text
package.json
scripts
dependencies / devDependencies
入口文件 main.ts / main.tsx
根组件 App.vue / App.tsx
配置文件 vite.config.ts / next.config.ts / nuxt.config.ts
目录约定 app/ / pages/
```

一句话：

```text
先看项目由谁启动，再看 UI 由谁编写。
```

---

### 2. scripts 先定入口：谁启动项目

| `scripts.dev` | 优先判断 |
|---|---|
| `vite` | Vite 项目 |
| `next dev` | Next.js 项目 |
| `nuxt dev` / `nuxi dev` | Nuxt.js 项目 |
| 其他命令 | 先查这个命令是谁 |

如果是：

```json
{
  "scripts": {
    "dev": "next dev"
  }
}
```

优先判断为 Next.js，而不是普通 React 项目。

---

### 3. dependencies 看 UI 和应用框架：依赖只是线索

先分清两个字段：

| 字段 | 通俗理解 | 常见内容 |
|---|---|---|
| `dependencies` | 应用运行时也需要的包 | `react`、`vue`、`next`、`nuxt` |
| `devDependencies` | 开发和构建时需要的包 | `vite`、`typescript`、框架插件 |

实际项目不一定百分百严格，但足够帮助你判断技术栈。

| 依赖线索 | 可能说明 |
|---|---|
| `react` + `react-dom` | React |
| `vue` | Vue |
| `next` | Next.js |
| `nuxt` | Nuxt.js |
| `react-router-dom` | React Router |
| `vue-router` | Vue Router |
| `pinia` / `zustand` / `redux` | 状态管理 |

注意：依赖只是线索，要和 scripts、入口文件一起看。

---

## 技术关系

### 1. React 项目线索

```text
react
react-dom
main.tsx
App.tsx
@vitejs/plugin-react
ReactDOM.createRoot
```

典型入口：

```tsx
import ReactDOM from "react-dom/client";
import App from "./App";

ReactDOM.createRoot(document.getElementById("root")!).render(<App />);
```

---

### 2. Vue 项目线索

```text
vue
App.vue
main.ts
@vitejs/plugin-vue
createApp
```

典型入口：

```ts
import { createApp } from "vue";
import App from "./App.vue";

createApp(App).mount("#app");
```

---

### 3. Next.js 项目线索

```text
next
next dev
app/ 或 pages/
next.config.ts
page.tsx
layout.tsx
```

看到 `next dev`，优先判断为 Next.js。

---

### 4. Nuxt.js 项目线索

```text
nuxt
nuxi
nuxt.config.ts
pages/
app.vue
```

看到 `nuxt dev` 或 `nuxi dev`，优先判断为 Nuxt.js。

---

### 5. Vanilla TS 项目线索

```text
没有 react / vue / next / nuxt
main.ts
document.querySelector
addEventListener
原生 DOM API
可能有 Vite
```

你的 `minimal-frontend-demo/01-html-css-js` 还不是 Vite + Vanilla TS，因为它没有 npm/Vite，只是原生 HTML + JS。

后面的 `02-vite-vanilla-ts` 才会进入：

```text
Vite + TypeScript + 原生 DOM
```

---

### 6. vite.config.ts 怎么看

有 `vite.config.ts`，只能说明有 Vite 配置。

继续看插件：

| 插件 | 判断 |
|---|---|
| `@vitejs/plugin-react` | Vite + React |
| `@vitejs/plugin-vue` | Vite + Vue |
| 没有框架插件 | 可能是 Vanilla TS |

所以：

```text
vite.config.ts 不等于 React/Vue。
```

---

## 示例判断

### 示例一：Vite + Vue

```json
{
  "scripts": {
    "dev": "vite"
  },
  "dependencies": {
    "vue": "^3.0.0"
  },
  "devDependencies": {
    "@vitejs/plugin-vue": "^5.0.0",
    "vite": "^5.0.0"
  }
}
```

判断：

```text
scripts.dev 是 vite -> Vite 项目
dependencies 有 vue -> Vue
插件是 @vitejs/plugin-vue -> Vite + Vue
```

---

### 示例二：Next.js

```json
{
  "scripts": {
    "dev": "next dev"
  },
  "dependencies": {
    "next": "^14.0.0",
    "react": "^18.0.0",
    "react-dom": "^18.0.0"
  }
}
```

判断：

```text
scripts.dev 是 next dev -> Next.js 项目
它基于 React，但不是普通 Vite React 项目
```

---

### 示例三：Vite + Vanilla TS

```text
src/
  main.ts
index.html
vite.config.ts
```

```ts
document.querySelector("#app")?.addEventListener("click", () => {
  console.log("click");
});
```

判断：

```text
有 Vite 和 TS
没有 React/Vue
代码是原生 DOM
= Vite + Vanilla TS
```

## 学习建议

读项目时做一张小表：

| 问题 | 你的判断 |
|---|---|
| 启动命令是什么？ | 例如 `vite` |
| UI 框架是什么？ | React / Vue / 无 |
| 工程化工具是什么？ | Vite / Next / Nuxt |
| 有没有应用框架？ | Next / Nuxt / 无 |
| 有没有路由和状态管理？ | Router / Store |
| 对应七层哪些层？ | 第一层到第六层 |

不要只凭一个文件下结论。

---

## 小结

判断技术栈靠多线索交叉验证。

```text
package.json 看入口和依赖
入口文件看挂载方式
配置文件看工程工具
目录结构看应用框架
源码写法看 React/Vue/原生 DOM
```

先判断“谁启动项目”，再判断“谁写 UI”。
