# 12. 现代前端推荐学习路线

## 问题背景

现代前端难的不是技术少，而是顺序乱。

常见纠结：

```text
先学 JS 还是 React？
TypeScript 要不要一开始学？
Vite 什么时候学？
Next / Nuxt 要不要现在学？
```

本文属于第七层：学习方法层。

主线先记这一条：

```text
学习时从底层往上
-> 动手时用小 demo 循环推进
-> 做项目时再按目标选型
```

---

## 核心解释

### 1. 学习顺序和项目选型不是一回事：学基础，项目看目标

学习时建议从底层往上：

```text
HTML / CSS / JS / DOM
TypeScript
React / Vue 思想和最小语法
Vite
Router / Store 概念和最小语法
Next 或 Nuxt
```

做项目时通常从目标倒推：

```text
我要做什么
需要什么应用形态
选择对应技术组合
再补缺的基础
```

一句话：

```text
学习时打地基，做项目时看目标。
```

---

### 2. 理解顺序和动手顺序也不是一回事：不用等完美再进入下一层

不用把每一层学到完美才进入下一层。

更适合初学者的是循环推进：

```text
做原生 demo
看基础层和 TypeScript
补 Vue / React 最小语法
看 Vite 工程化
依次做 Vite + TS、Vue、React demo
看 Router / Store 概念和最小语法
再加 Router / Store
最后再看 Next / Nuxt
```

你的 `minimal-frontend-demo` 就是干这个用的。

---

## 技术关系

### 1. 每层学到什么程度

| 层 | 先学到什么程度 |
|---|---|
| HTML | 常见结构、表单、语义化 |
| CSS | 盒模型、Flex、Grid、响应式 |
| JavaScript | 函数、数组、对象、DOM、事件、异步 |
| TypeScript | 基本类型、对象类型、函数类型、props 类型 |
| React/Vue | 组件、状态、事件、列表、表单、props |
| Vite | `npm run dev`、`build`、配置文件、插件线索 |
| Router/Store | 页面切换、局部状态、共享状态 |
| Next/Nuxt | 文件路由、CSR/SSR/SSG、应用结构 |

---

### 2. 不同目标怎么走

| 目标 | 推荐路线 | Router / Store 判断 |
|---|---|---|
| 普通单页网页 | HTML -> CSS -> JS DOM -> 必要时 Vite | 通常不需要 Router / Store |
| 多页官网 / 作品集 | HTML/CSS -> React/Vue + Router，或 Next/Nuxt | 多页面需要路由；通常不需要复杂 Store |
| 后台管理系统 | TS -> React/Vue -> Vite -> Router -> Store | Router 基本需要；Store 看登录信息、权限、筛选条件等共享状态 |
| 复杂 Web App | TS -> React/Vue -> Router/Store -> 项目结构 | Router / Store 通常都重要 |
| 现代全栈前端 | TS -> React/Vue -> 调 Express API -> 再选 Next/Nuxt | 先把前后端数据打通，再决定是否需要应用框架 |

这张表不是固定答案，重点看两个问题：

```text
页面是不是不止一个？
多个页面或组件之间有没有共享数据？
```

如果只是一个展示页，先别急着上 Router / Store。

如果是官网、作品集这种多页面展示，通常需要路由，但不一定需要复杂状态管理。

如果是后台或复杂 Web App，页面切换、登录信息、权限、筛选条件、用户配置这些数据一多，Router / Store 就会变重要。

---

### 3. 什么时候学 TypeScript

在 JavaScript 基本稳定后学。

你不需要等很久，但至少要先懂：

```text
函数
对象
数组
模块
Promise / async await
基本 DOM 或组件写法
```

结合你的 Swift 背景，做正式项目时 TypeScript 可以作为默认选择。

---

### 4. 什么时候学 Next / Nuxt

先能写普通 React/Vue 项目，再学 Next/Nuxt 更稳。

因为 Next/Nuxt 里仍然要写：

```text
组件
props
state/ref
事件
列表
表单
```

如果 UI 框架没理解，学应用框架会混。

---

## 学习建议

现在这阶段，不要急着做最终网站选型。

更好的节奏是：

```text
读 01 / 02
做 01-html-css-js
读 03 / 04 / 05 / 06 / 07
做 02-vite-vanilla-ts
再做 03-vue 和 04-react
读 08 / 09
做 05-router 和 06-store
做完 store 后回看 09A
最后再读 10 / 11 / 12
```

每学一个技术都问：

```text
它解决什么问题？
它属于哪一层？
它替我省掉了原生写法里的什么麻烦？
```

---

## 小结

现代前端学习最重要的是顺序感。

```text
学习时：从底层往上理解
做项目时：从目标往下组合
读项目时：从 scripts 和入口文件反推
```

能在这三个方向之间切换，前端就不再是一堆名词。
