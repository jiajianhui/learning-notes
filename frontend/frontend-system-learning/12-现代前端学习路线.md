# 12. 现代前端推荐学习路线

## 问题背景

现代前端难的不是技术少，而是顺序乱。

常见纠结：

```text
先学 JS 还是 React？
TypeScript 要不要一开始学？
Vite 什么时候学？
Next / Nuxt 要不要现在学？
```

本文属于第七层：学习方法层。

主线先记这一条：

```text
学习时从底层往上
-> 动手时用小 demo 循环推进
-> 做项目时再按目标选型
```

---

## 核心解释

### 1. 学习顺序和项目选型不是一回事：学基础，项目看目标

学习时建议从底层往上：

```text
HTML / CSS / JS / DOM
TypeScript
React / Vue 思想和最小语法
Vite
Router / Store 概念和最小语法
Next 或 Nuxt
```

做项目时通常从目标倒推：

```text
我要做什么
需要什么应用形态
选择对应技术组合
再补缺的基础
```

一句话：

```text
学习时打地基，做项目时看目标。
```

---

### 2. 理解顺序和动手顺序也不是一回事：不用等完美再进入下一层

不用把每一层学到完美才进入下一层。

更适合初学者的是循环推进：

```text
做原生 demo
看基础层和 TypeScript
补 Vue / React 最小语法
看 Vite 工程化
依次做 Vite + TS、Vue、React demo
看 Router / Store 概念和最小语法
再加 Router / Store
最后再看 Next / Nuxt
```

你的 `minimal-frontend-demo` 就是干这个用的。

---

## 技术关系

### 1. 每层学到什么程度

| 层 | 先学到什么程度 |
|---|---|
| HTML | 常见结构、表单、语义化 |
| CSS | 盒模型、Flex、Grid、响应式 |
| JavaScript | 函数、数组、对象、DOM、事件、异步 |
| TypeScript | 基本类型、对象类型、函数类型、props 类型 |
| React/Vue | 组件、状态、事件、列表、表单、props |
| Vite | `npm run dev`、`build`、配置文件、插件线索 |
| Router/Store | 页面切换、局部状态、共享状态 |
| Next/Nuxt | 文件路由、CSR/SSR/SSG、应用结构 |

---

### 2. 不同目标不是固定路线：先固定自己的主线，再判断缺什么

不要把“普通网页、后台、官网”理解成三条必须切换工具的路线。

如果你已经习惯 Next.js，当然可以继续用 Next.js 做普通展示页、官网、作品集、后台入口页。工具选择本来就包含个人工作流、团队约定、部署环境和长期维护习惯。

这里要训练的不是“做普通网页就必须退回 HTML -> CSS -> JavaScript DOM”，而是判断一个项目到底用了哪些层，以及当前目标真正需要哪些能力。

更实用的判断方式是：

| 项目目标 | 可以继续用的主线 | 重点补的能力 | Router / Store 判断 |
|---|---|---|---|
| 普通展示页 | Next.js / React / Vue / Vanilla 都可以 | HTML 语义、CSS 布局、少量交互 | 通常不需要复杂 Store；路由看页面数量 |
| 多页官网 / 作品集 | Next.js 很合适，也可以用 React/Vue + Router | 页面结构、内容组织、响应式、SEO/元信息 | 多页面通常需要路由；Store 通常很轻 |
| 后台管理系统 | React/Vue/Next 都可以作为工作流 | 表单、列表、权限、接口调用、组件复用 | Router 基本需要；Store 看登录信息、权限、筛选条件等共享状态 |
| 复杂 Web App | React/Vue/Next 按团队习惯选 | 状态边界、数据流、模块拆分、性能 | Router / Store 通常都重要 |
| 现代全栈前端 | Next.js 或“前端框架 + Express API”都可以 | 前后端数据打通、接口设计、部署边界 | 先看服务端能力放在哪里，再决定状态组织方式 |

这张表不是选型命令，而是排查清单。重点看三个问题：

```text
我是否已经有稳定顺手的项目主线？
页面是不是不止一个？
多个页面或组件之间有没有共享数据？
```

所以更合理的学习顺序是：基础概念要懂，项目实践不必死板切换工具。

比如你用 Next.js 做一个普通网页，也仍然可以在里面练：

```text
HTML 语义
CSS 布局
JavaScript 交互
React 组件
Next.js 文件路由和构建部署
```

区别只是：这些基础能力被放在 Next.js 这个工作流里练，而不是非要单独新建一个原生项目。

---

### 3. 什么时候学 TypeScript

在 JavaScript 基本稳定后学。

你不需要等很久，但至少要先懂：

```text
函数
对象
数组
模块
Promise / async await
基本 DOM 或组件写法
```

结合你的 Swift 背景，做正式项目时 TypeScript 可以作为默认选择。

---

### 4. 什么时候学 Next / Nuxt

先能写普通 React/Vue 项目，再学 Next/Nuxt 更稳。

因为 Next/Nuxt 里仍然要写：

```text
组件
props
state/ref
事件
列表
表单
```

如果 UI 框架没理解，学应用框架会混。

---

## 学习建议

现在这阶段，不要急着做最终网站选型。

更好的节奏是：

```text
读 01 / 02
做 01-html-css-js
读 03 / 04 / 05 / 06 / 07
做 02-vite-vanilla-ts
再做 03-vue 和 04-react
读 08 / 09
做 05-router 和 06-store
做完 store 后回看 09A
最后再读 10 / 11 / 12
```

每学一个技术都问：

```text
它解决什么问题？
它属于哪一层？
它替我省掉了原生写法里的什么麻烦？
```

---

## 小结

现代前端学习最重要的是顺序感。

```text
学习时：从底层往上理解
做项目时：从目标往下组合
读项目时：从 scripts 和入口文件反推
```

能在这三个方向之间切换，前端就不再是一堆名词。
