# 01. 前端大图景：从页面到应用

## 问题背景

你刚做完 `frontend/minimal-frontend-demo/01-html-css-js/`，应该已经感受到一件事：

```text
数据变了，页面不会自动变。
你必须找到 DOM，再手动修改页面。
```

比如：

```js
let total = 0;
const spanEl = document.querySelector("#span");
const btnEl = document.querySelector("#btn");

btnEl.addEventListener("click", () => {
  total += 1;
  spanEl.textContent = String(total);
});
```

这就是现代前端的起点。

React、Vue、Vite、路由、状态管理、Next.js、Nuxt.js 不是突然冒出来的名词。它们更像一串“问题的答案”。

本文是七层体系的总览入口。它不单独属于某一层，而是把这些层先串起来：

```text
基础层       HTML / CSS / JavaScript / DOM
语言增强层   TypeScript
UI 框架层    React / Vue
工程化层     Vite / 构建工具
应用组织层   路由 / 状态管理
应用框架层   Next.js / Nuxt.js
学习方法层   如何看项目、判断技术栈、规划路线
```

---

## 核心解释

### 1. 浏览器的老三件套

浏览器原生理解三类东西：

| 技术 | 负责什么 | 直觉理解 |
|---|---|---|
| HTML | 页面结构 | 有什么 |
| CSS | 视觉样式 | 长什么样 |
| JavaScript | 交互逻辑 | 会发生什么 |

它们通过 DOM 连起来：

```html
<button id="save">保存</button>
<p id="status">未保存</p>
```

```js
document.querySelector("#save").addEventListener("click", () => {
  document.querySelector("#status").textContent = "已保存";
});
```

这个模型从 1990 年代就存在，到今天仍然是前端地基。框架可以换，工具可以换，但最后都要变成浏览器能运行的 HTML、CSS 和 JavaScript。

---

### 2. 问题是怎么滚起来的

前端一开始像“写页面”，后来越来越像“写应用”。

| 出现的问题 | 典型感受 | 长出来的技术 |
|---|---|---|
| 页面需要交互 | 点按钮、改文字、表单校验 | JavaScript / DOM |
| 手动 DOM 越来越乱 | 数据和页面要手动同步 | React / Vue |
| JS 太自由 | 函数参数、接口字段容易搞错 | TypeScript |
| 浏览器不认识现代写法 | TS、JSX、`.vue` 不能直接跑 | Vite / 构建工具 |
| 页面不想整页刷新 | 切换页面像 App 内部跳转 | SPA / 前端路由 |
| 多处要共享数据 | 远距离组件都要用同一份数据 | 状态管理 |
| 项目结构也想约定 | 路由、SSR、SSG、目录结构 | Next.js / Nuxt.js |

所以现代前端不是为了复杂而复杂，而是浏览器里承载的事情变多了。

---

### 3. 从原生 demo 看 React / Vue 为什么出现

在原生写法里：

```js
todos.push(content);
renderList();
```

数组变了，页面不知道。你要手动 `renderList()`。

React / Vue 改变的是这件事：

```text
原生 JS：数据变了，你手动改 DOM。
React/Vue：你描述数据和 UI 的关系，框架帮你更新页面。
```

这就是“数据驱动视图”。

React 和 Vue 写法不一样，但核心目标相同：

| 框架 | 更像什么 |
|---|---|
| React | 用 JavaScript 表达 UI |
| Vue | 写增强版 HTML 模板 |

---

### 4. Vite 不是 React，也不是 Vue

这一点很重要。

```text
npm run dev 背后通常是 Vite 在工作，不是 React 或 Vue。
```

分工是这样的：

| 谁 | 负责什么 |
|---|---|
| npm | 读取 `package.json` 里的 scripts |
| Vite | 启动开发服务器、转换代码、热更新、打包 |
| React / Vue | 组件、状态变化后的 UI 更新 |
| TypeScript | 类型检查和类型提示 |

所以：

```text
Vite + Vanilla TS 可以
Vite + React 可以
Vite + Vue 也可以
```

看到 `vite.config.ts`，只能说明项目用了 Vite 或相关配置，不能直接判断它一定是 React 或 Vue。

---

### 5. Router 和 Store 也不是一件事

前端路由解决页面位置：

```text
/counter -> CounterPage
/todos   -> TodoPage
```

状态管理解决共享数据：

```text
计数器页改 count
列表页显示 count
导航栏也显示 count
```

一句话：

```text
Router 管页面位置。
Store 管共享数据。
```

这也是初学者很容易混在一起的地方。

---

### 6. Next / Nuxt 是更上层的应用框架

React / Vue 主要解决 UI。

Next.js / Nuxt.js 解决更大的项目组织问题：

```text
页面放哪里？
路由怎么约定？
SEO 怎么办？
哪些页面 SSR？
哪些页面 SSG？
```

关系可以这样记：

```text
Next.js = React + 应用框架能力
Nuxt.js = Vue + 应用框架能力
```

它们不是“更厉害的 React/Vue”，而是更上层的应用框架。

你的后端方向已经确定是 Node.js + Express，所以以后是否用 Next/Nuxt，要看网站类型、SEO、内容结构和交互复杂度，不要默认上。

## 技术关系

### 从页面到应用

| 阶段 | 更像什么 | 典型特征 |
|---|---|---|
| 静态网页 | 文档 | HTML 展示内容 |
| 交互网页 | 页面 + 脚本 | JS 操作 DOM |
| 单页应用 | 浏览器里的应用 | 组件、路由、状态 |
| 应用框架项目 | 完整工程 | 约定式路由、SSR、SSG、构建流程 |

---

### 七层地图

```text
第六层：应用框架层    Next.js / Nuxt.js
第五层：应用组织层    路由 / 状态管理 / 组件通信
第四层：工程化层      Vite / 构建工具 / 开发服务器 / 打包
第三层：UI 框架层     React / Vue
第二层：语言增强层    TypeScript
第一层：基础层        HTML / CSS / JavaScript / DOM
```

第七层不是具体技术，而是学习方法：

```text
看项目结构
判断技术栈
规划学习路线
```

看到新名词，先问三句话：

```text
它在哪一层？
它解决什么问题？
当前项目真的需要它吗？
```

---

### 最容易混淆的几组

| 名词 | 属于哪层 | 主要负责 |
|---|---|---|
| TypeScript | 语言增强层 | 类型检查 |
| React / Vue | UI 框架层 | 组件和页面更新 |
| Vite | 工程化层 | 开发服务器、转换、打包 |
| Router | 应用组织层 | URL 和页面组件对应 |
| Store | 应用组织层 | 共享业务数据 |
| Next / Nuxt | 应用框架层 | 应用结构和渲染模式 |

记住一句话：

```text
它们经常一起出现，但不是同一类东西。
```

---

## 学习建议

你现在最该复盘原生 demo 的三个问题：

| 问题 | 原生 demo 里的答案 |
|---|---|
| 状态存在哪里？ | `count`、`todos` 这些普通变量 |
| 页面为什么会更新？ | 你手动修改 DOM |
| 复杂后哪里会难维护？ | 数据和 DOM 更新逻辑会散落 |

接下来建议：

```text
看 02：把 HTML / CSS / JS / DOM 讲扎实
看 03：理解 Node 和 npm 为什么进入前端
看 04：理解 TypeScript 为什么适合你
做 02-vite-vanilla-ts：感受 npm run dev 背后是谁在工作
```

不要急着跳 React、Vue、Next。每学一层，都问它：

```text
它替我解决了原生写法里的哪个麻烦？
```

---

## 小结

现代前端的主线不是“哪个框架流行”，而是：

```text
页面越来越像应用，所以工具一层层出现。
```

压缩成一条链：

```text
HTML/CSS/JS 能做页面
DOM 让 JS 能改页面
手动 DOM 复杂后，需要 React/Vue
JS 项目变大后，需要 TypeScript
现代代码需要 Vite 处理
页面切换需要 Router
共享数据需要 Store
完整网站可能需要 Next/Nuxt
```

记住这条链，比背技术名更有用。
