# 01. 前端大图景：从页面到应用

## 问题背景

很多人刚学前端时，会觉得前端就是“写网页”：用 HTML 放内容，用 CSS 调样式，用 JavaScript 加一点交互。

这个理解没有错，但只解释了前端的早期形态。现代前端经常要做的是“应用”：有路由、有状态、有复杂交互、有构建流程、有框架、有开发服务器，还可能有不同渲染模式。

本文属于七层体系的总览入口，会同时提到多个层级：

```text
第一层：HTML / CSS / JavaScript / DOM
第二层：TypeScript
第三层：React / Vue
第四层：Vite / 构建工具
第五层：路由 / 状态管理
第六层：Next.js / Nuxt.js
第七层：学习方法
```

它的作用是先搭一个大框架，让后面的每一层不再像孤立名词。

## 核心解释

### 前端最开始是什么

最早的前端更接近“页面展示”：

```text
HTML：放文字、图片、链接、表单
CSS：控制颜色、间距、布局
JavaScript：处理点击、弹窗、表单校验
```

浏览器打开一个 HTML 文件，就能解析页面结构、加载样式、执行脚本。这个阶段的页面通常比较简单，页面之间通过刷新跳转。

### 为什么前端后来变成了应用

后来，浏览器里的需求越来越复杂：

- 不刷新页面也要切换内容。
- 表单、列表、筛选、弹窗、拖拽、图表越来越多。
- 页面里有很多区域需要根据数据变化自动更新。
- 一个项目里有几十个甚至几百个页面和组件。
- 多人协作时需要统一结构、规范和构建流程。

这时前端就不再只是“摆页面”，而是在浏览器里运行一个应用。

你可以这样理解：

| 阶段 | 更像什么 | 典型特征 |
|---|---|---|
| 传统网页 | 文档页面 | HTML 页面为中心，点击链接刷新 |
| 交互网页 | 页面 + 脚本 | JS 负责局部交互 |
| 现代前端应用 | 浏览器里的应用程序 | 组件、路由、状态、构建工具、框架 |

### 为什么现代前端会变复杂

复杂不是凭空来的，通常来自这些问题：

| 问题 | 需要什么能力 |
|---|---|
| 页面结构复杂 | 组件化 |
| 数据变化频繁 | 数据驱动视图 |
| 页面之间不想整页刷新 | 前端路由 / SPA |
| 多组件共享数据 | 状态管理 |
| JS 文件越来越多 | 模块化 / 构建工具 |
| 想写更稳定的 JS | TypeScript |
| 想要更好的首屏、SEO、路由约定 | Next.js / Nuxt.js |

所以现代前端不是为了复杂而复杂，而是因为浏览器里承载的事情变多了。

## 技术关系

### HTML、CSS、JavaScript 的分工

```text
HTML 负责内容结构
CSS 负责视觉表现
JavaScript 负责交互逻辑
DOM 是 JavaScript 操作页面的接口
```

比如一个按钮：

```html
<button id="save">保存</button>
```

```css
button {
  color: white;
  background: #2563eb;
}
```

```js
document.querySelector("#save").addEventListener("click", () => {
  console.log("保存");
});
```

这就是前端最基础的模型：页面结构、样式、逻辑，通过浏览器连接在一起。

### 框架解决什么问题

当页面变复杂时，直接手写 DOM 操作会变得难维护。React 和 Vue 这类 UI 框架主要解决：

- 如何把页面拆成组件。
- 如何根据数据变化更新界面。
- 如何组织复杂 UI 的状态和事件。
- 如何减少手动操作 DOM 的混乱。

框架不是替代 HTML/CSS/JS，而是在它们之上提供更高层的组织方式。

### 构建工具解决什么问题

现代项目里常见这些文件：

```text
src/
  main.tsx
  App.tsx
package.json
vite.config.ts
tsconfig.json
```

浏览器不能天然理解所有开发时写法，比如 TypeScript、JSX、`.vue` 单文件组件、模块路径处理等。构建工具负责把开发代码转换成浏览器最终能运行的代码。

Vite 常见职责：

- 启动本地开发服务器。
- 提供热更新。
- 处理 TypeScript、CSS、图片等资源。
- 打包生产环境代码。

### 应用框架解决什么问题

Next.js 和 Nuxt.js 位于更上层：

```text
Next.js = React + 应用级能力
Nuxt.js = Vue + 应用级能力
```

它们通常额外提供：

- 文件约定式路由。
- SSR / SSG 等渲染模式。
- 更完整的项目结构。
- 页面级组织方式。

它们不是简单的 UI 框架，而是“应用框架”。

## 学习建议

学习时不要一上来就问“我应该学 React 还是 Vue”。更好的顺序是：

1. 先理解浏览器如何运行 HTML / CSS / JS。
2. 再理解 TypeScript 为什么是 JS 的增强。
3. 再学一个 UI 框架，重点学组件化和数据驱动。
4. 再理解 Vite 这种工具为什么能启动和打包项目。
5. 再学路由、状态管理这些应用组织能力。
6. 最后再看 Next.js / Nuxt.js 如何把这些能力整合成应用框架。

做项目时可以反过来：先看目标是什么，再选择组合。

| 项目目标 | 常见组合 |
|---|---|
| 小交互页面 | HTML + CSS + JS |
| 普通组件化应用 | Vite + React/Vue |
| 后台管理系统 | Vite + React/Vue + Router + Store |
| 官网、内容型站点 | Next.js / Nuxt.js |
| 复杂 Web App | React/Vue + 路由 + 状态管理 + 工程化 |

## 小结

现代前端的核心变化，是从“写页面”变成“构建浏览器里的应用”。技术变多，是因为要解决的问题变多了。

先记住这条主线：

```text
基础能力 -> 语言增强 -> UI 框架 -> 工程化 -> 应用组织 -> 应用框架 -> 学习方法
```

后面每一篇文档都会沿着这条线继续展开。
