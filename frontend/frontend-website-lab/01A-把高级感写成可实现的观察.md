# 01A. 把高级感写成可实现的观察

## 问题背景

临摹优秀网站时，最容易写出这种句子：

```text
这个网站很高级。
这个页面很干净。
这个设计很有质感。
```

这些感受没有错。

但它们还不能指导你写代码。

这套练习真正要训练的是：

```text
把模糊感受
-> 拆成具体设计变量
-> 再翻译成 Tailwind 和组件写法
```

所以先记住这一句：

```text
不写：这个网站很高级。
要写：它几乎没有阴影，主要靠边框、留白和字号层级建立秩序。
```

这句话重要，是因为后一句已经能指导实现。

它告诉你：

- 少用或不用阴影
- 用细边框分隔内容
- 用留白拉开层次
- 用字号和字重建立主次

这就从“感觉”变成了“可写的页面策略”。

---

## 核心解释

### 1. “高级”不是答案，只是一个入口

“高级”通常不是一个单独的设计属性。

它可能来自很多具体选择：

| 模糊感受 | 可能真正起作用的东西 |
|---|---|
| 高级 | 留白、字体层级、低饱和颜色、克制动效 |
| 干净 | 少装饰、少阴影、弱边框、明确对齐 |
| 有质感 | 图片比例、材质感、黑白对比、细节过渡 |
| 像杂志 | 大标题、窄正文、图文节奏、强封面图 |
| 像工具 | 高密度信息、清晰分组、状态反馈、筛选入口 |

所以看到一个页面时，不要停在：

```text
它很好看。
```

要继续追问：

```text
它靠什么变好看？
这个“好看”能拆成哪些变量？
这些变量我能不能写出来？
```

---

### 2. 一句话拆解公式

写观察时，可以套这个公式：

```text
它看起来像/给人感觉是 ______。
因为它主要用了 ______、______、______。
落到代码里，我要控制 ______、______、______。
```

比如：

```text
它看起来很高级。
因为它几乎没有阴影，主要靠细边框、留白和字号层级建立秩序。
落到代码里，我要控制 border、padding、max-width、text-size、font-weight、line-height。
```

这时你已经知道 Tailwind 大概会写什么：

```text
border border-neutral-200
px-6 py-12
max-w-6xl mx-auto
text-sm text-neutral-500
text-4xl font-semibold leading-tight
```

不一定一开始就写对。

但至少你知道该调哪里。

---

### 3. 好观察应该能回答“我接下来改什么”

判断一条观察有没有用，可以看它能不能指导下一步实现。

| 不够有用的写法 | 更有用的写法 |
|---|---|
| 这个网站很高级 | 几乎没有阴影，靠边框、留白和字号层级建立秩序 |
| 这个页面很干净 | 背景接近纯白，色彩很少，内容区用大量留白分组 |
| 卡片很好看 | 卡片没有厚重阴影，只用浅边框和图片比例区分层级 |
| 字体很舒服 | 标题字重不重，正文行高较松，段落宽度被控制得比较窄 |
| 交互很顺 | hover 只改变背景和文字颜色，过渡时间很短，没有夸张动画 |
| 首页很有节奏 | 大图、短文案、文章卡片交替出现，section 之间留白明显 |

更有用的观察通常包含三类信息：

```text
看到了什么
为什么有效
可以怎么写
```

比如：

```text
看到了什么：卡片没有阴影。
为什么有效：页面显得更克制，信息不浮躁。
可以怎么写：用 border、divide-y、gap 和 hover:bg 替代 shadow。
```

---

## 技术关系

### 1. 把观察翻译成 Tailwind

常见观察可以这样翻译。

| 设计观察 | Tailwind 思路 |
|---|---|
| 几乎没有阴影 | 少用 `shadow-*`，优先用 `border`、`divide-y` |
| 靠留白建立层次 | `px-*`、`py-*`、`gap-*`、`space-y-*` |
| 内容不铺太宽 | `max-w-*`、`mx-auto` |
| 字号层级清楚 | `text-xs`、`text-sm`、`text-4xl`、`font-medium` |
| 正文舒服 | `leading-7`、`max-w-prose`、`text-neutral-*` |
| 卡片克制 | `border`、`rounded-*`、`overflow-hidden`、少阴影 |
| 列表高密度 | `text-sm`、`leading-5`、`divide-y` |
| hover 很轻 | `hover:bg-*`、`hover:text-*`、`transition`、`duration-200` |

这不是固定答案。

它只是提醒你：

```text
设计观察
-> 样式变量
-> Tailwind class
```

中间不能跳过“样式变量”。

---

### 2. 先拆变量，再写组件

不要一开始就问：

```text
这个组件怎么写？
```

先问：

```text
这个组件靠哪些变量成立？
```

比如一个文章卡片，先拆：

- 图片比例
- 标题字号
- 摘要行高
- 边框还是阴影
- 卡片之间的间距
- hover 时变化什么

然后再写组件。

这样组件不是硬凑出来的，而是从观察里长出来的。

---

## 学习建议

### 1. 每次临摹前先写 5 条“可实现观察”

打开项目之前，先写 5 条观察。

每条都尽量包含：

```text
感受
-> 设计变量
-> 可能的 Tailwind 写法
```

例如：

```text
这个页面很冷静
-> 色彩很少，主要是黑白灰，强调色几乎不用
-> text-neutral-*、bg-white、border-neutral-200
```

写不出来也没关系。

这说明你还需要多看页面，而不是马上开写。

### 2. 做完后回头检查一句话

项目做完后，回看最开始写的观察。

问自己：

```text
我有没有真的把这条观察写进页面？
```

如果你写的是：

```text
靠边框、留白和字号层级建立秩序
```

那就检查：

- 页面是不是用了太多阴影
- section 之间有没有足够留白
- 标题、正文、辅助文字是否有层级
- 卡片和列表是不是靠边框、分割线、间距组织

这一步比“看起来像不像”更具体。

---

## 小结

这篇只想强化一件事：

```text
不写：这个网站很高级。
要写：它几乎没有阴影，主要靠边框、留白和字号层级建立秩序。
```

前一句是感受。

后一句是方法。

这套练习要训练的，就是把感受变成方法，再把方法写成页面。
