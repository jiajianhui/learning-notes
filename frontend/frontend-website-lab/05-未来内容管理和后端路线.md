# 05. 内容怎么管理：现在先静态，未来再接后端

## 问题背景

你最终想做的不是一个只展示一次的静态页面，而是自己的个人网站：

```text
能放个人产品
能写文章
能整理项目
能长期更新
```

这种网站迟早会遇到一个问题：

```text
内容放在哪里？
文章怎么发布？
产品怎么新增？
标签、分类、图片怎么管理？
```

你的未来后端路线已经很清楚：

```text
Node.js + Express + PostgreSQL
```

但当前阶段先不要急着学后端。

主线先记这一条：

```text
现在先用 Next.js + TailwindCSS 做出网站的视觉完成度
-> 内容先用本地数组、JSON 或 Markdown 模拟
-> 以后再用 Node.js + Express + PostgreSQL 管理真实内容
```

---

## 核心解释

### 1. Lux 是怎么管理内容的：更像 Ghost 这一类 CMS

从前面抓到的源码线索看，`lux.camera` 不是典型的“自己写 Express 后端 + PostgreSQL 数据库”的网站。

它更像是：

```text
Ghost CMS
+ 自定义 Ghost 主题
+ 图片 CDN
+ 搜索、统计、内容 API
```

Ghost 可以先理解成：

```text
专门给博客、杂志、内容站用的一套发布系统。
```

它通常会帮你处理这些事：

- 写文章
- 管理作者
- 管理标签
- 上传图片
- 提供文章列表和文章详情数据
- 生成博客页面
- 提供后台编辑界面

所以 Lux 值得你学习的重点不是它用了 Ghost，而是它把内容站做得很有气质：

```text
产品入口
文章列表
图片节奏
专题区
品牌统一性
```

这些能力，未来你用不用 Ghost 都用得上。

---

### 2. 你的未来路线是什么：自己做一套内容系统

你以后想学的是：

```text
Node.js + Express + PostgreSQL
```

可以先这样理解这三个名字。

| 名字 | 先怎么理解 | 在个人网站里负责什么 |
|---|---|---|
| Node.js | 让 JavaScript 跑在服务器上的环境 | 运行后端代码 |
| Express | Node.js 里的后端 Web 框架 | 写接口，比如获取文章列表 |
| PostgreSQL | 关系型数据库 | 保存文章、产品、标签、项目记录 |

放到个人网站里，它们的关系大概是：

```text
Next.js 前端
-> 请求 Express API
-> Express 查询 PostgreSQL
-> 返回文章、产品、项目数据
-> 前端渲染页面
```

这就是“动态管理网站内容”的基本形态。

---

### 3. Ghost 和自建后端有什么区别

可以先用这张表理解。

| 方案 | 像什么 | 优点 | 代价 |
|---|---|---|---|
| Ghost CMS | 现成内容发布系统 | 很快能写文章、管理标签、使用后台 | 自定义业务能力会受它的系统影响 |
| Node.js + Express + PostgreSQL | 自己搭一套内容 API | 灵活，适合练后端和做自己的产品逻辑 | 需要自己设计数据库、接口和管理后台 |
| 当前本地数据 | 用文件模拟内容 | 最简单，适合先练页面 | 不是真正动态管理 |

这轮练习先选第三种。

原因很简单：

```text
你现在最需要练的是页面品味，不是系统复杂度。
```

等个人网站的前端形态稳定之后，再切到第二种路线。

不过这不代表成熟 CMS 不值得碰。

更合理的做法是：

```text
先用本地数据练页面
-> 在 Lux 这类内容站练习后试一次 Ghost
-> 看成熟 CMS 到底帮你解决了哪些重复问题
-> 后端阶段再自己实现一个小而清楚的版本
```

工具提效路线可以回看：

- [06-好用工具和 CMS：不是偷懒，是把精力放到关键处](./06-好用工具和CMS提效路线.md)

## 技术关系

### 1. 当前阶段：用本地内容模拟真实网站

现在每个项目可以先这样做内容：

```text
data/articles.ts
data/products.ts
data/projects.ts
```

或者：

```text
content/articles/*.md
content/projects/*.md
```

这一步的目标不是假装自己已经有后端，而是先把真实网站会出现的内容类型练出来。

比如个人网站未来大概率会有：

| 内容类型 | 现在怎么模拟 |
|---|---|
| 产品 | 本地数组里的 product cards |
| 文章 | Markdown 或本地 article list |
| 标签 | 字符串数组 |
| 分类 | category 字段 |
| 封面图 | `public/images/` |
| 精选内容 | `featured: true` |
| 发布状态 | `status: "published"` |

这样写的好处是：

```text
未来接后端时，页面结构不用大改。
只是把“本地数据”换成“接口返回的数据”。
```

---

### 2. 未来阶段：从静态内容走到动态内容

未来可以按这个顺序升级，不要一步到位：

```text
第 1 步：本地数组 / JSON
第 2 步：Markdown / MDX
第 3 步：模拟 API 返回数据
第 4 步：Express 写真实 API
第 5 步：PostgreSQL 保存内容
第 6 步：做一个简单管理后台
```

到第 4 步之后，网站结构会变成：

```text
浏览器
-> Next.js 页面
-> Express API
-> PostgreSQL 数据库
```

到第 6 步之后，才会出现真正的“内容管理”：

```text
登录后台
-> 新建文章
-> 上传封面
-> 设置标签
-> 发布
-> 前台自动展示
```

这些都很重要，但不是这轮练习的主战场。

---

### 3. 它和 Lux 的关系：学形态，不抄后台

Lux 对你的启发应该是：

```text
一个个人产品或独立团队网站，也可以像一本精美杂志。
```

它值得临摹的是：

- 首页如何兼顾产品和文章
- 图片如何制造质感
- 文章卡片如何有编辑感
- 导航如何让产品、博客、更新共存
- 内容长期更新时，页面仍然保持统一气质

至于后台怎么做，可以以后再选：

```text
用现成 CMS
或者自己写 Node.js + Express + PostgreSQL
```

对你来说，更有学习价值的路线是先自建一次。

因为它能让你真正理解：

```text
前端页面
API
数据库
内容管理
部署
```

这些东西是怎么接起来的。

## 学习建议

### 1. 现在不要把项目做成全栈

现在每个临摹项目只需要问：

```text
这个页面需要哪些内容？
这些内容用什么结构保存？
用 Tailwind 怎么排得好看？
```

不要现在就问：

```text
数据库表怎么设计？
后台编辑器怎么做？
用户权限怎么做？
图片上传怎么做？
```

这些问题留到后端阶段。

### 2. 但写前端时要提前有数据意识

即使现在不用数据库，也不要把内容乱写在 JSX 里。

优先这样组织：

```text
数据
-> 组件
-> 页面
```

比如：

```text
articles 数据
-> ArticleCard 组件
-> ArticleGrid 页面区域
```

这会让你以后接 Express API 时更轻松。

---

## 小结

这轮学习的边界是：

```text
先做出好看、完整、有品味的个人网站前端。
```

未来的技术路线是：

```text
Node.js + Express + PostgreSQL
```

Lux 更像是用 Ghost 这类 CMS 管理内容。

你现在不用照抄它的后台，只要先学它的内容站气质。等前端练稳，再把自己的后端系统接进来。
