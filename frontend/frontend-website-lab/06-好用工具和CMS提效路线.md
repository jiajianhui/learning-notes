# 06. 好用工具和 CMS：不是偷懒，是把精力放到关键处

## 问题背景

你倾向于自己搭建 CMS，这个方向是对的。

因为自建一次内容系统，能真正练到：

```text
接口
数据库
文章模型
标签模型
图片上传
发布状态
后台管理
部署维护
```

但这不代表所有阶段都要硬写。

成熟工具也值得试。就像写前端不会每次都自己实现路由、构建工具、轮播、弹窗和 CSS 框架一样，做内容站也可以先研究成熟 CMS。

主线先记这一条：

```text
工具不是替代学习
-> 工具帮你看见成熟解法
-> 自建时再把关键能力拆回来练
```

所以这一节值得放进 `frontend-website-lab`。

它解决的不是“我以后还要不要学后端”，而是另一个问题：

```text
什么时候借工具提高效率？
什么时候自己写来练能力？
```

---

## 核心解释

### 1. 为什么 Ghost 值得试：它让你看到 CMS 的完整样子

Ghost 可以先理解成：

```text
给内容站、博客、Newsletter、会员订阅准备的一整套发布系统。
```

它帮你处理：

- 文章编辑
- 作者管理
- 标签管理
- 图片上传
- 主题系统
- 搜索
- 内容 API
- 会员和订阅
- 后台编辑界面

你不用把它当成最终方案。

更好的学习方式是：

```text
先用 Ghost 跑一个真实后台
-> 看成熟 CMS 都有哪些模块
-> 再决定自己以后要实现哪些最小能力
```

这会让你以后自建 CMS 时少走弯路。

比如你会更清楚：

| Ghost 里已经有的能力 | 以后自建 CMS 时对应练什么 |
|---|---|
| Posts | 文章表、文章 API、文章详情页 |
| Tags | 标签表、多对多关系、筛选 |
| Authors | 用户表、作者信息、权限边界 |
| Assets | 图片上传、图片路径、静态资源服务 |
| Draft / Published | 草稿状态、发布时间、发布流程 |
| Themes | 前台页面模板、组件和内容数据的关系 |
| Content API | 后端如何给前端提供内容数据 |

---

### 2. 工具和自建不是二选一

可以把学习路线分成两条线：

```text
做作品
-> 借成熟工具提效

练后端
-> 自己实现关键模块
```

它们不冲突。

更合理的节奏是：

| 阶段 | 内容管理怎么做 | 目的 |
|---|---|---|
| 当前前端练习 | 本地数组、JSON、Markdown | 先把页面做漂亮 |
| Lux 风格内容站练习后 | 本地试 Ghost | 看成熟 CMS 怎么组织内容 |
| 个人网站第一版 | Markdown / 本地数据 / Ghost 当 Headless CMS（Ghost 管内容后台，Next.js 做网站前台）三选一 | 先让作品可用 |
| 后端学习阶段 | Node.js + Express + PostgreSQL 自建轻量 CMS | 真正练接口、数据库和后台 |

一句话：

```text
做作品时用工具提效
练后端时自己实现关键模块
```

---

### 3. 这一节该怎么学：只试最小闭环

不要一上来就研究 Ghost 的所有功能。

这里先记一句：

```text
Headless CMS
-> Ghost 管内容后台
-> Next.js 做网站前台
```

后面会再展开它和传统 CMS 用法的区别。

先试一个最小闭环：

```text
本地跑起来
-> 创建文章
-> 创建标签
-> 上传封面图
-> 看主题如何展示内容
-> 看 Content API 怎么把文章给前端
```

官方本地安装路线可以这样跑：

```bash
mkdir ghost-lab
cd ghost-lab
npm install ghost-cli@latest -g
ghost install local
```

跑起来后打开：

```text
前台：http://localhost:2368
后台：http://localhost:2368/ghost
```

注意：

```text
Ghost 本地安装需要一个干净空目录。
不要直接装进 frontend-website-lab 项目目录里。
```

第一次试 Ghost，只看这些地方就够：

| 位置 | 观察什么 |
|---|---|
| Posts | 一篇文章有哪些字段 |
| Tags | 标签和文章是什么关系 |
| Pages | 页面和文章有什么区别 |
| Settings | 站点标题、导航、品牌设置放在哪里 |
| Design / Theme | 前台页面外观怎么被主题控制 |
| Content API | 前端怎样读取内容数据 |

## 技术关系

### 1. Ghost 可以有两种用法

##### 1.1 传统 CMS 用法

```text
Ghost 后台
-> Ghost 主题
-> Ghost 直接生成前台网站
```

这种方式最快。

适合你快速理解：

- 文章如何发布
- 主题如何控制页面
- 后台和前台如何连在一起

##### 1.2 Headless CMS 用法

```text
Ghost 后台
-> Ghost Content API
-> Next.js 前端
```

`Headless` 的意思是“不要它自带的前台页面”。

它不是另一个 Ghost 产品，而是 Ghost 的一种接法。

可以这样理解：

```text
Ghost 负责内容后台
-> 管文章、标签、图片、作者、发布状态
Next.js 负责网站前台
-> 自己写页面、样式、交互和路由
```

这种方式更贴近你的长期方向。

因为你仍然可以用 Next.js + Tailwind 做自己的前台，只是暂时把文章管理交给 Ghost。

以后你自建后端时，可以把它替换成：

```text
Node.js + Express API
-> PostgreSQL
-> Next.js 前端
```

前端页面不一定要大改。

---

### 2. 哪些工具值得先用

结合前面参考站里出现的工具，可以先这样分类。

| 工具 | 当前阶段怎么用 | 以后是否需要自己写 |
|---|---|---|
| Ghost | 试 CMS，理解内容系统 | 后端阶段可以自建一个小版 |
| Netlify / Vercel | 部署前端项目、生成预览链接 | 不需要自己写部署平台 |
| Fastly / CDN | 理解图片和资源为什么要走 CDN | 不需要自己写 CDN |
| Swiper | 复杂轮播做不稳时再引入 | 简单横滑可以先自己写 |
| NProgress | 页面跳转进度条 | 可以用现成库 |
| Headless UI | 菜单、弹窗、列表框等交互组件 | 可先用库，再学可访问性细节 |
| Next.js / React / TailwindCSS | 当前练习主线 | 不需要自己造框架 |

判断原则很简单：

```text
如果这个东西是作品的基础设施，就优先用成熟工具。
如果这个东西正好是你的学习目标，就自己写一个最小版。
```

---

### 3. 自建 CMS 时先别追完整 Ghost

Ghost 是成熟产品，不是你的第一版作业。

以后自己写 CMS，可以只做最小模型：

```text
文章
标签
封面图
草稿 / 发布
文章列表 API
文章详情 API
简单后台表单
```

第一版不要急着做：

- 会员系统
- Newsletter
- 复杂权限
- 主题市场
- 多作者协作
- 数据统计
- 全文搜索

这些都可以以后加。

你自建 CMS 的目标不是“复刻 Ghost”，而是：

```text
理解一个内容系统从数据库到前端页面是怎么跑通的。
```

## 学习建议

### 1. 在 Lux 项目后试 Ghost 最合适

建议顺序：

```text
先做 03-lux-style-editorial-site
-> 体会内容站页面需要什么
-> 再本地试 Ghost
-> 回头理解为什么成熟内容站会需要 CMS
```

这样 Ghost 不是空学工具，而是回答你刚刚遇到的问题：

```text
文章多起来以后怎么管理？
图片、标签、作者、专题怎么组织？
```

### 2. 每次看到工具，都问三个问题

```text
它解决了什么重复问题？
我现在是否真的需要它？
如果以后自己写，最小版要实现哪 3 个能力？
```

这比单纯收藏工具更有用。

---

## 小结

这类工具教程值得加。

但它在这套路线里的定位要清楚：

```text
不是从“自己学后端”改成“永远用工具”
而是先用好工具提高效率
再把真正值得练的部分拆出来自己写
```

Ghost 就是一个很好的样本。

它能帮你提前看懂一个成熟 CMS 的形态；等你开始学 Node.js + Express + PostgreSQL，再自建一个小而清楚的个人网站内容系统。
