# 03. 设计怎么拆：把感觉翻译成代码

## 问题背景

做优秀网站，不能只问：

```text
这个用什么技术实现？
```

更重要的问题是：

```text
这个页面为什么看起来好？
```

技术是落地方式，看懂设计选择背后的原因，才是这轮练习的核心。

主线先记这一条：

```text
先拆感觉，再拆结构，最后拆 Tailwind 写法。
```

---

## 核心解释

### 1. 先说出这个网站的感觉

先用 3 到 5 个词描述它：

```text
冷静、密集、复古、克制、锐利、温暖、像杂志、像工具、像档案、像艺术书
```

例子：

| 网站 | 可以提炼的感觉 |
|---|---|
| funes.matsu.io | 极简、档案感、冷静、高密度 |
| aeroprecipe.com | 亲切、工具感、内容丰富、轻量产品化 |
| lux.camera | 摄影感、编辑感、黑白对比、产品质感 |
| makingsoftware.com | 叙事、个性、图形化、书籍感 |

---

### 2. 再画页面骨架

不用画漂亮，画结构：

```text
Header
Hero
Section A
Section B
Grid / List
Footer
```

关键是看：

- 页面有几个主要区块
- 哪个区块最重
- 哪个区块最轻
- 内容是横向展开还是纵向阅读
- 页面有没有固定导航或侧栏

---

### 3. 然后拆视觉系统

记录这些设计变量：

```text
背景色
正文色
强调色
最大内容宽度
基础字号
标题字号
行高
圆角
边框
图片比例
section 间距
card 间距
```

不要只写“好看”。要写成可以实现的观察：

```text
标题很大，正文很小，中间留白大。
卡片没有阴影，只靠边框和图片比例区分。
列表很密，hover 时只改变背景和文字色。
```

---

## 技术关系

### 1. 核心组件：从页面结构里长出来

每个项目先只拆这些：

- `SiteHeader`
- `Hero`
- `ContentCard`
- `ContentList`
- `FilterPanel`
- `SiteFooter`

如果组件名字想不出来，说明你还没有看清页面结构，可以先写在一个页面里。

---

### 2. 交互细节：不要贪多

交互不要贪多。每个项目挑 2 到 4 个：

- 导航 hover
- 卡片 hover
- 图片 hover
- sticky sidebar
- drawer menu
- filter active
- 横向滚动
- 滚动进场淡入

每个交互都要问：

```text
它是在帮助理解，还是只是在炫？
```

---

### 3. Tailwind 写法：把设计语言转成 class

把设计语言转成 class：

```text
大标题 -> text-5xl / text-7xl / leading-none
细边框 -> border border-neutral-200
高密度 -> text-xs leading-5 divide-y
大图裁切 -> aspect-[16/9] object-cover
固定侧栏 -> sticky top-6 h-[calc(100vh-3rem)]
柔和过渡 -> transition duration-200 ease-out
```

---

## 学习建议

每次临摹前，先写 5 句话：

```text
这个网站的感觉是什么？
首屏最重要的信息是什么？
它主要靠什么建立高级感？
我这次只学其中哪 3 个点？
这些点分别怎么用 Tailwind 写？
```

写不出来就先不要开项目。

这不是拖延，而是在避免盲写。

---

## 小结

这轮练习里，最重要的不是“我会不会写某个 class”，而是：

```text
我能不能看出一个好页面的秩序，并把它翻译成代码。
```
