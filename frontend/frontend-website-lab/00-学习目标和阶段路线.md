# 00. 从学技术到做网站：这一阶段练什么

## 问题背景

前面的学习已经帮你建立了前端技术地图。接下来要换一种学习方式：

```text
不再围绕知识点学，而是围绕优秀网站做。
```

这轮练习的目标不是证明自己懂多少技术，而是训练这件事：

```text
看到一个设计很棒的网站，能拆出来、做出来、再变成自己的东西。
```

这套练习背后的长期目标是：

```text
做出自己的个人网站。
它要能放个人产品、文章、项目记录和长期创作沉淀。
```

所以这不是随机临摹几个酷站，而是在为自己的长期个人网站积累能力。

这套路线的关键不是“临摹完四个网站”，而是：

```text
每个参考站只取最有价值的一部分
-> 迁移到自己的个人网站
-> 最后做成一个可长期更新的网站
```

参考目标：

- https://funes.matsu.io/
- https://aeroprecipe.com/
- https://www.lux.camera/
- https://www.makingsoftware.com/

主线先记这一条：

```text
基础阶段看技术分层
-> 项目阶段看网站完成度
-> 做出自己的个人网站
```

---

## 核心解释

### 1. 这阶段练什么：版式、字体、间距、交互细节

这轮练习只盯 4 个能力：

| 能力 | 具体练什么 |
|---|---|
| 版式 | 页面分区、栅格、内容密度、留白 |
| 字体 | 字号层级、字重、行高、英文/中文混排 |
| 间距 | section、card、list、button 的节奏 |
| 交互细节 | hover、active、sticky、drawer、filter、scroll |

暂时不把重点放在：

- CMS
- 后端
- 数据库
- 登录注册
- 支付
- 管理后台
- 原站技术栈考据

但这不等于未来不做后端。

长期个人网站的内容管理路线，可以先记成：

```text
Node.js + Express + PostgreSQL
```

只是当前阶段先不学它。

现在先用本地数据把页面做漂亮，等页面形态稳定之后，再让后端来管理文章、产品、标签和图片。

中间可以试成熟工具，但不要让工具打断这轮主线：

| 工具方向 | 先怎么放进路线 |
|---|---|
| VitePress | 适合文档站、学习笔记和教程，不是个人内容 CMS 主线 |
| MDX | 放在后端数据库之前，作为个人网站文章和项目复盘的文件型轻 CMS |
| Ghost | 在 Lux 项目后试一次，看成熟内容发布系统怎么组织文章 |
| Payload CMS | 个人网站第一版稳定后重点看，和 Next.js 路线更近 |
| Directus | 学 PostgreSQL 后再看，帮助理解数据库后台和 API |

工具选择的完整说明放在：

- [05A-MDX轻CMS方案.md](./05A-MDX轻CMS方案.md)
- [06-好用工具和CMS提效路线.md](./06-好用工具和CMS提效路线.md)

一句话：

```text
这轮练的是前端页面的品味和完成度。
```

放回个人网站目标里，可以这样理解：

| 现在练的能力 | 以后用在个人网站哪里 |
|---|---|
| 版式 | 首页、产品区、文章区、项目区的整体结构 |
| 字体 | 个人品牌气质、文章阅读体验 |
| 间距 | 页面高级感和内容节奏 |
| 交互细节 | 导航、筛选、移动端菜单、文章卡片反馈 |

---

### 2. 为什么直接用 Next.js + TailwindCSS：项目目标已经明确

如果目标只是理解概念，可以继续用最小 demo。

但现在目标已经变成：

```text
做出像优秀网站一样的页面
```

所以可以直接进入：

```text
Next.js + React + TypeScript + TailwindCSS
```

这里不是因为 Next.js 是唯一选择，而是为了先固定主线，减少分心。

## 技术关系

### 1. 四个练习分别练什么，最后用在个人网站哪里

##### 阶段 1：极简信息站

参考：

```text
https://funes.matsu.io/
```

练习重点：

- 单色或近似单色页面
- 高密度列表
- 极少装饰下的秩序感
- hover 和 active 状态
- CSS Grid / Flex 布局

目标：证明不靠大图和复杂动效，也能做出有品味的页面。

##### 阶段 2：数据型内容站

参考：

```text
https://aeroprecipe.com/
```

练习重点：

- 卡片列表
- 筛选侧栏
- sticky 区域
- 横向滚动推荐区
- 本地数据驱动页面

目标：从“静态展示”进入“内容很多但仍然清楚”的真实网站形态。

##### 阶段 3：编辑类图片内容站

参考：

```text
https://www.lux.camera/
```

练习重点：

- 大图 hero
- 图片文章卡片
- 首页内容节奏
- 文章列表和专题区
- 图片遮罩、hover、淡入

目标：练习摄影、产品、博客类网站的高级视觉表达。

这一阶段最接近个人网站的长期目标。以后你的个人网站大概率也会需要：

```text
产品入口
文章列表
精选内容
长期更新的内容系统
统一的视觉气质
```

##### 阶段 4：视觉叙事站

参考：

```text
https://www.makingsoftware.com/
```

练习重点：

- 强个性的视觉语言
- 章节型页面
- 文本和图形的关系
- 滚动节奏
- 小而精的动效

目标：从“页面像样”走向“页面有性格”。

##### 阶段 5：个人网站

目标项目：

```text
projects/05-personal-lux-style-site/
```

它不是再临摹一个新网站，而是把前面练到的东西放进自己的站：

| 来源练习 | 迁移到个人网站哪里 |
|---|---|
| Funes | 文章索引、项目清单、资源列表的密度和秩序 |
| AeroPrecipe | 标签筛选、内容卡片、移动端筛选入口 |
| Lux | 首页主视觉、产品入口、精选文章、图片和品牌气质 |
| Making Software | About 页、首页叙事段落、项目复盘页的作者气质 |

这一阶段的目标：做出一个能长期使用的个人网站，而不是一个一次性 demo。

从这个阶段开始，可以正式接入：

```text
TypeScript 数据文件
-> 管列表 metadata

MDX
-> 写文章和项目复盘正文

mdx-components.tsx
-> 统一文章元素的渲染和样式
```

### 2. 项目默认技术路线

默认项目技术栈：

```text
Next.js + React + TypeScript + TailwindCSS
```

默认项目策略：

- `app/` 路由
- TypeScript
- TailwindCSS
- 本地数据文件
- 个人网站阶段再接 MDX 文章和组件映射
- 组件按页面需要拆分
- 先完成视觉和交互，再考虑抽象

未来会接上的后端路线：

```text
MDX 文件型轻 CMS
-> 内容结构先稳定
-> 后端阶段再接入
Node.js
-> Express
-> PostgreSQL
-> 内容 API
-> 个人网站前端读取内容
```

这条线先放在脑子里，不要现在就把练习变复杂。

## 学习建议

### 1. 每个练习按同一套流程做

```text
1. 截图观察
2. 拆页面结构
3. 拆视觉系统
4. 列核心组件
5. 搭 Next 项目
6. 用 Tailwind 还原
7. 做响应式
8. 补交互细节
9. 写复盘
10. 写清楚：这一站能迁移到个人网站的 1 到 2 个点
```

临摹不是终点。每个项目结束时都要多写一句：

```text
如果我要把这个能力放进自己的个人网站，它应该出现在哪个页面？
```

### 2. 不要在第一轮追求完美

第一轮先做到：

```text
结构像
气质像
移动端不乱
交互有基本反馈
```

第二轮再改：

```text
字体更准
间距更准
图片比例更准
细节更舒服
```

---

## 小结

这轮学习的主线不是“我学完了 Next.js”，也不是“我临摹完四个网站”，而是：

```text
我能用 Next.js + TailwindCSS 做出接近优秀网站的视觉完成度，
并把这些能力用在自己的个人网站里。
```

当你能稳定做出这种完成度，再回头学 CMS、后端和数据库，就不会被功能复杂度拖住审美观察。

在这之前，可以先插入一章 MDX：

```text
不用后台
不用数据库
先让个人网站拥有可长期写文章和项目复盘的内容结构
```
