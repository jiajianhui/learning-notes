## 04、开发过程中的收获
- 使用 Next.js 开发时，page.tsx 最好保持清楚，只负责页面结构和组合，不要塞太多交互逻辑。

- _components 这种下划线私有目录可以明确告诉自己和团队：这里不是路由，是内部实现


- 关于`use client`：在 Next App Router 中，组件默认是 Server Component，不能使用 `useState`、`useEffect`、`onClick` 等客户端交互能力；需要交互时要在对应组件顶部加 `"use client"`，Next 才会把这个组件作为 Client Component 发送到浏览器执行。


- 关于组件：保持 page.tsx 的干净整洁，不要为了拆分而拆分

- Tailwind CSS相关：Tailwind 是移动端优先：不带前缀的基础样式默认从小屏开始设计，再用 `sm`、`md`、`lg` 等断点为更大的屏幕逐级覆盖或增强。

## 05、这次学到的 Tailwind 写法
- flex-1 —— 撑开剩余空间，父元素必须先有一个“可用高度”
- col-span-2 —— 元素横向占 2 列
- self-stretch —— 在交叉轴方向上拉满父级
- justify-center —— 沿主轴居中
- items-center —— 沿交叉轴居中

## 07、开发问题记录
在本地开发时，如果手机通过局域网 IP 访问电脑上的 Next dev server，可能会被 Next 的开发模式跨源限制拦截部分开发资源，导致页面交互异常；可以在 `next.config.ts` 中配置允许的开发来源，例如 `allowedDevOrigins: ["172.20.10.5"]`，然后重启服务生效。正式部署后通常不会有这个问题。
