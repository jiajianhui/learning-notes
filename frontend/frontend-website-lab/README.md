# Next.js + Tailwind：用项目练出好网站的感觉

## 问题背景

前面的 `frontend-system-learning` 解决的是：

```text
现代前端有哪些层？
每一层解决什么问题？
React、Vue、Vite、Next、Nuxt 之间是什么关系？
```

这套文档从这里开始换一个目标。

现在不再继续补基础课，而是进入真实网站练习：

用 Next.js + TailwindCSS 做出接近这些优秀网站的视觉、版式、交互和品味：

- https://www.lux.camera/
- https://funes.matsu.io/
- https://aeroprecipe.com/
- https://www.makingsoftware.com/

更长期的目标是：

```text
做出自己的个人网站，
用来放个人产品、文章、创作记录和项目沉淀。
```

其中 `lux.camera` 是最接近长期目标的参考形态：它既有产品入口，也有文章内容，还有统一的品牌气质。

主线先记这一条：

```text
不是复刻原站技术栈
-> 而是学习优秀网站的设计判断
-> 每个练习都沉淀到自己的个人网站
-> 最后做出一个 Lux 气质的个人网站成品
```

这套目录不只是“四个临摹项目”。更准确地说，它是：

```text
四个能力练习
+ 一个最终个人网站项目
```

前四个项目分别练排版、数据、图片和叙事；最后把这些能力合成到自己的个人网站里。

未来内容管理可以先记成这一条：

```text
现在先用本地数组、JSON、Markdown 模拟内容
-> 以后再用 Node.js + Express + PostgreSQL 动态管理内容
-> 中间可以试 Ghost 这类成熟 CMS，学习它怎么提高内容站效率
```

## 核心解释

### 1. 这套目录解决什么问题：把审美拆成能写的代码

这轮练习不急着做 CMS、后端、数据库。

先把重点放在这些问题上：

- 页面结构为什么舒服
- 字体、间距、颜色为什么高级
- 卡片、列表、导航、图片如何组织
- hover、滚动、切换、筛选这些交互如何克制地增强体验
- 如何用 Next.js + TailwindCSS 把这些设计判断落到代码里

如果这套目录只能记住一条训练规则，就是这句：

```text
不要只写感受，要写能指导实现的观察。
```

比如：

```text
不写：这个网站很高级。
要写：它几乎没有阴影，主要靠边框、留白和字号层级建立秩序。
```

这句话不是写作技巧，而是整套练习的观察标准。

它单独展开在：

- [01A-把高级感写成可实现的观察.md](./01A-把高级感写成可实现的观察.md)

一句话：

```text
先做出好看的前端页面，再考虑复杂功能。
```

对最终个人网站来说，先要练出来的是这些能力：

| 个人网站模块 | 现在对应练什么 |
|---|---|
| 个人产品展示 | 产品入口、视觉卡片、CTA（行动入口，比如查看作品、阅读文章、联系我）、品牌气质 |
| 文章和笔记 | 编辑类排版、文章列表、详情页结构 |
| 项目沉淀 | 高密度列表、分类、筛选、标签 |
| 个人表达 | 章节叙事、视觉语言、滚动节奏 |

## 技术关系

### 1. 项目怎么推进：四个练习，最后合成一个个人网站

建议顺序：

```text
01-funes-style-minimal-site
-> 极简信息站：练字体、列表、密度、hover、信息架构

02-aeroprecipe-style-data-site
-> 数据型内容站：练卡片、筛选、侧栏、响应式布局

03-lux-style-editorial-site
-> 图片编辑类内容站：练大图、文章卡片、首页视觉节奏

04-makingsoftware-style-visual-site
-> 视觉叙事站：练章节、插画/图形、滚动节奏、个性化表达

05-personal-lux-style-site
-> 最终个人网站：把前四站学到的能力合成自己的作品
```

先做极简，再做数据，再做图片内容，最后做视觉叙事。

但不要把前四个项目理解成互不相关的临摹。每做完一个项目，都要问：

```text
这个项目里哪 1 到 2 个能力，能迁移到我的个人网站？
```

最终目标不是“我临摹过四个网站”，而是：

```text
我能做出一个有产品入口、有文章内容、有项目沉淀、有个人气质的网站。
```

---

### 2. 每个项目做到什么程度：有共同底线，但不要一刀切

四个参考网站的侧重点不一样，所以不要把每个练习都做成同一种强度。

共同底线是：

| 要求 | 说明 |
|---|---|
| 完整首页 | 至少是一页能从头看到尾的页面，不是零散组件 |
| 响应式 | 移动端和桌面端都能看，布局不明显崩掉 |
| 核心结构 | 有清楚的页面入口、主要内容区和收尾区域 |
| 项目复盘 | 写清楚参考站、练习重点、遇到的问题和可迁移到个人网站的部分 |

然后按项目选择重点：

| 项目 | 本次重点 | 不必强求 |
|---|---|---|
| `01-funes-style-minimal-site` | 字体、间距、列表密度、hover 反馈 | 不必做复杂组件和大动画 |
| `02-aeroprecipe-style-data-site` | 本地数据、卡片列表、筛选、响应式侧栏 | 不必追求强视觉叙事 |
| `03-lux-style-editorial-site` | 大图、产品入口、文章卡片、首页节奏 | 不必做完整博客系统 |
| `04-makingsoftware-style-visual-site` | 章节叙事、图形/插画感、滚动节奏、结尾行动入口 | 不必做复杂数据筛选 |
| `05-personal-lux-style-site` | 把前四个练习迁移成自己的个人网站 | 第一版不必做后台、数据库和登录 |

组件和交互不是硬凑数量。

更合理的要求是：

```text
前四个练习项目：至少有 1 个能复用的核心组件
前四个练习项目：至少有 1-2 个符合当前参考站气质的交互细节
最终个人网站：按 05 项目 brief 做成多页面成品站
```

比如：

```text
Funes：列表项 hover
Aeroprecipe：筛选 / 移动端 drawer
Lux：图片 hover / 文章卡片 hover
Making Software：sticky 章节导航 / 滚动过程中的视觉变化
个人网站：文章标签、项目卡片、页面导航、移动端菜单
```

不用一开始就完美。

先做出当前参考站最重要的气质，再慢慢补完成度。

## 练习顺序

这套目录不用先把所有文档读完再动手。

更合理的节奏是：

| 读到哪里 | 开始做什么 | 为什么这时做 |
|---|---|---|
| 读完 [00](./00-学习目标和阶段路线.md)、[01](./01-优秀网站拆解清单.md)、[01A](./01A-把高级感写成可实现的观察.md)、[02](./02-Nextjs-Tailwind启动方式.md)、[03](./03-设计拆解方法.md) | 做 [01-funes-style-minimal-site](./projects/01-funes-style-minimal-site/) | 已经知道目标、会拆参考站、项目能跑起来，也知道怎么把设计感觉翻译成 Tailwind |
| 做完 Funes，并按 [04-项目复盘模板](./04-项目复盘模板.md) 写复盘 | 做 [02-aeroprecipe-style-data-site](./projects/02-aeroprecipe-style-data-site/) | 先练过极简页面，再进入本地数据、卡片、筛选和响应式侧栏 |
| 做完 Aeroprecipe，并读 [05](./05-未来内容管理和后端路线.md) 里“当前阶段：用本地内容模拟真实网站”这一部分 | 做 [03-lux-style-editorial-site](./projects/03-lux-style-editorial-site/) | Lux 更接近产品 + 文章内容站，需要有内容结构意识，但还不需要真的做 CMS |
| 做完 Lux，并读 [06-好用工具和 CMS 提效路线](./06-好用工具和CMS提效路线.md) | 本地试一次 Ghost，记录成熟 CMS 解决了哪些问题 | Lux 最像产品 + 内容站，这时试 Ghost 最容易理解“工具为什么能提效” |
| 试完 Ghost，并继续按 [04-项目复盘模板](./04-项目复盘模板.md) 记录可迁移点 | 做 [04-makingsoftware-style-visual-site](./projects/04-makingsoftware-style-visual-site/) | 前面已经练过列表、数据和图文节奏，最后再挑战章节叙事和滚动视觉 |
| 四个练习都做完，并回看每次复盘里的可迁移点 | 做 [05-personal-lux-style-site](./projects/05-personal-lux-style-site/) | 这一步不再临摹单个网站，而是把前面练到的能力合成自己的个人网站 |
| 个人网站第一版能跑起来 | 回看 [05-未来内容管理和后端路线.md](./05-未来内容管理和后端路线.md) 和 [06](./06-好用工具和CMS提效路线.md) | 再考虑以后怎么接 Markdown、CMS、后端或数据库 |

每个项目结束后都要写复盘。

不是为了交作业，而是为了留下这次能迁移到个人网站的东西：

```text
我参考了什么
我学会了什么页面能力
哪些设计或组件以后可以放进自己的个人网站
```

## 小结

这套目录的核心不是“学完 Next.js”，而是：

```text

```
