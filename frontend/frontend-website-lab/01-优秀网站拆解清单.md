# 01. 优秀网站怎么拆：先看设计判断

## 问题背景

临摹不是把页面截图当背景描一遍。

真正有价值的临摹，是拆出这些东西：

```text
页面为什么这样分区？
信息为什么这样排列？
视觉重点为什么落在那里？
哪些细节让它看起来高级？
如果我用 Tailwind 写，要怎么组织？
```

主线先记这一条：

```text
先拆设计判断
-> 再拆页面结构
-> 最后拆 Tailwind 写法
```

##### 2.1 Ghost：给内容站用的发布系统

Ghost 可以先理解成：

```text
写文章、管理作者、管理标签、生成博客页面的一套系统。
```

它类似 CMS。

CMS 是 Content Management System，意思是内容管理系统。它解决的是：

```text
文章放哪里
图片放哪里
谁来发布
标签怎么管理
页面怎么生成
```

当前阶段不需要做 CMS。

你只需要先学 Lux 这种内容站的视觉：

```text
文章怎么排
图片怎么放
首页怎么有编辑节奏
```

从源码线索看，Lux 更像是 Ghost 驱动的内容站。

这和你未来想学的路线不是一套东西：

```text
Lux 当前线索
-> Ghost CMS + 自定义主题

你的未来路线
-> Node.js + Express + PostgreSQL + 自己写内容 API
```

现在不用急着选边。

这一轮先临摹 Lux 的内容站气质；等你开始学后端，再决定是用现成 CMS，还是自己做一套轻量内容管理系统。

完整对比可以回看：

- [05-未来内容管理和后端路线.md](./05-未来内容管理和后端路线.md)

---

##### 2.2 Netlify 和 Vercel：把网站部署出去的平台

Netlify 和 Vercel 可以先理解成：

```text
把前端项目构建好，再放到网上给别人访问的平台。
```

它们不是 UI 框架，也不是 CSS 框架。

它们主要负责：

- 构建
- 部署
- 域名
- CDN
- 预览链接

当前阶段你可以先在本地 `npm run dev` 做页面。等页面做好，再考虑部署。

---

##### 2.3 Next.js、React 和 TailwindCSS：这轮练习的主线

Next.js 可以先理解成：

```text
React 之上的应用框架。
```

React 负责组件。

Next.js 负责更完整的应用结构，比如：

```text
页面目录
路由
布局
构建
渲染模式
```

TailwindCSS 负责快速写样式。

这一轮主线就是：

```text
用 React 写组件
用 Next.js 组织页面
用 TailwindCSS 还原设计
```

---

##### 2.4 `__NEXT_DATA__` 和 `_next/static`：判断 Next.js 的线索

看到页面源码里有这些东西：

```text
__NEXT_DATA__
_next/static
x-powered-by: Next.js
```

通常说明这个网站和 Next.js 有关。

现在不需要深入它们的内部机制，只要知道：

```text
这些是识别 Next.js 项目的线索。
```

真正写项目时，还是回到：

```text
app/
layout.tsx
page.tsx
components/
```

---

##### 2.5 Swiper、NProgress、Headless UI：常见小工具

这些不是必须学的主线，但你会经常在网站里遇到。

| 名字 | 先怎么理解 |
|---|---|
| Swiper | 做轮播、横向滑动、图片切换的库 |
| NProgress | 页面加载时顶部那条进度条 |
| Headless UI | 提供菜单、弹窗、列表框等无样式交互组件 |

当前阶段可以这样处理：

```text
能用 CSS 和简单 React 状态做出来，就先自己做。
做不稳，再考虑引入库。
```

---

##### 2.6 CDN 和图片 CDN：让资源加载更快

CDN 可以先理解成：

```text
把图片、CSS、JS 放到离用户更近的服务器上。
```

图片 CDN 专门处理图片资源，比如：

- 不同尺寸
- 压缩
- 缓存
- 更快加载

当前阶段你不需要搭图片 CDN。

先用 `public/images/` 放本地图片，重点练：

```text
图片比例
object-cover
响应式尺寸
hover 效果
```

### 3. 页面结构：先只看骨架

先只看骨架：

```text
header
hero / intro
main content
secondary content
footer
```

记录：

- 首屏出现了什么
- 哪些内容被放大
- 哪些内容被压低
- 页面是单栏、双栏、卡片网格，还是列表
- 移动端结构是否改变

---

### 4. 视觉语言：把“好看”拆成变量

记录：

- 主背景色
- 文字颜色
- 强调色
- 字体气质
- 圆角大小
- 边框使用方式
- 阴影是否存在
- 图片是裁切、留白、遮罩，还是原样展示

重点观察：

```text
它靠什么显得高级？
是留白、字体、图像、秩序、动效，还是某种强个性？
```

---

### 5. 核心组件：先拆大块，不要拆太细

每个页面拆 3 到 6 个组件就够：

- Header
- Nav
- Hero
- Card
- List row
- Filter panel
- Article preview
- Footer

不要一开始拆太细。先把页面做出来，再提取组件。

## 技术关系

### 1. 交互细节：先做克制的反馈

至少记录：

- hover 状态
- active 状态
- sticky 区域
- drawer / menu
- 横向滚动
- 图片缩放或淡入
- 滚动时导航变化

交互原则：

```text
能不用复杂动画就不用复杂动画。
先做克制、稳定、舒服的细节。
```

---

### 2. Tailwind 落地方式：把观察翻译成 class

把观察翻译成 Tailwind：

| 设计观察 | Tailwind 思路 |
|---|---|
| 大留白 | `px-*`、`py-*`、`max-w-*`、`mx-auto` |
| 卡片网格 | `grid`、`grid-cols-*`、`gap-*` |
| 高密度列表 | `text-sm`、`leading-*`、`border-y`、`divide-y` |
| 悬浮反馈 | `hover:*`、`transition`、`duration-*` |
| 固定侧栏 | `sticky`、`top-*`、`h-screen` |
| 图片裁切 | `object-cover`、`aspect-*`、`overflow-hidden` |
| 细边框 | `border`、`border-neutral-*`、`divide-*` |

## 学习建议

每个项目先按下面模板拆，不要直接开写。

```md
# 项目名

## 参考网站

## 我想学习的感觉

## 页面结构

## 视觉关键词

## 核心组件

## 交互细节

## Tailwind 实现笔记

## 做完后的复盘
```

拆解时只写对实现有帮助的观察。

比如：

```text
不写：这个网站很高级。
要写：它几乎没有阴影，主要靠边框、留白和字号层级建立秩序。
```

---

## 小结

拆解时要盯住设计判断，不要陷入“原站到底用了什么库”。

这轮训练的关键句是：

```text
我不是复制技术栈，我是学习好网站的视觉决策。
```
