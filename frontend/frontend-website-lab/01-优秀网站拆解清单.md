# 01. 优秀网站怎么拆：先看它为什么这样设计

## 问题背景

临摹不是把页面截图当背景描一遍。

真正有价值的临摹，是拆出这些东西：

```text
页面为什么这样分区？
信息为什么这样排列？
视觉重点为什么落在那里？
哪些细节让它看起来高级？
如果我用 Tailwind 写，要怎么组织？
```

主线先记这一条：

```text
先看它为什么这样设计
-> 再拆页面结构
-> 最后拆 Tailwind 写法
```

这里的“为什么这样设计”，指的是：

```text
为什么这样分区？
为什么这样安排信息顺序？
为什么用这种字体、间距、颜色和边框？
这些选择最后制造了什么感觉？
```

### 3. 页面结构：先只看骨架

先只看骨架：

```text
header
hero / intro
main content
secondary content
footer
```

记录：

- 首屏出现了什么
- 哪些内容被放大
- 哪些内容被压低
- 页面是单栏、双栏、卡片网格，还是列表
- 移动端结构是否改变

---

### 4. 视觉语言：把“好看”拆成变量

记录：

- 主背景色
- 文字颜色
- 强调色
- 字体气质
- 圆角大小
- 边框使用方式
- 阴影是否存在
- 图片是裁切、留白、遮罩，还是原样展示

重点观察：

```text
它靠什么显得高级？
是留白、字体、图像、秩序、动效，还是某种强个性？
```

---

### 5. 核心组件：先拆大块，不要拆太细

每个页面拆 3 到 6 个组件就够：

- Header
- Nav
- Hero
- Card
- List row
- Filter panel
- Article preview
- Footer

不要一开始拆太细。先把页面做出来，再提取组件。

## 技术关系

### 1. 交互细节：先做克制的反馈

至少记录：

- hover 状态
- active 状态
- sticky 区域
- drawer / menu
- 横向滚动
- 图片缩放或淡入
- 滚动时导航变化

交互原则：

```text
能不用复杂动画就不用复杂动画。
先做克制、稳定、舒服的细节。
```

---

### 2. Tailwind 落地方式：把观察翻译成 class

把观察翻译成 Tailwind：

| 设计观察 | Tailwind 思路 |
|---|---|
| 大留白 | `px-*`、`py-*`、`max-w-*`、`mx-auto` |
| 卡片网格 | `grid`、`grid-cols-*`、`gap-*` |
| 高密度列表 | `text-sm`、`leading-*`、`border-y`、`divide-y` |
| 悬浮反馈 | `hover:*`、`transition`、`duration-*` |
| 固定侧栏 | `sticky`、`top-*`、`h-screen` |
| 图片裁切 | `object-cover`、`aspect-*`、`overflow-hidden` |
| 细边框 | `border`、`border-neutral-*`、`divide-*` |

## 学习建议

每个项目先按下面模板拆，不要直接开写。

```md
# 项目名

## 参考网站

## 我想学习的感觉

## 页面结构

## 视觉关键词

## 核心组件

## 交互细节

## Tailwind 实现笔记

## 做完后的复盘
```

拆解时只写对实现有帮助的观察。

比如：

```text
不写：这个网站很高级。
要写：它几乎没有阴影，主要靠边框、留白和字号层级建立秩序。
```

这条原则很重要，单独展开在：

## 小结

拆解时要盯住“它为什么这样设计”，不要陷入“原站到底用了什么库”。

这轮训练的关键句是：

```text
我不是复制技术栈，我是学习好网站的视觉决策。
```
