# 07. 关系型数据库：先把数据放进有规则的表

## 问题背景

内存数组可以暂时保存数据，但程序重启后数据会消失，也很难保证两条数据不会重复、两张表不会错误关联。

关系型数据库解决两件事：

```text
长期保存数据
用表结构和约束阻止错误数据
```

这一章先学习数据怎样组织，不急着连接 Node.js。下一章再使用 SQL 完成增删改查。

---

## 1. 表、行和列分别是什么

一张 `articles` 表可以先理解成：

| id | title | slug | status |
|---:|---|---|---|
| 1 | 第一篇文章 | first-article | draft |
| 2 | 第二篇文章 | second-article | published |

```text
表 table
-> 保存同一类数据，例如所有文章

行 row
-> 一条具体数据，例如 id 为 1 的文章

列 column
-> 每条文章都有哪些字段，例如 title 和 status
```

设计表时先问：

```text
一行代表什么？
每一行必须有哪些字段？
哪些字段不能重复？
```

---

## 2. 数据类型限制一列能保存什么

每一列都要声明数据类型。常用类型先掌握这些：

| 类型 | 适合保存 | 示例 |
|---|---|---|
| `INTEGER` | 常用整数编号 | `42` |
| `TEXT` | 标题、正文、slug | `"first-article"` |
| `BOOLEAN` | 是或否 | `true` |
| `TIMESTAMPTZ` | 带时区的时间 | 创建时间 |

数据类型解决的是：

> 这一列允许保存哪一类值？

它不能独自表达所有产品规则。例如 `TEXT` 可以保存任意文本，但文章状态只允许 `draft` 和 `published`，还需要约束继续限制。

---

## 3. `NULL`、`NOT NULL` 和 `DEFAULT`

### `NULL` 表示没有值

`NULL` 不是空字符串 `""`，也不是数字 `0`。它表示这一列当前没有值。

例如文章摘要可以不填：

```sql
summary TEXT
```

### `NOT NULL` 表示必须有值

标题和正文不能缺少：

```sql
title TEXT NOT NULL,
content TEXT NOT NULL
```

`NOT NULL` 只能阻止 `NULL`。空字符串 `""` 仍然需要应用校验或额外 `CHECK` 约束处理。

### `DEFAULT` 提供默认值

没有传文章状态时，数据库可以自动使用 `draft`：

```sql
status TEXT NOT NULL DEFAULT 'draft'
```

`DEFAULT` 只在没有提供该列时生效，不会自动修正错误值。

---

## 4. 约束负责阻止错误数据

数据类型回答“能保存哪类值”，约束回答“哪些值才允许保存”。

### 主键：稳定识别一行

```sql
id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY
```

`GENERATED ALWAYS AS IDENTITY` 表示这列的编号由 PostgreSQL 依次生成。创建文章时不用自己提供 id。

主键不能重复，也不能是 `NULL`。标题和 slug 以后都可能修改，表之间建立关系时通常使用稳定的 `id`。

### 唯一约束：某个值不能重复

```sql
slug TEXT NOT NULL UNIQUE
```

应用通常把 slug 放进公开 URL。数据库并不知道 URL 长什么样，它只负责保证两行文章不会保存相同 slug。

### `CHECK`：值必须符合指定条件

```sql
status TEXT NOT NULL
  DEFAULT 'draft'
  CHECK (status IN ('draft', 'published'))
```

这样即使应用漏掉校验，数据库也不会接受 `status = 'abc'`。

## 5. 一张文章表怎样建立

下面使用 PostgreSQL 语法建立一张最小文章表。当前不需要背下整段语法，先练习按列读懂每条规则：

```sql
CREATE TABLE articles (
  id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  title TEXT NOT NULL,
  slug TEXT NOT NULL UNIQUE,
  summary TEXT,
  content TEXT NOT NULL,
  status TEXT NOT NULL
    DEFAULT 'draft'
    CHECK (status IN ('draft', 'published')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

`NOW()` 表示 PostgreSQL 执行这条 SQL 时的当前时间。

逐列读：

```text
id
-> 数据库生成，稳定识别文章

title / content
-> 必须提供文本

slug
-> 必须提供，而且不能重复

summary
-> 可以没有值

status
-> 默认 draft，只允许两个状态

created_at / updated_at
-> 插入文章时没有提供这两列，就记录当时的时间
```

## 6. 表结构先做到什么程度

个人 Web 项目的第一轮，能够回答下面的问题就够了：

```text
一行代表什么？
每列是什么类型？
哪些列必须有值？
哪些值不能重复？
哪些值只能来自固定范围？
```

先把一张表设计正确，再进入 SQL CRUD。

## 小结

```text
表
-> 保存同一类数据

行
-> 表里的一条具体数据

列
-> 表中的一个字段，例如 title、slug 和 status

数据类型
-> 规定一列能保存哪一类值，例如 TEXT 和 TIMESTAMPTZ

NULL / NOT NULL
-> 这一列能不能没有值

DEFAULT
-> 没有提供这一列时，数据库使用什么值

主键 / UNIQUE / CHECK
-> 防止编号或 slug 重复、状态乱填
```
