# 11. 数据关系和事务：多张表怎样一起保持正确

## 问题背景

文章和标签不是一张表里的简单字段。

一篇文章可以有多个标签，一个标签也可以属于多篇文章，这是典型的多对多关系。

```text
articles
<-> article_tags
<-> tags
```

---

## 核心解释

### 1. 常见关系

```text
一对一
-> 一个用户对应一个个人设置

一对多
-> 一个作者对应多篇文章

多对多
-> 一篇文章有多个标签，一个标签属于多篇文章
```

多对多通常需要中间表。

### 2. 文章和标签的中间表

```sql
CREATE TABLE article_tags (
  article_id BIGINT NOT NULL REFERENCES articles(id) ON DELETE CASCADE,
  tag_id BIGINT NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (article_id, tag_id)
);
```

联合主键防止同一篇文章重复添加同一个标签。

外键防止关联不存在的文章或标签。

`ON DELETE CASCADE` 在这里表示文章或标签删除后，对应的关联记录一起删除，不是把另一侧的文章或标签也删除。

### 3. JOIN 把关联数据查回来

```sql
SELECT tags.id, tags.name, tags.slug
FROM tags
JOIN article_tags ON article_tags.tag_id = tags.id
WHERE article_tags.article_id = $1;
```

JOIN 不是把表永久合并，而是在一次查询里按关系组合结果。

---

## 为什么需要事务

假设创建文章需要：

```text
1. 插入 articles
2. 插入三条 article_tags
```

如果第一步成功、第二步失败，就会留下不完整结果。

事务让它们：

```text
全部成功 -> COMMIT
任何一步失败 -> ROLLBACK
```

### 使用 pg 执行事务

事务中的所有 SQL 必须使用同一个 client：

```ts
const client = await pool.connect();

try {
  await client.query("BEGIN");

  const articleResult = await client.query(
    "INSERT INTO articles (...) VALUES (...) RETURNING id",
    values,
  );

  await client.query(
    "INSERT INTO article_tags (article_id, tag_id) VALUES ($1, $2)",
    [articleResult.rows[0].id, tagId],
  );

  await client.query("COMMIT");
} catch (error) {
  await client.query("ROLLBACK");
  throw error;
} finally {
  client.release();
}
```

这里的 `client` 是从连接池临时借出的一条确定连接。`BEGIN`、业务 SQL、`COMMIT` 或 `ROLLBACK` 必须都在这条连接上执行，最后再用 `client.release()` 归还连接。

不能在同一事务里连续使用不确定连接的 `pool.query()`。

---

## 什么时候需要事务

先问：

```text
这些数据库操作是否必须作为一个整体成功？
```

Mini CMS 中可能需要：

- 创建文章并保存标签关系。
- 更新文章并替换全部标签关系。
- 发布文章并记录相关状态。

单条普通查询不需要为了形式套事务。

---

## 常见误区

- 把标签数组塞进文章字符串字段，数据库无法保证标签真实存在或方便查询关系；多对多关系使用中间表。
- 建外键时要先决定删除文章或标签后，关联记录是禁止删除、保留空值还是一起删除。
- 一篇文章关联三个标签时，JOIN 可能产生三行文章数据；需要按目标聚合标签或去重，不能直接当成三篇文章。
- 事务中的 SQL 如果使用不同连接，`BEGIN` 就无法约束后面的操作；整组 SQL 必须使用同一个 client。
- 忘记在 `finally` 中 `client.release()`，连接不会归还，次数多了连接池会耗尽。
- 单条 SQL 本身已经是一个完整操作，不需要全部额外套事务；只有多步操作必须一起成功时才使用事务。

---

## 小结

```text
外键保护关系存在
中间表表达多对多
JOIN 在查询时组合关联数据
事务保证一组操作一起成功或失败
```

这一层完成后，Mini CMS 才从单表 CRUD 进入真正的关系型业务。
