# 18. 后端术语表：先知道它属于哪一层

## 运行环境和工程

| 术语 | 先怎么理解 |
|---|---|
| Node.js | 让 JavaScript 在服务器等环境运行 |
| npm | 安装包、管理依赖、执行 scripts |
| TypeScript | 给 JavaScript 增加静态类型检查 |
| module | 可以导入和导出的代码单元 |
| environment variable | 随运行环境变化的配置 |
| build | 把源码转换成可运行产物 |

## HTTP 和 API

| 术语 | 先怎么理解 |
|---|---|
| HTTP | 客户端和服务器交换请求、响应的协议 |
| request | 客户端发给服务器的信息 |
| response | 服务器返回给客户端的信息 |
| method | 请求意图，如 GET、POST、PATCH、DELETE |
| URL | 请求资源的位置 |
| header | 请求或响应的附加信息 |
| body | 请求或响应携带的主要数据 |
| status code | 用数字表示请求结果类型 |
| JSON | 常用的文本数据格式 |
| API | 软件之间约定好的调用入口 |
| contract | 请求、响应和错误结构的约定 |

## Express

| 术语 | 先怎么理解 |
|---|---|
| Express | Node.js Web 框架 |
| app | 整个 Express 应用对象 |
| route | HTTP 方法和路径对应的处理入口 |
| router | 一组相关路由 |
| handler | 真正处理一次请求的函数 |
| middleware | 请求到达 handler 前后经过的公共处理函数 |
| `req` / `request` | Express handler 收到的请求对象，用来读取 params、query、body 和 headers |
| `res` / `response` | Express handler 使用的响应对象，用来设置状态码并发送数据 |
| `next` | 让 Express 继续执行下一个中间件，或把错误交给错误处理流程 |
| controller | 把 HTTP 输入输出和业务调用连接起来 |
| service | 组织业务规则和事务 |
| repository | 集中处理数据库查询 |

## Next.js 服务端能力（只对应选读 12A）

| 术语 | 先怎么理解 |
|---|---|
| Server Component | 在服务器渲染，并且可以直接读取服务端数据的 React 组件 |
| Server Action | 由 Next.js 页面触发、在服务器执行的数据修改函数 |
| Route Handler | 用 `route.ts` 提供 GET、POST 等公开 HTTP 接口 |
| Backend for Frontend | 主要为当前前端整理数据、保护密钥和统一接口的后端层 |
| Custom Server | 放弃默认启动方式，自行控制 Next.js HTTP server 的特殊方案 |

## 数据库

| 术语 | 先怎么理解 |
|---|---|
| Docker | 用容器运行 PostgreSQL 等项目依赖 |
| container | 根据镜像启动的隔离运行实例 |
| volume | 让容器重建后仍可保留数据的存储 |
| PostgreSQL | 关系型数据库管理系统 |
| SQL | 查询和修改关系型数据的语言 |
| ORM | 用代码描述表和查询，再转换成数据库操作的工具层 |
| Prisma Schema | 使用 `schema.prisma` 定义模型、字段、约束和关系 |
| Prisma Client | 根据 Prisma Schema 生成的类型安全数据库客户端 |
| Prisma Migrate | 根据模型变化生成和执行迁移的工具 |
| Prisma Studio | 开发阶段查看和编辑数据库数据的可视化工具 |
| driver adapter | Prisma 7 连接具体数据库驱动的适配层 |
| database | 一组被数据库服务管理的数据 |
| schema | database 内进一步组织对象的命名空间 |
| table | 保存同一类结构化数据 |
| row | 表中的一条记录 |
| column | 一类字段 |
| data type | 限制一列能保存哪一类值 |
| `NULL` | 当前没有值，不等于空字符串或数字 0 |
| `NOT NULL` | 这一列必须有值 |
| `DEFAULT` | 没有提供该列时使用的默认值 |
| primary key | 稳定且唯一识别一行 |
| foreign key | 约束一张表对另一张表的引用 |
| unique constraint | 保证字段或字段组合不重复 |
| `CHECK` | 限制一列必须符合指定条件 |
| CRUD | 创建、查询、修改和删除四类基本数据操作 |
| `WHERE` | 选择符合条件的行 |
| `ORDER BY` | 指定查询结果的排序方式 |
| `LIMIT / OFFSET` | 限制返回数量并跳过前面的行 |
| `JOIN` | 只返回两边都能匹配的关联数据 |
| `LEFT JOIN` | 保留左表全部数据，即使右表没有匹配项 |
| transaction | 让一组操作一起成功或失败 |
| index | 帮助数据库更快定位数据的额外结构 |
| migration | 可追踪地修改数据库结构 |
| connection pool | 复用有限数量的数据库连接 |
| pg | PostgreSQL 的 Node.js 驱动，Prisma 7 的 pg adapter 在底层使用它 |

## 登录和安全

| 术语 | 先怎么理解 |
|---|---|
| authentication | 确认用户是谁 |
| authorization | 判断用户能做什么 |
| password hash | 不保存明文密码的单向处理结果 |
| Cookie | 浏览器按规则保存并随请求携带的小段数据 |
| HttpOnly | 阻止浏览器 JavaScript 读取 Cookie 的属性 |
| CORS | 浏览器跨来源请求的访问规则 |
| CSRF | 借用用户已登录状态伪造敏感请求的攻击 |
| SQL injection | 把恶意输入混入 SQL 结构的攻击 |

## 测试和运行

| 术语 | 先怎么理解 |
|---|---|
| unit test | 验证一个小函数或规则 |
| integration test | 验证多层代码是否正确配合 |
| end-to-end test | 从用户入口验证完整流程 |
| Vitest | JavaScript / TypeScript 测试运行工具 |
| Supertest | 对 Node HTTP 服务进行接口断言的工具 |
| health check | 判断服务是否可用的轻量接口 |
| log | 记录运行过程和错误上下文 |
| deployment | 把应用放到目标环境稳定运行 |
| backup | 为数据准备可恢复副本 |

## 小结

遇到陌生术语时，先按下面的顺序判断：

```text
它是在启动项目、处理请求、读写数据、测试还是部署时出现？
-> 它接收什么，又交出什么？
-> 它解决的是哪个具体问题？
-> 应该回看哪一章的最小例子？
```

先搞清它在当前流程中的作用，再学具体写法。
