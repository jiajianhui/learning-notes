# 01. 后端大图景：页面背后还有服务器和数据库

## 问题背景

前端负责用户看到和操作的页面，但页面不会自己永久保存文章，也不应该直接拿着数据库密码连接数据库。

一个常见 Web 产品可以先画成：

```text
浏览器
-> 前端页面
-> 后端服务器
-> 数据库
```

Mini CMS 中对应的是：

```text
浏览器
-> Next.js + Ant Design 管理后台
-> Express API
-> PostgreSQL
```

---

## 核心解释

### 1. 前端负责什么

- 展示文章列表。
- 收集表单输入。
- 显示 loading、错误和成功状态。
- 向服务器发送 HTTP 请求。

前端可以暂时保存页面状态，但不能作为长期数据来源。

### 2. 后端负责什么

- 接收请求。
- 判断参数是否合法。
- 判断用户有没有权限。
- 执行业务规则。
- 读写数据库。
- 返回明确的结果和状态码。

后端不是“没有界面的页面”，而是产品的数据和规则中心。

### 3. 数据库负责什么

- 长期保存数据。
- 用约束保护数据一致性。
- 按条件查询、排序和关联数据。
- 在事务中保证一组操作一起成功或失败。

数据库不直接处理页面，也不决定 HTTP 状态码。

---

## 一次创建文章的过程

```text
1. 用户填写标题和正文
2. Next.js 发送 POST /api/articles
3. Express 检查登录状态
4. Express 校验 title、slug、content
5. pg 执行 INSERT SQL
6. PostgreSQL 保存并返回文章
7. Express 返回 201 和 JSON
8. Next.js 显示创建成功
```

任何一步失败，都应该在对应层处理：

| 失败 | 主要属于哪层 |
|---|---|
| 表单没填标题 | 前端可以先提示，后端仍必须校验 |
| 未登录 | 后端认证层 |
| slug 重复 | 业务规则和数据库约束 |
| SQL 语法错误 | 后端执行 SQL 的代码 |
| 页面没有显示错误 | 前端状态处理 |

## 技术关系

### Next.js 是前端还是后端

Next.js 既能写页面，也能提供服务端能力。

它可以使用 Server Component、Server Action 和 Route Handler 读取数据库、修改数据或提供 HTTP API。具体使用场景和它与 Express 的区别，放在：

- [10A-Next.js 也能写后端：具体什么时候用](./10A-Nextjs也能写后端-具体什么时候用.md)

但这次为了专门学习 Express，职责固定为：

```text
Next.js
-> 管理后台前端

Express
-> 独立后端 API
```

第一轮不让 Next.js 直接访问 PostgreSQL，也不把主要接口改写成 Route Handler。

### Node.js 和 Express 是什么关系

```text
Node.js 是运行环境。
Express 是运行在 Node.js 里的 Web 框架。
```

类似地：

```text
浏览器是前端 JavaScript 的运行环境。
React 是运行在浏览器和构建环境里的 UI 工具。
```

## 常见误区

### 误区 1：后台管理页面就是后端

后台管理页面仍然是前端，只是用户通常是管理员。

### 误区 2：数据库就是后端

数据库负责长期保存和约束数据；判断谁能修改文章、应该返回什么状态码，仍然是后端代码的工作。

### 误区 3：接口返回数据就算完成

接口成功返回一次，只能说明最短流程跑通了；错误、权限、页面反馈和自动化测试仍然要补。

---

## 小结

先记住四个角色：

```text
浏览器负责发请求
Next.js 负责管理界面
Express 负责数据和业务入口
PostgreSQL 负责长期保存数据
```
