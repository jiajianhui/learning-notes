# 01. 后端大图景：页面背后还有服务器和数据库

## 问题背景

前端负责用户看到和操作的页面，但页面不会自己永久保存文章，也不应该直接拿着数据库密码连接数据库。

一个常见 Web 产品可以先画成：

```text
浏览器
-> 前端页面
-> 后端服务器
-> 数据库
```

在文章管理场景中可以对应为：

```text
浏览器
-> Next.js + Ant Design 管理后台
-> Express API
-> PostgreSQL
```

---

## 页面、后端和数据库分别负责什么

### 1. 前端负责什么

- 展示文章列表。
- 收集表单输入。
- 显示 loading、错误和成功状态。
- 向服务器发送 HTTP 请求。

前端可以暂时保存页面状态，但不能作为长期数据来源。

### 2. 后端负责什么

- 接收请求。
- 判断参数是否合法。
- 执行业务规则。
- 读写数据库。
- 返回明确的处理结果。

后端不是“没有界面的页面”，而是产品的数据和规则中心。

### 3. 数据库负责什么

- 长期保存数据。
- 用约束保护数据一致性。
- 按条件查询、排序和关联数据。

数据库不直接处理页面，也不决定接口应该怎样回应客户端。

---

## 一次创建文章的过程

```text
1. 用户填写标题和正文
2. Next.js 发送 POST /api/articles
3. Express 校验 title、slug、content
4. Express 请求 PostgreSQL 保存文章
5. PostgreSQL 保存并返回结果
6. Express 返回创建结果
7. Next.js 显示创建成功
```

任何一步失败，都应该在对应层处理：

| 失败 | 主要属于哪层 |
|---|---|
| 表单没填标题 | 前端可以先提示，后端仍必须校验 |
| slug 重复 | 业务规则和数据库约束 |
| 数据库操作失败 | 后端读写数据库的代码 |
| 页面没有显示错误 | 前端状态处理 |

## Next.js、Node.js 和 Express 是什么关系

### Next.js 是前端还是后端

Next.js 既能写页面，也能在服务器上执行代码。完成这套后端主线后，可以再通过下面的可选章节对比它与 Express 的使用场景：

- [12A-Next.js 也能写后端：具体什么时候用](./12A-Nextjs也能写后端-具体什么时候用.md)

但这次为了专门学习 Express，职责固定为：

```text
Next.js
-> 管理后台前端

Express
-> 独立后端 API
```

### Node.js 和 Express 是什么关系

```text
Node.js 是运行环境。
Express 是运行在 Node.js 里的 Web 框架。
```

类似地：

```text
浏览器是前端 JavaScript 的运行环境。
React 是运行在浏览器和构建环境里的 UI 工具。
```

## 小结

先记住四个角色：

```text
浏览器
-> 显示页面，并根据用户操作发送 HTTP 请求

Next.js
-> 组成管理页面，收集输入并显示请求结果

Express
-> 接收请求，检查输入和规则，再读写数据库

PostgreSQL
-> 长期保存文章等数据
```
