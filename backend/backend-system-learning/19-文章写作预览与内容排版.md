# 19. 文章写作、预览与内容排版

> Mini CMS 阶段 8 的第一步。完成两套后台后，用本章完善文章写作、预览和公开阅读，再进入第 20、20A 章准备上线与部署。

前面的后台能保存和发布文章，但正文只是一个文本框。现在要让它真正适合写文章：能编辑标题、列表和图片，保存后继续修改，并在发布前看到网站上的排版效果。

本章直接接入 Tiptap 富文本编辑器。Markdown 只用于理解内容表示方式，不再建设一套过渡编辑器。按下面三步完成同一套实现：

| 步骤 | 得到什么 | 先掌握什么 |
|---|---|---|
| 最小链路 | 编辑、保存、回显、公开阅读 | 编辑器 JSON 怎样经过表单、API 和数据库 |
| 正文排版与预览 | 图片、代码、表格，以及统一的文章页面 | 内容结构怎样变成阅读效果 |
| 写作体验 | 两套后台都适合写长文 | 工具栏、保存反馈、预览和离开提醒 |

先在 `admin-web-antd` 跑通，再接入 `admin-web-shadcn`。两边继续使用原来的 fetch、Axios 和同一套 Express API。

## 1. 先固定内容与页面的分工

### 1.1 我们要做出的文章效果

本章参考这些真实文章的内容组织，不推测它们使用了什么编辑器或 CMS：

- [Vercel：How our agents build on-brand pages with design.md](https://vercel.com/blog/how-our-agents-build-on-brand-pages-with-design-md)：分节长文、列表、配图与图注。
- [Raycast：Raycast for iOS](https://www.raycast.com/blog/raycast-for-ios)：产品说明、分级标题和连续的功能配图。
- [OpenAI：Introducing GPT-4.5](https://openai.com/index/introducing-gpt-4-5/)：文章头部、章节组织和图文内容。

把参考变成本项目可检查的目标：文章头部有标题、摘要、日期、标签和可选封面；正文有稳定的阅读宽度和段落节奏；图片可以使用正文宽度或宽幅；代码和表格在手机上单独横向滚动。

这是同一套文章模板。写作者选择“二级标题”“引用”“宽幅图片”等内容类型，页面负责具体字号、颜色和间距。第一版不在编辑器里开放任意字体、颜色和像素宽度，也不做参考网站里的所有互动演示。

### 1.2 Markdown 和富文本 JSON 分别保存什么

例如一段加粗文字，Markdown 可以写成：

```md
这是 **重点**。
```

Tiptap 会用对象描述“段落里面有文字，其中一段带加粗标记”：

```json
{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [
        { "type": "text", "text": "这是 " },
        { "type": "text", "text": "重点", "marks": [{ "type": "bold" }] },
        { "type": "text", "text": "。" }
      ]
    }
  ]
}
```

`doc` 是整篇正文，`paragraph` 是段落，`text` 是文字，`marks` 表示文字上的格式。写作者不需要手写 JSON；编辑器会在输入和点击工具栏时生成它。

本章把 `Article.content` 从 Prisma `String` 改为 `Json`，保存上面的对象。标题、slug、摘要、状态、发布时间和标签仍然是独立字段。JSON 是唯一正文来源，不再同时维护可编辑的 Markdown 或 HTML 副本。

```text
Tiptap 编辑内容
→ getJSON() 得到正文对象
→ 表单把对象放进 content
→ Express 校验正文结构
→ Prisma 写入 PostgreSQL JSONB
→ 详情接口返回对象
→ 编辑器回显，或 ArticleBody 渲染文章
```

这里改变的是正文 contract。前面章节先用字符串完成 CRUD 的步骤仍然成立，不需要回头重写每一章。

### 2.1 把正文能力放进一个小共享包

两套后台和个人网站将使用相同的正文规则，因此在真实 `mini-cms` 中新增：

```text
packages/article-content/
├── package.json
├── tsconfig.json
└── src/
    ├── extensions.ts      哪些内容类型可以出现
    ├── schema.ts          校验正文、定义数据类型
    ├── editor.tsx         编辑正文，属于客户端组件
    ├── renderer.tsx       只读正文，不创建编辑器
    └── article.css        编辑、预览和网站共用的样式
```

这是本章新增的代码位置，不是前面已经实现的文件。个人网站继续保留在自己的仓库中，通过安装这个包复用代码。先按文末附录准备包配置；下面每完成一步就构建、打包并更新使用它的工程。

`extensions.ts` 先只开放段落、二三级标题、加粗、列表和换行：

```ts
import StarterKit from "@tiptap/starter-kit";

export function createArticleExtensions() {
  return [
    StarterKit.configure({
      heading: { levels: [2, 3] },
      blockquote: false,
      codeBlock: false,
      code: false,
      horizontalRule: false,
      italic: false,
      link: false,
      strike: false,
      underline: false,
    }),

```

StarterKit 是一组常用扩展。没有关闭的段落、文字、列表、换行和撤销重做继续可用。文章的大标题由独立的 `title` 字段提供，所以正文从 `h2` 开始。

### 2.2 后端要检查“是不是允许的正文”

前面的 `z.string().trim().min(1)` 已经不适用。一个对象即使是合法 JSON，也可能包含不存在的节点，或者把列表项放错位置。

在共享包的 `schema.ts` 新增下面的最小完整实现：

```ts
import { getSchema, type JSONContent } from "@tiptap/core";
import { z } from "zod";
import { createArticleExtensions } from "./extensions.js";

export type ArticleDocument = JSONContent & {
  type: "doc";
  content: JSONContent[];
};

export function emptyDocument(): ArticleDocument {
  return { type: "doc", content: [{ type: "paragraph" }] };
}

const editorSchema = getSchema(createArticleExtensions());

// 允许空段落，用于新文章和编辑中的预览。
export const documentSchema = z.json().transform((value, context) => {
  try {
    if (JSON.stringify(value).length > 500_000) {
      throw new Error("正文数据过大");
    }
    const doc = editorSchema.nodeFromJSON(value);
    if (doc.type.name !== "doc") throw new Error("正文必须是文档");
    doc.check();
    doc.descendants((node) => {
      if (node.type.name === "heading" && ![2, 3].includes(node.attrs.level)) {
        throw new Error("正文只允许二级和三级标题");
      }
    });
    if (doc.textContent.length > 100_000) {
      throw new Error("正文文字不能超过 100000 个字符");
    }
    return doc.toJSON() as ArticleDocument;
  } catch (error) {
    context.addIssue({
      code: "custom",
      message: error instanceof Error ? error.message : "正文格式不正确",
    });
    return z.NEVER;
  }
});

// 保存时延续原来的规则：正文不能只有空白。
export const contentSchema = documentSchema.refine(
  (value) => editorSchema.nodeFromJSON(value).textContent.trim().length > 0,
  { message: "正文不能为空" },
);
```

`getSchema()` 从已启用的扩展得到文档规则；`nodeFromJSON()` 读取对象；`check()` 检查节点和嵌套是否合法。这里不创建编辑器，也不需要浏览器。最后返回整理后的 JSON，后端保存校验结果，不保存未经检查的原始请求体。

在 `server/src/modules/articles/article-schema.ts` 中，用共享包导出的 `contentSchema` 替换旧的字符串 Schema。创建时使用 `contentSchema`，更新时继续使用 `contentSchema.optional()`，其余字段规则保留：

```ts
import { contentSchema } from "@mini-cms/article-content/schema";
```

同时检查 `server/src/app.ts` 的 `express.json()` 请求大小限制。这里将整个 JSON 请求限制为 `1mb`，正文的文字数量和序列化长度由上面的规则继续限制：

```ts
app.use(express.json({ limit: "1mb" }));
```

不要重复注册第二个 JSON 中间件；替换现有配置。请求体超限时沿用错误中间件，返回明确的 413，而不是包装成未知的 500。

### 2.3 转换旧文章，再改变字段类型

在 `server/prisma/schema.prisma` 中只改 `Article` 的正文属性：

```prisma
content Json
```

在 `server` 执行：

```bash
npx prisma migrate dev --name article-content-json --create-only
```

先打开生成的 `migration.sql`。旧文章是普通文字，不能直接执行 `content::jsonb`：普通文字不是一个 JSON 文档。也不要接受会清空旧正文的迁移或用数据库重置来绕过这个问题。

下面是本次正文列转换的 SQL。先备份，在本地数据库副本验证后，把生成文件中对应的列类型变更替换为它；迁移文件中其他有意保留的变更另行检查。

```sql
BEGIN;

ALTER TABLE "articles" ADD COLUMN "content_rich" JSONB;

UPDATE "articles" AS article
SET "content_rich" = (
  SELECT jsonb_build_object(
    'type', 'doc',
    'content', jsonb_agg(
      CASE WHEN line = '' THEN jsonb_build_object('type', 'paragraph')
      ELSE jsonb_build_object(
        'type', 'paragraph',
        'content', jsonb_build_array(jsonb_build_object('type', 'text', 'text', line))
      ) END ORDER BY position
    )
  )
  FROM regexp_split_to_table(article."content", E'\r?\n')
       WITH ORDINALITY AS lines(line, position)
);

ALTER TABLE "articles" ALTER COLUMN "content_rich" SET NOT NULL;
ALTER TABLE "articles" DROP COLUMN "content";
ALTER TABLE "articles" RENAME COLUMN "content_rich" TO "content";

COMMIT;
```

它把旧正文的每一行变成一个段落，空行保留为空段落。这里转换的是此前练习产生的纯文本，不解析 Markdown，也不编译旧网站的 `.mdx` 文件。已有 MDX 文章里的图片组等组件需要逐篇转换成新支持的内容，不能直接粘贴到 JSON 字段。

检查 SQL 后执行：

```bash
npx prisma migrate dev
npx prisma generate
```

同步修改这些真正受影响的位置：

| 位置 | 本次变化 |
|---|---|
| `article-schema.ts` | `content` 接受文档对象；更新字段仍可省略 |
| `article-repository.ts` | 接收校验后的对象并交给 Prisma，不对正文调用 `trim()` |
| 两个后台的详情、创建、更新类型 | `content: string` 改为 `ArticleDocument` |
| 两个后台的表单默认值 | `content: ""` 改为 `emptyDocument()` |
| 种子数据、18A 的文章测试数据 | 正文改成有效文档对象 |
| 前面手写的“未修改”比较 | 正文不能再用字符串或对象引用的 `===` 比较 |

Prisma 返回的 `JsonValue` 不保证一定符合文章结构。组装详情响应时，用 `documentSchema.parse(article.content)` 得到 `ArticleDocument`。如果写入处需要 Prisma 的 `InputJsonObject` 类型，只在通过 `contentSchema` 校验后进行类型衔接；类型断言本身不能替代校验。

本次 contract 变化需要后端、两套后台和个人网站一起升级。本章在上线前完成；如果项目已经运行在线上，先在本地副本做完，安排统一升级窗口，不能让旧文本框客户端继续写入新的 JSON 接口。

**验证：** 旧文章数量不变，中文、引号和换行保留；向 API 提交有效文档能保存，提交字符串、未知节点或空白正文得到 422；只修改标题的 PATCH 仍然有效。

### 2.4 让编辑器把值交给现有表单

共享包的 `editor.tsx` 是一个完整的最小编辑器。先做少量按钮，后面继续在这里增加能力：

```tsx
"use client";

import { useEffect } from "react";
import { EditorContent, useEditor, useEditorState } from "@tiptap/react";
import { createArticleExtensions } from "./extensions.js";
import { emptyDocument, type ArticleDocument } from "./schema.js";

type ArticleEditorProps = {
  value?: ArticleDocument;
  onChange?: (value: ArticleDocument) => void;
  onBlur?: () => void;
  disabled?: boolean;
};

export function ArticleEditor({
  value, onChange, onBlur, disabled = false,
}: ArticleEditorProps) {
  const editor = useEditor({
    extensions: createArticleExtensions(),
    content: value ?? emptyDocument(),
    immediatelyRender: false,
    editorProps: {
      attributes: { class: "article-body", "aria-label": "文章正文" },
    },
    onUpdate: ({ editor }) => onChange?.(editor.getJSON() as ArticleDocument),
    onBlur: () => onBlur?.(),
  });

  const state = useEditorState({
    editor,
    selector: ({ editor }) => ({
      bold: editor?.isActive("bold") ?? false,
      heading: editor?.isActive("heading", { level: 2 }) ?? false,
      list: editor?.isActive("bulletList") ?? false,
    }),
  });

  useEffect(() => {
    if (!editor) return;
    const nextValue = value ?? emptyDocument();
    if (JSON.stringify(editor.getJSON()) !== JSON.stringify(nextValue)) {
      editor.commands.setContent(nextValue, {
        emitUpdate: false,
        errorOnInvalidContent: true,
      });
    }
  }, [editor, value]);

  useEffect(() => {
    editor?.setEditable(!disabled);
  }, [editor, disabled]);

  if (!editor) return <p>正在加载编辑器…</p>;

  return (
    <section className="article-editor">
      <div role="group" aria-label="正文格式">
        <button type="button" disabled={disabled} aria-pressed={state?.heading}
          onClick={() => editor.chain().focus().toggleHeading({ level: 2 }).run()}>
          二级标题
        </button>
        <button type="button" disabled={disabled} aria-pressed={state?.bold}
          onClick={() => editor.chain().focus().toggleBold().run()}>
          加粗
        </button>
        <button type="button" disabled={disabled} aria-pressed={state?.list}
          onClick={() => editor.chain().focus().toggleBulletList().run()}>
          无序列表
        </button>
        <button type="button" disabled={disabled}
          onClick={() => editor.chain().focus().undo().run()}>撤销</button>
        <button type="button" disabled={disabled}
          onClick={() => editor.chain().focus().redo().run()}>重做</button>
      </div>
      <EditorContent editor={editor} />
    </section>
  );
}
```

先记住这里的三个方向：

- 用户输入时，`onUpdate` 通过 `onChange` 把 JSON 交给表单。编辑器不自己发送保存请求。
- 详情请求、表单重置等外部变化通过 `value` 回到编辑器。只有内容不同时才调用 `setContent`，避免每次输入都重设光标。
- `emitUpdate: false` 阻止外部回填再次触发表单更新。Next.js 中的 `immediatelyRender: false` 用来避免服务端初始化编辑器带来的渲染不一致。

`useEditorState` 订阅编辑器状态，让“加粗”等按钮跟随光标位置更新。所有格式按钮都使用 `type="button"`，避免误提交文章表单。

在 Ant Design 文章表单中，把正文的 `ProFormTextArea` 换成以下局部片段，保留外层现有的 ProForm/DrawerForm：

```tsx
import { Form } from "antd";
import { ArticleEditor } from "@mini-cms/article-content/editor";
import { contentSchema } from "@mini-cms/article-content/schema";

// 放在已有表单中，不新建第二层 Form。
<Form.Item
  name="content"
  label="正文"
  rules={[{
    validator: async (_, value) => {
      const result = contentSchema.safeParse(value);
      if (!result.success) throw new Error(result.error.issues[0].message);
    },
  }]}
>
  <ArticleEditor />
</Form.Item>
```

Form.Item 会传入 `value` 和 `onChange`。保存函数仍然提交完整表单值；fetch 仍对整个请求对象 `JSON.stringify(values)`，不要单独把 `content` 再序列化成字符串。

编辑已有文章时，先请求详情再挂载表单，并按文章 id 设置稳定的 `key`。切换文章要重建对应的编辑器，防止撤销历史串到另一篇；不要用每次都会变化的随机 key。已有的失败提示和保留输入逻辑继续使用。

正文的“是否变化”可以先比较 `JSON.stringify(values.content)` 与加载时的正文快照。它比较内容，不比较对象引用；加载和保存成功后再更新快照，回填时不当作用户编辑。

**验证：** 新建一篇含二级标题、加粗和列表的文章，保存、关闭、重新打开；检查格式与原来相同。再打开另一篇，确认内容和撤销历史不会串篇。制造保存失败，正文仍保留。

## 3. 让个人网站读到真正的文章

### 3.1 公开接口只读取已发布内容

沿用第 06、15、17 章的路由、查询和认证能力，增加：

```text
GET /api/public/articles
GET /api/public/articles/:slug
```

公开列表只选择标题、slug、摘要、发布时间、标签等列表字段，不携带完整正文。详情按 slug 查询，返回经过 `documentSchema` 检查的 `content` 对象。

后端固定限制 `status = published` 且 `publishedAt` 不为 `null`，按发布时间从新到旧排序。草稿、撤回内容和不存在的 slug 对公开详情都返回 404。管理接口继续受登录保护，不用公开路由替代后台读写接口。

如果需要文章封面，在本章增加可为空的 `coverImageUrl`，并同步 Prisma 迁移、两套表单、请求校验和公开响应：

```prisma
coverImageUrl String? @map("cover_image_url")
```

第一版的封面和正文图片都输入可访问的 HTTPS 图片地址。图片上传与云存储没有在此前课程实现，本章不把粘贴本地文件或上传按钮当作已经可用的能力。

**验证：** 在 Apifox 中读取已发布文章；请求草稿和撤回文章得到 404；列表响应没有正文；管理接口仍然需要登录。

### 3.2 用同一个 ArticleBody 渲染 JSON

在共享包的 `renderer.tsx` 新增：

```tsx
import { renderToReactElement } from "@tiptap/static-renderer/pm/react";
import { createArticleExtensions } from "./extensions.js";
import { documentSchema } from "./schema.js";

export function ArticleBody({ content }: { content: unknown }) {
  const document = documentSchema.parse(content);
  return (
    <div className="article-body">
      {renderToReactElement({
        extensions: createArticleExtensions(),
        content: document,
      })}
    </div>
  );
}
```

Static Renderer 根据扩展把 JSON 渲染成 React 元素，不创建可编辑实例。公开页面只导入这个入口，不导入 `editor.tsx`；也不需要把 JSON 转成 HTML 再交给 `dangerouslySetInnerHTML`。

在个人网站已有详情页中，用公开 API 替换写死的数据来源，再把 `article.content` 传给 `ArticleBody`。公开详情的 404 交给网站的不存在页面处理；格式异常属于数据错误，记录并显示错误状态，不能静默丢掉未知节点后继续展示。

此时先验证结构：标题确实成为 `h2`，加粗成为 `strong`，列表成为 `ul/li`。具体视觉在下一节集中完成。

**验证：** 后台发布后，个人网站的列表和详情能读取真实内容；撤回后两处都不可读。第一轮请求显式使用 `cache: "no-store"`，避免旧缓存让撤回验证失真，缓存优化留到之后。

## 4. 补齐内容类型，并完成统一排版

### 4.1 增加一种内容，要同时支持编辑、保存和展示

在共享包目录安装图片和表格扩展，版本与前面保持一致：

```bash
npm install --save-exact @tiptap/extension-image@3.32.0 @tiptap/extension-table@3.32.0
```

在 `extensions.ts` 中取消 StarterKit 对 `blockquote`、`codeBlock`、`code` 的禁用，把 `link: false` 改为 `link: { openOnClick: false }`。再加入图片扩展和 `TableKit`：

```ts
import { TableKit } from "@tiptap/extension-table";
import { ArticleImage } from "./image.js";

// 加入 createArticleExtensions() 返回的数组，保留原来的 StarterKit。
ArticleImage,
TableKit.configure({ table: { resizable: false, renderWrapper: true } }),
```

上面是数组中的新增片段，不是整个文件。Tiptap 3 的 StarterKit 已包含 Link，不要再重复注册同名扩展。

图片需要图注和宽度选择，因此新增 `src/image.ts`。它仍叫 `image` 节点，复用图片扩展的选中和插入能力：

```ts
import Image from "@tiptap/extension-image";

export const ArticleImage = Image.extend({
  addAttributes() {
    return {
      ...this.parent?.(),
      alt: { default: "" },
      caption: { default: "" },
      layout: { default: "normal" },
    };
  },
  renderHTML({ node }) {
    return [
      "figure",
      { "data-layout": node.attrs.layout },
      ["img", { src: node.attrs.src, alt: node.attrs.alt ?? "", loading: "lazy" }],
      ["figcaption", {}, node.attrs.caption],
    ];
  },
}).configure({ allowBase64: false });
```

图片属性面板填写 URL、替代文字、图注和“正文宽度/宽幅”。插入时通过 `insertContent` 传入完整对象：

```ts
// 放在图片属性面板的确认事件中；四个值来自面板表单。
editor.chain().focus().insertContent({
  type: "image",
  attrs: { src, alt, caption, layout },
}).run();
```

选中现有图片后，用 `updateAttributes("image", { src, alt, caption, layout })` 修改。图注由面板编辑，不假设图中已经出现可直接输入的富文本框。复制外部 HTML 图片时只承诺保留可识别的图片属性；跨后台完整回显依赖保存的 JSON。

同时扩展 `schema.ts`：在 `doc.check()` 后的 `doc.descendants()` 回调中，保留标题校验并增加图片与链接检查。可以先在同文件定义：

```ts
export function isWebUrl(value: unknown, protocols = ["https:"]) {
  if (typeof value !== "string") return false;
  try {
    return protocols.includes(new URL(value).protocol);
  } catch {
    return false;
  }
}
```

再在遍历每个节点时检查：

```ts
if (node.type.name === "image") {
  if (!isWebUrl(node.attrs.src)) throw new Error("图片需要有效的 HTTPS 地址");
  if (typeof node.attrs.alt !== "string" || typeof node.attrs.caption !== "string") {
    throw new Error("图片说明格式不正确");
  }
  if (!["normal", "wide"].includes(node.attrs.layout)) {
    throw new Error("图片宽度选项不正确");
  }
}
for (const mark of node.marks) {
  if (mark.type.name === "link" && !isWebUrl(mark.attrs.href, ["https:", "http:", "mailto:"])) {
    throw new Error("链接地址不支持");
  }
}
```

前后端使用同一校验入口，图片和链接面板从共享包的 `/schema` 入口导入 `isWebUrl`，确认属性有效后才插入正文；封面也使用相同的 HTTPS 地址规则。不要因为 JSON 没有直接写 HTML，就允许任意链接协议。保存仍要求正文含有非空文字，纯图片文章暂不纳入本轮。

按相同方式给工具栏增加引用、链接、代码块和表格。下面是接入时使用的命令，不是要求全部写在一个事件里：

| 用户操作 | 编辑器调用 |
|---|---|
| 三级标题、恢复普通段落 | `toggleHeading({ level: 3 })`、`setParagraph()` |
| 有序列表 | `toggleOrderedList()` |
| 引用 | `toggleBlockquote()` |
| 代码块 | `toggleCodeBlock()` |
| 添加、移除链接 | `extendMarkRange("link").setLink({ href })`、`unsetLink()` |
| 插入表格 | `insertTable({ rows: 3, cols: 3, withHeaderRow: true })` |
| 调整表格 | `addRowAfter()`、`addColumnAfter()`、`deleteRow()`、`deleteColumn()`、`deleteTable()` |

这些命令放在 `editor.chain().focus()...run()` 中。链接或图片面板打开前记录编辑位置，确认时恢复选区再执行命令；同时验证取消面板不会改变正文。代码高亮可以在基本代码块稳定后接入，不影响本节的保存和阅读链路。

**验证：** 每新增一种内容，就走一遍“插入 → 保存 → 重新打开 → 网站显示”。额外尝试未知节点和不支持的 URL 协议，API 应拒绝。扩展变化后重新构建共享包，同时更新所有使用它的工程。

### 4.3 预览必须读取当前表单值

在共享包的 `renderer.tsx` 中继续增加 `ArticlePage`，让后台和网站连文章头部也共用：

```tsx
export type ArticlePageProps = {
  title: string;
  summary?: string | null;
  publishedAt?: string | null;
  tagNames: string[];
  coverImageUrl?: string | null;
  content: unknown;
};

export function ArticlePage(props: ArticlePageProps) {
  const date = props.publishedAt
    ? new Intl.DateTimeFormat("zh-CN", { timeZone: "Asia/Shanghai" })
        .format(new Date(props.publishedAt))
    : "尚未发布";

  return (
    <article className="article-page">
      <header className="article-header">
        <h1>{props.title || "未命名文章"}</h1>
        {props.summary && <p className="article-summary">{props.summary}</p>}
        <p className="article-meta">{date} · {props.tagNames.join(" / ")}</p>
        {props.coverImageUrl && <img className="article-cover" src={props.coverImageUrl} alt="" />}
      </header>
      <ArticleBody content={props.content} />
    </article>
  );
}
```

后台从表单中取标题、摘要、封面、标签和正文，映射成这些属性。Ant Design 使用同一表单实例的 `Form.useWatch`；shadcn/ui 使用 React Hook Form 的 `useWatch`。不要只读 `getFieldsValue()` 却没有订阅变化，也不要重新请求数据库里的旧正文来预览。

编辑与预览用标签页切换；切换时保留表单和编辑器实例，可以用 `hidden` 隐藏编辑区域。预览渲染当前表单快照，即使还没保存也能看。窄屏、桌面按钮分别给预览外层设置例如 `390px`、`1040px` 的最大宽度。

个人网站也使用 `ArticlePage`，并提供同样的字体和 CSS。最终一致性来自同一份数据、扩展、组件、样式和相同的可用宽度，不能只凭“都装了 Tiptap”判断。

预览不调用发布接口，不改变文章状态。尚未发布时显示“尚未发布”，不能伪造发布时间。第一版在后台本地预览，不新增可被游客访问的草稿地址。

**验证：** 修改一篇尚未保存的文章，预览立刻反映新内容；返回编辑时光标、撤销记录和输入仍在。保存并发布后，在相同宽度下比较后台预览与网站；标题、正文、图片宽度、图注和代码样式一致。

## 5. 接到 shadcn/ui，并打磨写作体验

### 5.1 第二套后台只改变表单接法

在 `admin-web-shadcn/features/articles/article-form-schema.ts` 中，把旧的正文字符串 Schema 换为共享 `contentSchema`，默认值换为 `emptyDocument()`。继续通过 `z.infer` 推导表单值，不再单独手写一个 `content: string`。

共享 Schema 的输入是待校验 JSON，输出才是 `ArticleDocument`。因此在第 28 章原有 `useForm` 调用中，明确输入与输出类型；选项继续保留原来的 resolver 和默认值：

```ts
useForm<
  z.input<typeof articleFormSchema>,
  unknown,
  z.output<typeof articleFormSchema>
>
```

这是原有调用的类型参数，不是一个新的表单实例。提交回调使用 `z.output` 对应的表单值类型。

正文 Controller 的 `render` 改为下面的局部片段；保留原来的 Field、标签和错误展示，并从共享包导入 `documentSchema`：

```tsx
<ArticleEditor
  value={documentSchema.parse(field.value)}
  onChange={field.onChange}
  onBlur={field.onBlur}
  disabled={form.formState.isSubmitting}
/>
```

类型导入、详情回填和提交数据同步使用 `ArticleDocument`。Axios 仍然把完整表单对象放进 `data`，不单独序列化正文。

`documentSchema.parse(field.value)` 把待校验的字段值转换为文档。新建表单必须提供 `emptyDocument()`，详情回填前也已检查正文结构，所以这里不会把 `undefined` 当作初始正文。业务上的“正文不能为空”仍在提交时由 `contentSchema` 检查。

保存成功时用服务端返回的数据更新表单和已保存快照；保存失败不执行 `reset()`。详情加载完成后再挂载带文章 id 的表单，保持与 Ant Design 相同的切篇规则。

**验证：** 在 Ant Design 后台保存带图片和表格的文章，在 shadcn/ui 后台编辑，再回到前者打开。格式、正文和元信息相同，没有某一边不认识而丢掉的内容。

### 5.2 把长文编辑从抽屉移到独立页面

最小链路稳定后，文章新建、编辑改用：

```text
/admin/articles/new
/admin/articles/[id]/edit
```

复用已有表单、详情请求和保存函数。Ant Design 将文章的 DrawerForm 换为页面内 ProForm，提交成功后的留页或跳转由页面显式处理，不再依赖 DrawerForm 返回 `true` 关闭抽屉。标签管理仍沿用原来的简单弹窗。

页面提供足够宽的写作区域，标题和正文作为主内容，slug、标签、状态放在次要区域。不要把正文挤在窄抽屉里，也不要让两个后台各实现一套编辑器。

第一版按下面的可观察行为验收：

| 体验 | 应该发生什么 |
|---|---|
| 格式工具栏 | 能恢复普通段落，按钮状态随选区变化；链接和图片用表单面板填写 |
| 中文输入和快捷键 | 输入法选字不中断；加粗、撤销、重做可用；格式按钮不触发提交 |
| 保存反馈 | 显示保存中、保存成功或失败；提交期间不重复请求 |
| 输入保护 | 失败保留正文；只有保存成功才更新“已保存”快照 |
| 离开提醒 | 有未保存变化时，站内离开先确认；刷新或关闭页面注册 `beforeunload` |
| 预览 | 不必保存即可查看完整文章，切换回来可以继续编辑 |

`beforeunload` 只覆盖刷新、关闭等浏览器离开行为，不能代替站内导航处理。后台的返回按钮、菜单和取消操作统一经过离开检查；浏览器后退也要实际验证。如果路由方案无法完整拦截后退，增加按文章 id 区分的本地草稿恢复，并明确提示恢复来源。

第一版保留明确的“保存”操作。不要直接把每次输入都自动提交到现有更新接口：对已发布文章这样做可能立即改变公开正文。自动保存和“已发布版本之外的修改草稿”需要单独定义版本规则，不作为本章前置任务。

- 有效正文保存后往返一致；仅更新标题不覆盖正文。

## 附录：共享包怎样供几个项目使用

这一节只解决“同一份正文代码怎样被几个项目使用”。本轮不引入 monorepo 构建工具，也不要求把个人网站搬进 Mini CMS。

在 `mini-cms/packages/article-content/package.json` 写入以下基础配置：

```json
{
  "name": "@mini-cms/article-content",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "files": ["dist", "src/article.css"],
  "exports": {
    "./schema": { "types": "./dist/schema.d.ts", "default": "./dist/schema.js" },
    "./editor": { "types": "./dist/editor.d.ts", "default": "./dist/editor.js" },
    "./renderer": { "types": "./dist/renderer.d.ts", "default": "./dist/renderer.js" },
    "./styles.css": "./src/article.css"
  },
  "scripts": { "build": "tsc -p tsconfig.json" },
  "peerDependencies": { "react": "^19.0.0", "react-dom": "^19.0.0" }
}
```

在这个目录安装依赖，由 npm 把实际版本写进 `package.json` 和锁文件：

```bash
npm install --save-exact @tiptap/core@3.32.0 @tiptap/pm@3.32.0 @tiptap/react@3.32.0 @tiptap/starter-kit@3.32.0 @tiptap/static-renderer@3.32.0 zod@4
npm install -D typescript@5 @types/react@19 @types/react-dom@19
```

第 4 节再安装图片和表格扩展。本章示例按 Tiptap 3.32.0 校对；后续升级时一起更新所有 Tiptap 包并重测。StarterKit 中的 Link、`setContent` 的选项对象等写法不要混用旧版教程。

新增 `tsconfig.json`：

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "jsx": "react-jsx",
    "strict": true,
    "declaration": true,
    "rootDir": "src",
    "outDir": "dist",
    "skipLibCheck": true
  },
  "include": ["src"]
}
```

本章包内相对导入使用 `.js` 后缀，TypeScript 会对应到源码并输出可被 Node.js 加载的 ESM。`tsc` 保留 `editor.tsx` 顶部的 `"use client"`，不要用一个带客户端指令的总入口把只读渲染器和校验代码一起导出。

源文件准备好后在包目录运行：

```bash
npm run build
npm pack
```

将生成的 `mini-cms-article-content-0.1.0.tgz` 复制到每个使用方自己的 `vendor/`：`server`、两个后台，以及个人网站。在各工程根目录运行：

```bash
npm install ./vendor/mini-cms-article-content-0.1.0.tgz
```

这样 `server` 只导入 `/schema`，后台导入 `/editor`、`/renderer` 和样式，个人网站导入 `/renderer` 和样式。归档、使用方的 `package.json` 与锁文件一起纳入版本管理；编译产物 `dist/` 和 `node_modules/` 可以忽略。

修改共享源码后提升包版本，重新构建、打包，并在使用方显式安装新的归档。不要用相同版本名覆盖归档后期待依赖自动更新。开发初期多一次打包动作，换来几个独立项目和 Docker 构建都使用相同的确定版本。

第 20A 章的 Dockerfile 会在 `npm ci` 前复制 `vendor/`。否则本地能安装，容器里仍会因找不到归档而失败。
