# 12. Express 项目结构：拆分启动、路由和 404 处理

> Mini CMS 阶段 3（第二部分）：第 11 章已经完成请求校验和统一错误处理。本章只调整文件位置，不增加新功能。

第 11 章结束后，`app.ts` 中既有路由和中间件，也有 `app.listen()`。本章拆出三处：

```text
app.listen() -> server.ts
文章路由   -> article-router.ts
404 处理   -> not-found.ts
```

`app.ts` 继续注册路由和中间件。Schema、Repository 和错误中间件保持不动；当前不创建 Controller 和 Service。

---

## 1. 把 `app.listen()` 移到 `server.ts`

`app.ts` 负责组装应用，`server.ts` 负责真正启动应用。先在 `src/app.ts` 中把：

```ts
const app = express();
```

改为：

```ts
export const app = express();
```

然后删除 `app.ts` 底部的：

```ts
app.listen(3001, () => {
  console.log("Server is running at http://localhost:3001");
});
```

其他代码先不要移动。新建 `src/server.ts`：

```ts
import "dotenv/config";

import { app } from "./app";

const port = Number(process.env.PORT ?? 3001);

app.listen(port, () => {
  console.log(`Server is running at http://localhost:${port}`);
});
```

修改 `package.json` 的开发命令：

```json
{
  "scripts": {
    "dev": "tsx watch src/server.ts"
  }
}
```

运行类型检查并重新启动服务器：

```bash
npx tsc --noEmit
npm run dev
```

确认服务器仍然可以启动，再继续拆文章路由。

---

## 2. 把文章路由移到 `article-router.ts`

Router 是一组可以挂载到 Express app 上的路由。这里把文章接口整体移走，路由内部原有的校验、Repository 调用和响应暂时不再细拆。

新建：

```text
src/modules/articles/article-router.ts
```

写入：

```ts
import { Router } from "express";

import { AppError } from "../../errors/app-error";
import {
  createArticle,
  deleteArticle,
  getArticleById,
  getArticles,
  updateArticle,
} from "./article-repository";
import {
  articleIdParamsSchema,
  createArticleSchema,
  updateArticleSchema,
} from "./article-schema";

export const articleRouter = Router();

articleRouter.get("/health", (_request, response) => {
  response.json({
    articleService: "server is running",
  });
});

articleRouter.get("/", async (_request, response) => {
  const articles = await getArticles();

  response.json({ data: articles });
});

articleRouter.get("/:id", async (request, response) => {
  const { id } = articleIdParamsSchema.parse(request.params);
  const article = await getArticleById(id);

  if (!article) {
    throw new AppError(
      404,
      "ARTICLE_NOT_FOUND",
      "文章不存在",
    );
  }

  response.json({ data: article });
});

articleRouter.post("/", async (request, response) => {
  const input = createArticleSchema.parse(request.body);
  const article = await createArticle(input);

  response.status(201).json({ data: article });
});

articleRouter.patch("/:id", async (request, response) => {
  const { id } = articleIdParamsSchema.parse(request.params);
  const input = updateArticleSchema.parse(request.body);
  const article = await updateArticle(id, input);

  response.json({ data: article });
});

articleRouter.delete("/:id", async (request, response) => {
  const { id } = articleIdParamsSchema.parse(request.params);
  const article = await deleteArticle(id);

  response.json({ data: article });
});
```

文章健康检查和 CRUD 现在都由 `articleRouter` 管理。`/health` 要写在 `/:id` 前面，避免被当成文章 ID。

## 3. 在 `app.ts` 中注册文章 Router

文章路由移走后，删除 `app.ts` 中不再使用的 Article Schema、Repository 和 `AppError` 导入，再导入 Router：

```ts
import { articleRouter } from "./modules/articles/article-router";
```

用下面这行注册文章 Router：

```ts
app.use("/api/articles", articleRouter);
```

Express 会把挂载前缀和 Router 中的相对路径拼起来：

| `app.ts` 中的前缀 | Router 中的路径 | 实际接口 |
|---|---|---|
| `/api/articles` | `/health` | `/api/articles/health` |
| `/api/articles` | `/` | `/api/articles` |
| `/api/articles` | `/:id` | `/api/articles/:id` |

不要在 Router 中再写一次 `/articles`，否则路径会变成 `/api/articles/articles`。

## 4. 把 404 处理移到 `not-found.ts`

新建 `src/middleware/not-found.ts`：

```ts
import type { RequestHandler } from "express";

export const notFound: RequestHandler = (
  _request,
  response,
) => {
  response.status(404).json({
    error: {
      code: "ROUTE_NOT_FOUND",
      message: "接口不存在",
    },
  });
};
```

`RequestHandler` 是 Express 普通请求处理函数的类型，用来检查函数是否符合 `(request, response, next)` 的基本结构。路由处理函数和中间件都可以使用它，具体角色取决于注册位置。`import type` 表示它只供 TypeScript 检查，编译后不会保留这个导入。

这里的 `_request` 没有被使用，所以用下划线开头。`notFound` 直接返回 404 响应，不需要调用 `next()`。

## 5. 整理后的 `app.ts`

`src/app.ts` 最终保留：

```ts
import express from "express";

import { errorHandler } from "./middleware/error-handler";
import { notFound } from "./middleware/not-found";
import { articleRouter } from "./modules/articles/article-router";

export const app = express();

app.use(express.json());

app.use("/api/articles", articleRouter);

app.use(notFound);
app.use(errorHandler);
```

`notFound` 必须放在业务路由之后，`errorHandler` 必须放在最后。

整理后的目录是：

```text
src/
├── app.ts
├── server.ts
├── db/
│   └── client.ts
├── errors/
│   └── app-error.ts
├── middleware/
│   ├── not-found.ts
│   └── error-handler.ts
└── modules/
    └── articles/
        ├── article-router.ts
        ├── article-schema.ts
        └── article-repository.ts
```

## 6. 检查整理结果

先运行：

```bash
npx tsc --noEmit
```

再用 Apifox 检查：

| 场景 | 预期结果 |
|---|---|
| `GET /api/articles/health` | `200` |
| 查询文章列表 | `200` |
| 创建合法文章 | `201` |
| 创建空标题文章 | `422 VALIDATION_ERROR` |
| 创建重复 slug | `409 SLUG_CONFLICT` |
| 查询不存在的文章 | `404 ARTICLE_NOT_FOUND` |
| 请求不存在的接口 | `404 ROUTE_NOT_FOUND` |

如果文章接口全部变成 404，先检查 `app.use()` 的前缀和 Router 中的相对路径有没有重复或缺失。

## 7. 当前为什么不拆 Controller 和 Service

现在的文章 Router 虽然包含路由处理代码，但每个接口都只有三步：

```text
校验输入
-> 调用 Repository
-> 返回响应
```

对当前 Mini CMS 来说，这条流程仍然容易阅读。此时增加 Controller 只会把同一段代码移动到另一个文件，请求链却多跳一次。

以后出现下面情况时，再继续拆：

- Router 中的处理函数明显变长，HTTP 输入和响应很难快速找到时，再提取 Controller。
- 发布文章需要组合状态、发布时间、标签和事务时，再增加 Service 表达业务规则。

不要根据目录模板提前创建空层。
