# 16B. 用 Ant Design 完善后台 UI

第 16 章已经跑通文章与标签的交互，16A 梳理了前后端数据流。现在回到页面：功能可用之后，怎样用普通 Ant Design 组件做出协调、完整的管理后台？

本章先讲还原页面时需要的几个判断，再由你结合目标页面自主实现。可以继续向 AI 提问；把实现中的关键选择记录下来，日后就有内容可回看。

## 1. 先确定要还原什么

以 [Ant Design Pro 查询表格演示](https://preview.pro.ant.design/list/table-list) 为视觉参考，完善现有 `admin-web-antd`：

- 顶栏和左侧导航固定，滚动时仍能找到导航与操作入口。
- 顶栏有半透明背景和背景模糊，内容区与导航有清楚的层次。
- 页面标题、筛选区、表格工具栏与数据表格排列协调。
- 文章页、标签页和编辑抽屉使用统一的颜色、间距与控件尺寸。

保留 Mini CMS 的文章、标签和原有操作，不必复制演示里的业务字段与全部按钮。先保存当前页面截图，后面用同一窗口宽度比较效果。

## 2. 固定与滚动：Layout 和 CSS 各负责什么

当前 `app/admin/layout.tsx` 用 Header、Sider、Content 分出了顶栏、导航和内容区。**Layout 提供区域结构，固定位置与滚动范围仍要通过 CSS 决定。** 只给外层设置 `h-screen`，不会自动固定顶栏和侧栏。

先决定“谁滚动”。本章建议让页面内容随浏览器滚动，顶栏与侧栏固定在视口中：

| 区域 | 布局要点 |
|---|---|
| 顶栏 | `position: fixed`，贴住顶部，明确高度和层级 |
| 左侧导航 | 固定在顶栏下方，明确宽度；菜单超高时自身滚动 |
| 内容区 | 为顶栏高度和侧栏宽度留出空间，避免被遮挡 |

`fixed` 元素不再占据原来的文档空间，因此内容区需要补上对应偏移。收起侧栏时，侧栏宽度与内容偏移也要一起变化。不要同时给外层页面和 Content 都加固定高度与纵向滚动，造成两条滚动条。

### 顶栏的模糊为什么可能看不出来

下面是顶栏局部样式示意，定位、尺寸和层级仍按上面的布局确定：

```css
.admin-header {
  background: rgb(255 255 255 / 80%);
  backdrop-filter: blur(12px);
  border-bottom: 1px solid rgb(5 5 5 / 6%);
}
```

`backdrop-filter` 模糊的是顶栏背后的内容。背景完全不透明时看不到它；背后只有纯色时，效果也不明显。滚动时让内容从固定顶栏下方经过，才能观察到变化。这里的透明度与模糊半径只是起点，可以对照目标调整。

## 3. 统一风格：主题配置与局部样式怎样分工

项目已有 `app/components/antd-provider.tsx`，其中的 ConfigProvider 配置了主色、背景和圆角。继续从这里统一风格，避免每个页面分别改一遍。

Ant Design 把这些可复用的设计值称为 **Token**。可以按影响范围判断放在哪里：

| 想调整什么 | 放在哪里 |
|---|---|
| 全站主色、基础圆角、文字颜色 | `theme.token` |
| 某类组件的默认外观，例如 Layout 顶栏背景 | `theme.components` |
| 顶栏固定、背景模糊、某个筛选区的排列 | 对应区域的 CSS 或 Tailwind 类 |

例如，现有 Provider 的 `theme.components.Layout` 中配置了白色 `headerBg`。要让顶栏半透明，可以将它改为 `"rgba(255, 255, 255, 0.8)"`，再用局部样式增加 `backdrop-filter`；不要让主题与局部样式各自维护一套不同的背景值。

优先查组件属性和主题配置能否表达需要的外观，再补局部样式。修改全局 Token 后，同时查看文章页、标签页和抽屉，确认影响范围符合预期。

## 4. 组件组合：为什么放上 Table 还不像完整后台

Table 解决数据怎样按行列展示；页面的标题、筛选、操作区和留白，需要围绕它组织。

先把文章列表看成四个区域：

```text
页面标题与简短说明
筛选区：标题、状态、标签、查询与重置
表格工具栏：列表标题、新建文章
Table 与分页
```

筛选区可用 Form 组织字段，区域容器可用 Card，按钮与控件排列可用 Flex 或 Space。先看区域是否必要，再选择组件；不必给每一层都套一张 Card。

### 用间距表达关系

同组筛选控件靠近，筛选区与结果区之间留出更大的间距；主标题、说明文字和操作按钮各有层级。可以先统一页面边距、区域间距、控件间距三组值，再观察效果，避免每个元素随手写一个数。

新建按钮作为主要操作，编辑与删除留在行内；长标题、标签换行和列宽也要一起观察。标签页没有文章页的筛选分页需求，沿用视觉规则即可，不必补出不存在的功能。

## 5. 状态反馈：页面不只有“有数据”这一种样子

调整布局时，继续使用第 16 章已有的状态，让反馈出现在对应区域：

| 场景 | 用户应看到什么 |
|---|---|
| 首次获取列表、切换筛选或翻页 | 表格显示 `listLoading` 对应的加载状态 |
| 请求成功但没有数据 | Table 的空数据文案，例如 `locale={{ emptyText: "暂无标签" }}` |
| 获取列表失败 | 列表区域显示 `listError`，不要只呈现“暂无数据” |
| 获取文章详情 | 抽屉内显示 `detailLoading` 或 `detailError` 对应的反馈 |
| 保存表单 | 提交按钮显示 `submitting`；保存失败在表单内显示 `submitError`，保留输入 |

标签编辑直接使用当前行数据，不需要为了统一外观增加详情请求。文章与标签抽屉可以统一标题、字段间距和按钮位置，继续保留各自的数据流程。

完成外观调整后，用慢速网络、空查询结果和重复 slug 各看一次页面。这样才能确认新布局也容得下加载与错误提示。

## 6. 自主还原，并留下自己的实现记录

按照“后台布局 → 文章列表 → 标签列表与抽屉”的顺序完成。每次向 AI 提问时，提供当前截图、目标截图和相关代码，集中解决一个差异，例如：

> 我正在用普通 Ant Design 完善 Mini CMS。请先分析当前截图与目标截图在顶栏、侧栏和滚动方式上的差异，结合我的 admin/layout.tsx 解释调整理由，再给出修改建议。

遇到具体 API 或样式问题，再查下方官方文档。不必一次拿到整个后台的重写代码；每完成一个区域，滚动、缩窄窗口并操作一次，确认理解了改动。

在 Mini CMS 的 `docs/ui-notes.md` 中留一份简短记录即可：

- **效果对比**：还原前后截图，以及采用的目标页面。
- **改动位置**：布局、Provider、页面或样式文件分别改了什么。
- **关键理解**：选一个实际遇到的问题，写清原因、解决方式与验证结果。

完成时检查：顶栏与导航稳定，内容不被遮挡；窗口缩窄后控件能换行、表格仍可访问；文章和标签的增删改查、筛选分页及错误提示都正常。

通过 Git 保留这版普通 Ant Design 实现，再进入 [16C-用 ProComponents 简化管理后台](./16C-用ProComponents简化管理后台.md)。下一章以同样的 UI 和业务行为为目标，比较业务组件能减少哪些代码。
