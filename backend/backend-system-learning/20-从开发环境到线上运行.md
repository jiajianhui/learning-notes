# 20. 从开发环境到线上运行：准备生产发布

> Mini CMS 阶段 8：先完成[第 19 章的文章写作、预览与内容排版](./19-文章写作预览与内容排版.md)，再用本章检查生产构建和运行条件。

## 这一章完成什么

第 19 章已经跑通富文本编辑、JSON 保存、公开文章 API、个人网站详情页和统一预览。本章把这个已经可用的产品准备成可以部署的工程：

```text
复查正式内容的发布与撤回
-> 检查生产构建、环境变量和启动命令
-> 确认迁移、健康检查、日志和备份
-> 交给 20A 完成真实服务器部署
```

第 20 系列专注上线。编辑器、内容格式和文章排版在第 19 章完成，不在部署时临时选择。全部本地检查通过后，使用 [20A-用 1Panel 和 Docker Compose 部署 Mini CMS](./20A-用1Panel和Docker-Compose部署MiniCMS.md) 完成真实自托管部署。本项目不使用宝塔。

## 1. 上线前复查发布与撤回

第 19 章已经实现并验证公开阅读链路。准备上线时，用最终构建再走一遍真实操作：

```text
在管理后台新建草稿
-> 草稿不出现在个人网站
-> 发布后出现在公开列表
-> 点击进入文章详情页
-> 正文排版与第 19 章的后台预览一致
-> 撤回后公开列表和详情都不能继续访问
```

如果已经使用页面缓存，发布、修改和撤回后的列表与详情都要及时更新；第一版可以继续使用第 19 章的 `cache: "no-store"`。内容编辑和排版问题回到第 19 章修复，本章不重新选择正文格式。

## 2. 准备交给部署的项目

开发环境中可以同时运行管理后台、Express 和 PostgreSQL，个人网站也可以在自己的项目中单独启动。线上环境还要考虑域名、HTTPS、构建、环境变量、数据迁移和日志。

HTTPS 是加密传输的 HTTP，避免密码和 Cookie 在网络传输时直接暴露。

部署对象始终是已经完成的真实 `mini-cms`：管理后台、`server` 和 PostgreSQL 各自使用生产配置，不再新建部署 demo。个人网站保留在自己的项目中，通过正式 API 域名读取内容。

### 构建和启动命令

```text
npm run dev
-> 开发时运行 TypeScript

npm run build
-> 编译并检查

npm run start
-> 运行生产构建
```

README 要写清楚 Node.js、环境变量、数据库和启动顺序。

### 可重复的数据库迁移

线上不能依赖“我记得自己手动建过哪些表”。

需要保存：

- `schema.prisma` 和生成的迁移文件。
- 执行顺序。
- 修改结构前的数据备份。

代码版本和数据库结构必须能够对应。

Prisma 的开发和生产命令不要混用：

```text
本地开发：prisma migrate dev
-> 根据 schema.prisma 创建迁移，并应用到开发数据库

构建阶段：prisma generate
-> 生成当前代码需要的 Prisma Client

测试、预发布和生产：prisma migrate deploy
-> 只按顺序应用已经提交的迁移
```

`migrate dev` 会使用开发流程检查结构差异，不能拿来操作生产数据库；`migrate deploy` 不会替你生成 Prisma Client，所以构建流程仍要显式执行 `prisma generate`。迁移应由部署流程执行，不要为了上线临时把生产数据库地址复制到本机。

### 公开健康检查

```text
GET /api/health
```

可以检查应用是否运行，必要时增加数据库连通性信息，但不要返回密码和内部配置。

### 请求与错误日志

至少记录：

- 请求方法和路径。
- 响应状态码。
- 请求耗时。
- 未知错误的内部细节。

不要在日志中记录密码、完整 Cookie 和敏感密钥。

## 3. 进入 20A 前的交付检查

先保证：

- 两个公开文章接口可以在本地读取已发布内容，并拒绝公开草稿和撤回文章。
- 个人网站的文章列表和详情页已经读取真实 API，不再依赖写死的临时文章。
- 第 19 章的富文本 JSON 迁移、接口校验、两个后台编辑回显和发布预览已经验收。
- 个人网站与后台使用同一版本的正文渲染组件和样式，布局与正文排版已经完成。
- 各工程的依赖声明和锁文件完整，Docker 构建可独立安装依赖。
- 公开接口的核心规则已有自动化测试。
- `.env.example` 完整。
- 真实 `.env` 不提交。
- `build`、`start`、`test` 命令可用。
- Prisma 迁移有记录并且能在新数据库重复执行。
- 有 `/api/health`。
- 有基础请求和错误日志。
- README 能指导新环境启动。
- 数据库知道怎样备份。
