# 20. 从本地到服务器：上线前需要改什么

接下来的 [20A](./20A-用宝塔和Docker-Compose部署MiniCMS.md)会在 Mac 制作镜像，再让服务器下载运行。本章先补齐它要调用的项目脚本，并把启动方式记到 README。

## 1. 补齐后端脚本

在 `server/package.json` 的现有 `scripts` 中增加两项，保留原有 `dev` 和其他脚本：

```json
{
  "start": "tsx src/server.ts",
  "db:migrate:deploy": "prisma migrate deploy"
}
```

`start` 运行原来的 Express 入口，去掉开发命令里的 `watch`，不再监听代码修改。`db:migrate:deploy` 把已经提交的迁移应用到 `DATABASE_URL` 指定的数据库；开发时新增迁移仍使用原来的 `db:migrate`。

## 2. 前后端上线时分别怎样启动

管理端已有 `build`、`start`，不用新增脚本：

| 执行目录 | 本地开发 | 上线使用的方式 |
|---|---|---|
| `server` | `npm run dev` | `npm run start`，通过 `tsx` 直接运行后端 |
| `admin-web-antd` | `npm run dev` | 先 `npm run build` 生成 `.next/`，再 `npm run start` 提供页面 |

## 3. 把配置与命令记到 README

把下面这段放到 `mini-cms/README.md`：

```markdown
# Mini CMS

Express + Prisma + PostgreSQL 提供 API，Next.js + Ant Design 提供管理页面。

## 本地准备

- 安装 Node.js 24 和 Docker，在 `server`、`admin-web-antd` 中分别执行 `npm ci`。
- 后端参考 `server/.env.example` 创建 `server/.env`。
- 前端参考 `admin-web-antd/.env.example` 创建 `admin-web-antd/.env.local`。
- 在项目根目录执行 `docker compose up -d postgres`，启动数据库。
- 首次运行时，确认数据库可连接，在 `server` 中依次执行 `npm run db:generate`、`npm run db:migrate:deploy`。
- 新数据库还需创建管理员：在后端 `.env` 临时填写 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD`，执行 `npm run admin:create`，成功后删除 `.env` 中的 `ADMIN_PASSWORD`。

## 启动命令

前后端分别在两个终端中运行：

| 执行目录 | 开发时 | 上线时 |
|---|---|---|
| `server` | `npm run dev` | `npm run start` |
| `admin-web-antd` | `npm run dev` | 先 `npm run build`，再 `npm run start` |

本地管理页面是 `http://localhost:3000`，API 地址是 `http://localhost:3001`。

## 数据库命令

以下命令在 `server` 中执行：

- `npm run db:migrate -- --name 变更名`：开发时生成迁移并更新开发库。
- `npm run db:generate`：生成 Prisma Client。
- `npm run db:migrate:deploy`：把已有迁移应用到配置指定的数据库。
```

部署时会另外配置三个地址：前端的 `NEXT_PUBLIC_API_BASE_URL` 使用正式 API 域名，后端的 `ADMIN_WEB_ORIGIN` 使用正式后台来源，`DATABASE_URL` 使用线上账号和 Compose 数据库服务地址 `postgres:5432`。具体值和传入方式跟着 20A 填写。

补好脚本和 README 后，进入 [20A：用宝塔和 Docker Compose 部署 Mini CMS](./20A-用宝塔和Docker-Compose部署MiniCMS.md)。
