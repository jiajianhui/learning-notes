## 1. 让标题和正文组成连续写作区

### 1.1 文章标题继续使用独立的 title

`title` 是整篇文章的名称，用于列表和文章头部；Tiptap 的 Heading 是正文里的小节。第 19 章已经将正文标题限制为 h2、h3，文章头部的 h1 由 `ArticlePage` 根据 `title` 渲染。

例如写一篇“我的 React 学习记录”：

```text
title：我的 React 学习记录
content：开场段落 → h2「组件」→ 段落 → h2「状态」→ 段落
```

不要在正文第一行再填写一次文章名。界面看起来是一篇文章，表单里依然分别保存 `title` 和 `content`；无需从正文的第一行提取标题。

### 1.2 对齐标题与正文，去掉演示页的空白

在 `app/admin/articles/_components/article-form.tsx` 中，将现有标题字段放进 `article-title-area`，保留原来的字段名和校验。下面替换标题部分，正文 `Form.Item` 继续放在它的后面：

```tsx
<div className="article-title-area">
  <Form.Item

    rules={[
      { required: true, whitespace: true, message: "请输入标题" },
      { max: 200, message: "标题不能超过 200 个字符" },
```

`autoSize` 让长标题随内容增高，标题仍由原来的 Form 管理。左侧写作容器设置 `min-width: 0`，右侧继续使用第 19 章的文章设置栏。

## 2. 选中文字后出现排版工具

Tiptap 的 `BubbleMenu` 负责跟随选区显示菜单，里面放什么按钮由我们决定。它和正文使用同一个 `editor`，点击按钮仍然通过原来的 `onUpdate → onChange → Form.content` 更新表单。

本章使用 Tiptap 3.32.0，与第 19 章保持一致。在 `admin-web-antd` 中执行：

```bash
npm install --save-exact @tiptap/extension-bubble-menu@3.32.0 @tiptap/extension-floating-menu@3.32.0
npm install @floating-ui/dom@^1.6.0
```

从 `@tiptap/react/menus` 导入 React 组件。组件会注册自己的菜单插件，不再把同名菜单扩展加入 `createArticleExtensions()`；菜单只负责编辑交互，个人网站不需要安装它们。

新增 `features/articles/article-text-menu.tsx`：

```tsx
"use client";

import { useRef } from "react";
import { isTextSelection, type Editor } from "@tiptap/core";
import { BubbleMenu } from "@tiptap/react/menus";
import { HeadingDropdownMenu } from "@/components/tiptap-ui/heading-dropdown-menu";
import { ListDropdownMenu } from "@/components/tiptap-ui/list-dropdown-menu";
import { MarkButton } from "@/components/tiptap-ui/mark-button";
import { LinkPopover } from "@/components/tiptap-ui/link-popover";

export function ArticleTextMenu({ editor }: { editor: Editor }) {
  const menuRef = useRef<HTMLDivElement>(null);

  return (
    <BubbleMenu
      ref={menuRef}
      editor={editor}
      pluginKey="article-text-menu"
      options={{ placement: "top", offset: 8, flip: true, shift: true }}
      shouldShow={({ view, state, from, to }) =>
        editor.isEditable &&
        (view.hasFocus() || !!menuRef.current?.contains(document.activeElement)) &&
        isTextSelection(state.selection) &&
        !state.selection.empty &&
        state.doc.textBetween(from, to).trim().length > 0
      }
      className="article-text-menu"
      role="group"
      aria-label="选中文字的排版"
    >
      <HeadingDropdownMenu editor={editor} levels={[2, 3]} modal={false} />
      <ListDropdownMenu
        editor={editor}
        types={["bulletList", "orderedList", "taskList"]}
        modal={false}
      />
      <MarkButton editor={editor} type="bold" />
      <MarkButton editor={editor} type="italic" />
      <MarkButton editor={editor} type="code" />
      <LinkPopover editor={editor} autoOpenOnLinkActive={false} />
    </BubbleMenu>
  );
}
```

这里复用模板已有按钮，不重写加粗、链接和标题菜单：

- `editor` 指向当前正文；`levels={[2, 3]}` 与已有正文规则一致。
- `pluginKey` 是这个菜单的标识，后面的插入菜单使用另一个名字。
- `shouldShow` 限定为非空文字选区，排除只选中图片的情况；点击菜单内按钮时，也把菜单视为编辑区的一部分。
- `autoOpenOnLinkActive={false}` 让链接面板只在主动点击按钮后打开，避免光标经过链接就弹出。

在 `components/tiptap-templates/simple/simple-editor.tsx` 中导入 `ArticleTextMenu`，将下面的 JSX 放在现有 `EditorContext.Provider` 内，与 `EditorContent` 并列。先保留原工具栏：

```tsx
{editor && !disabled && <ArticleTextMenu editor={editor} />}
```

在后台 `article.css` 中增加菜单样式：

```css

  max-width: calc(100vw - 24px);
  padding: 6px;
  color: #202020;
  background: #fff;
  border: 1px solid #e5e5e5;
  border-radius: 10px;
```

**验证：** 连续输入时菜单隐藏；选中文字后菜单出现，加粗按钮的状态随选区变化。设置链接时能输入地址，确认后链接作用于原选区；点击正文空白处后菜单消失。格式操作不能触发表单提交。

## 3. 在空白段落用 + 插入内容

文字排版菜单不能代替插入入口：文章还是空白时，没有文字可选。`FloatingMenu` 可以跟随空白段落显示 `+`。

新增 `features/articles/article-insert-menu.tsx`：

```tsx
"use client";

import { useRef, useState } from "react";
import type { Editor } from "@tiptap/core";
import { FloatingMenu } from "@tiptap/react/menus";

type ArticleInsertMenuProps = {
  editor: Editor;
  onInsertImage: () => void;
};

export function ArticleInsertMenu({ editor, onInsertImage }: ArticleInsertMenuProps) {
  const [open, setOpen] = useState(false);
  const menuRef = useRef<HTMLDivElement>(null);

  function runCommand(command: () => void) {
    if (!editor.isEditable) return;
    command();
    setOpen(false);
  }

  const items = [
    { label: "二级标题", run: () => { editor.chain().focus().setHeading({ level: 2 }).run(); } },
    { label: "三级标题", run: () => { editor.chain().focus().setHeading({ level: 3 }).run(); } },
    { label: "无序列表", run: () => { editor.chain().focus().toggleBulletList().run(); } },
    { label: "有序列表", run: () => { editor.chain().focus().toggleOrderedList().run(); } },
    { label: "任务列表", run: () => { editor.chain().focus().toggleTaskList().run(); } },
    { label: "引用", run: () => { editor.chain().focus().toggleBlockquote().run(); } },
    { label: "代码块", run: () => { editor.chain().focus().toggleCodeBlock().run(); } },
    { label: "图片", run: onInsertImage },
    { label: "表格", run: () => { editor.chain().focus().insertTable({ rows: 3, cols: 3, withHeaderRow: true }).run(); } },
  ];

  return (
    <FloatingMenu
      ref={menuRef}
      editor={editor}
      pluginKey="article-insert-menu"
      options={{ placement: "bottom-start", offset: 6, flip: true, shift: true }}
      shouldShow={({ view, state }) => {
        const { empty, $from } = state.selection;
        return editor.isEditable &&
          (view.hasFocus() || !!menuRef.current?.contains(document.activeElement)) &&
          empty && $from.depth === 1 &&
          $from.parent.type.name === "paragraph" &&
          $from.parent.childCount === 0;
      }}
      className="article-insert-menu"
      onKeyDown={(event) => {
        if (event.key === "Escape" && !event.nativeEvent.isComposing) {
          event.preventDefault();
          setOpen(false);
          editor.commands.focus();
        }
      }}
    >
      <button
        type="button"
        aria-label="插入内容"
        aria-expanded={open}
        onMouseDown={(event) => event.preventDefault()}
        onClick={() => setOpen(!open)}
      >
        +
      </button>
      {open && (
        <div className="article-insert-panel" role="group" aria-label="内容类型">
          {items.map((item) => (
            <button
              key={item.label}
              type="button"
              onMouseDown={(event) => event.preventDefault()}
              onClick={() => runCommand(item.run)}
            >
              {item.label}
            </button>
          ))}
        </div>
      )}
    </FloatingMenu>
  );
}
```

`open` 只记录插入面板是否展开，正文内容继续由 `editor` 管理：

```text
进入空白段落 → 显示 + → 展开面板 → 选择内容类型
→ 命令改变正文 → onUpdate 更新表单 content
```

`$from` 表示光标所在的位置。这里要求它位于正文最外层的空白段落，因此不会在代码块、表格单元格或列表内部额外显示 `+`。先把这条正常流程做通，再考虑更细的插入位置。

按钮的 `type="button"` 避免提交表单；`onMouseDown` 阻止鼠标按下时抢走光标，命令再通过 `focus()` 操作当前插入点。不要把这个阻止默认行为的处理加到整张表单，否则链接和图片面板里的输入框也会受到影响。

### 3.1 连接已有图片面板

在 `simple-editor.tsx` 中导入 `ArticleInsertMenu`，同样放在 `EditorContext.Provider` 内：


这里的 `openImagePanel` 是给第 19 章第 5.1 节已有图片属性面板的“打开”事件起的名称，不是 Tiptap API。将原“插入图片”按钮使用的处理函数传进来；若已有名称不同，使用项目中的名称。

面板打开前记录 `editor.state.selection` 的 `from`、`to`；确认时恢复该选区，再执行已有的图片插入命令。图片地址、替代文字、图注、宽幅规则和取消行为继续沿用第 19 章，不在 `+` 菜单里重新实现。表格扩展也使用该章已经接入的 TableKit。

### 3.2 收起面板，并补齐样式

在 `ArticleInsertMenu` 中增加下面的 Effect，同时把 `useEffect` 加入 React 导入。光标移动、正文改变或点击编辑区外部时收起面板，避免回到另一空行时展开旧菜单：

```tsx
useEffect(() => {
  const close = () => setOpen(false);
  const closeOutside = (event: PointerEvent) => {
    if (!menuRef.current?.contains(event.target as Node)) close();
  };
  const closeFromEditor = (event: KeyboardEvent) => {
    if (event.key === "Escape" && !event.isComposing) close();
  };
  const editorElement = editor.view.dom;

  editor.on("selectionUpdate", close);
  editor.on("update", close);
  editorElement.addEventListener("keydown", closeFromEditor);
  document.addEventListener("pointerdown", closeOutside);
  return () => {
    editor.off("selectionUpdate", close);
    editor.off("update", close);
    editorElement.removeEventListener("keydown", closeFromEditor);
    document.removeEventListener("pointerdown", closeOutside);
  };
}, [editor]);
```

Effect 放在 `runCommand` 前面，始终在组件顶层调用。点击 `+` 时光标仍留在正文，所以正文也监听 Escape；键盘焦点进入菜单时，由菜单自身处理。输入法正在组合文字时，不用 Escape 关闭插入面板。事件清理让组件卸载后不再监听旧编辑器。

展开面板后，浮层高度也会变化。再增加一个 Effect，让 FloatingMenu 根据新尺寸调整位置：

```tsx
useEffect(() => {
  editor.commands.setMeta("article-insert-menu", "updatePosition");
}, [editor, open]);
```

```css

.article-insert-menu > button,
.article-insert-panel button {
  min-width: 36px;
  min-height: 36px;
  padding: 6px 10px;
  font: inherit;
  font-size: 14px;
  color: #333;
  background: #fff;
  border: 1px solid #e5e5e5;
  border-radius: 6px;
  cursor: pointer;
}
.article-insert-panel {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 4px;
  margin-top: 6px;
}
.article-insert-panel button:hover { background: #f5f5f5; }
.article-insert-menu button:focus-visible {

```

这版将 `+` 放在空行附近，由浮层处理屏幕边缘的位置。先保证窄屏可用，不用负的 `left` 强行把按钮挤到文章外侧。

## 4. 收起固定工具栏，保留其他操作入口

现在可以让固定工具栏退出主要写作区。但选中文字的菜单和空行 `+` 还没有覆盖全部已有能力，先给其余按钮安排位置：

| 已有能力 | 新入口 |
|---|---|
| 标题、列表、加粗、斜体、行内代码、链接 | 选中文字的浮动菜单 |
| 创建标题、列表、引用、代码块、图片、表格 | 空行 `+` |
| 下划线、删除线、高亮、上下标、对齐，以及修改已有段落类型 | 收起的“更多排版”区 |
| 修改图片、编辑表格行列 | 保留第 19 章已有面板与操作按钮，移到“更多排版”区 |
| 撤销、重做、查找替换 | “更多排版”区；快捷键继续可用 |
| 保存、预览、发布 | 原来的页面顶部操作 |

### 4.1 将原工具栏移进可展开区域

在 `simple-editor.tsx` 中，先简化现有 `MainToolbarContent`，保留它的其他格式按钮和查找替换按钮：

- 删除 `{isMobile && <ToolbarSeparator />}` 和用于左右撑开按钮的两个 `<Spacer />`。
- 保留 `onSearchAndReplaceClick`、`isSearchAndReplaceOpen`、`searchAndReplaceButtonRef` 三个参数。

现在各屏幕统一使用按钮自身的弹层。用下面的结构替换原来的固定 `<Toolbar>...</Toolbar>`，保留其他 JSX：

```tsx
{!disabled && (
```

最终 Provider 内包含：更多排版区、原查找替换面板、两个新菜单，以及唯一一个 `EditorContent`。继续保留第 19 章已有的 `editor.setEditable(!disabled)`；图片属性面板的确认事件也检查当前是否允许编辑。

### 4.3 预览时关闭菜单，保留正文实例

第 19 章通过显示切换保留整个表单。浮动菜单可能挂在页面外层，因此还要把预览状态交给编辑器。给 `ArticleEditorProps` 增加 `previewing?: boolean`，在 `SimpleEditor` 参数解构中设置 `previewing = false`。ArticleForm 将已有的预览状态作为 `previewing` 属性传入；状态变量使用已有名称，不再创建第二份预览状态。

把两个新菜单以及更多排版区的显示条件统一改为 `editor && !disabled && !previewing`。另外在 `SimpleEditor` 顶层增加：

```tsx
useEffect(() => {
  if (disabled || previewing) setIsSearchAndReplaceOpen(false);
}, [disabled, previewing]);
```

这样保存或进入预览时，菜单内部的链接、高亮弹层随菜单卸载，查找替换面板也关闭。第 19 章的图片属性面板在这两个状态下同样关闭；确认事件在 `disabled` 或预览状态下直接返回。

这里只卸载操作菜单，`EditorContent` 和 `useEditor()` 始终保留，所以返回编辑时仍使用原来的正文实例与撤销历史。

**验证：** 默认页面只显示标题、正文和收起的更多入口；图片、表格、已有格式仍能修改。保存时不能通过新菜单、更多排版或已经打开的面板修改正文；预览返回后，文字、光标和撤销历史仍在。

## 5. 用一次真实写作检查体验

写一篇包含小节标题、列表、链接、代码、图片和表格的文章，按下面的顺序检查：

1. 输入文章标题，进入正文连续输入中文，输入法选字不会触发插入操作。
2. 选中一句话加粗，再选其他文字，按钮状态与当前选区一致。
3. 设置和修改链接；面板获得焦点后，原选区仍然正确。
4. 在两个段落之间新建空白段落，通过 `+` 插入图片；取消不改变正文，确认插在原位置。
5. 插入表格后，从更多排版区增删行列；图片仍能修改图注和宽幅。
6. 不选文字，展开更多排版，将当前小节恢复为普通段落；撤销、重做和查找替换可用。
7. 预览未保存内容，再返回继续编辑；随后保存、刷新，核对正文格式和图片属性。
8. 缩窄页面并在手机上检查选区菜单、`+`、链接输入和文章设置，页面不整体横向滚动。

图片和链接面板的确认事件继续检查第 19 章的 URL 规则。这里只改变触发入口，不放宽后端格式限制，也不新增自动保存。

在 `admin-web-antd` 中运行已有检查：

```bash
npm run lint
npm run build
```

本章主要验证界面、焦点和选区；API contract 沿用第 19 章，不为菜单位置重复编写接口测试。后续第二套后台接入时，将两个菜单、编辑区样式和触发规则同步过去，继续使用各自的文章表单。

## 6. 可选练习：用 / 搜索插入内容

`+` 菜单已经提供可发现的插入入口。熟悉后，可以在新行输入 `/` 来搜索内容类型。

它与 FloatingMenu 是不同的触发方式：FloatingMenu 显示空行菜单；输入 `/` 后段落已不再为空，需要另行接入 [Suggestion](https://tiptap.dev/docs/editor/api/utilities/suggestion) 来识别触发字符和搜索文字。

这项练习复用第 3 节的内容类型与执行命令，重点完成：

- 输入 `/` 后打开列表，继续输入时筛选，上下键选择、Enter 确认、Escape 关闭。
- 选择命令时，先删除 `/` 和搜索文字所在范围，再转换当前段落或插入内容。
- 中文输入法正在组合文字时，不抢走 Enter 和方向键；关闭菜单后保留正常输入。
- `+` 继续保留，两个入口使用同一份命令列表，不分别维护两套插入逻辑。

`/` 的实现不作为本章验收前提。完成第 5 节后，可以回到[第 10 章](./10-MiniCMS项目总览.md)核对阶段 8，再进入[第 20 章](./20-从开发环境到线上运行.md)准备生产运行。
