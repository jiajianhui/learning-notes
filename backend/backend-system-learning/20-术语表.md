# 20. 数据库与 ORM 术语速查

这一章只收集数据库和 ORM 主线里的名词。Express、Next.js、Cookie 和 CRUD 等已知概念不再重复解释。

| 术语 | 先怎么理解 |
|---|---|
| Docker | 用容器运行 PostgreSQL 等项目依赖 |
| container（容器） | 根据镜像启动的隔离运行环境 |
| volume（数据卷） | 让容器重建后仍可保留数据的存储 |
| PostgreSQL | 关系型数据库软件 |
| TablePro | macOS 上连接 PostgreSQL、查看表和数据、编写并执行 SQL 的桌面工具 |
| SQL | 查询和修改关系型数据的语言 |
| ORM | Object-Relational Mapping，用模型 API 描述查询和修改，再转换成 SQL 的工具层 |
| Prisma Schema | 使用 `schema.prisma` 定义模型、字段、约束和关系 |
| Prisma Client | 根据 Prisma Schema 生成，提供模型方法和 TypeScript 类型的数据库客户端 |
| Prisma Migrate | 根据模型变化生成并执行表结构修改 SQL 的工具 |
| Prisma Studio | 开发阶段查看和编辑数据库数据的可视化工具 |
| 驱动适配器（driver adapter） | Prisma 7 连接具体数据库驱动的适配层 |
| database（数据库） | 一组被数据库软件管理的数据 |
| table（表） | 保存同一类结构化数据 |
| row（行） | 表中的一条记录 |
| column（列） | 一类字段 |
| data type（数据类型） | 限制一列能保存哪一类值 |
| `NULL` | 当前没有值，不等于空字符串或数字 0 |
| `NOT NULL` | 这一列必须有值 |
| `DEFAULT` | 没有提供该列时使用的默认值 |
| primary key（主键） | 稳定且唯一识别一行 |
| foreign key（外键） | 约束一张表对另一张表的引用 |
| unique constraint（唯一约束） | 保证字段或字段组合不重复 |
| `CHECK` | 限制一列必须符合指定条件 |
| `WHERE` | 选择符合条件的行 |
| `ORDER BY` | 指定查询结果的排序方式 |
| `LIMIT / OFFSET` | 限制返回数量并跳过前面的行 |
| `JOIN` | 根据匹配条件组合多张表中的相关数据 |
| `LEFT JOIN` | 保留左表全部数据，即使右表没有匹配项 |
| transaction（事务） | 让一组操作一起成功或失败 |
| index（索引） | 帮助数据库更快定位数据的额外结构 |
| migration（迁移） | 可追踪地修改数据库结构 |
| connection pool（连接池） | 复用有限数量的数据库连接 |
| pg | PostgreSQL 的 Node.js 驱动，Prisma 7 的驱动适配器在底层使用它 |
| SQL injection（SQL 注入） | 把恶意输入混入 SQL 结构的攻击 |

## 小结

遇到陌生的数据库或 ORM 术语时，先判断：

```text
它是在定义表结构、连接数据库、生成 SQL 还是执行 SQL 时出现？
-> 它接收什么，又交出什么？
-> 它解决的是哪个具体问题？
-> 应该回看第 07～10 章的哪个例子？
```

先搞清它在当前流程中的作用，再学具体写法。
