# 00. 阅读导引：用同一条文章请求穿过整个后端

## 问题背景

后端初学者最容易遇到的问题不是概念太少，而是每个概念都单独学：

```text
今天学 Express
明天学 SQL
后天学 Cookie
```

最后知道很多名字，却不知道一次请求怎样经过这些技术。

这套文档固定使用同一条业务流程：

```text
在管理后台新建一篇文章。
```

对应请求：

```http
POST /api/articles
Content-Type: application/json

{
  "title": "我的第一篇文章",
  "slug": "my-first-article",
  "content": "正文"
}
```

功能不变，只逐层补上后端能力。

---

## 核心解释

### 1. 一条请求会经过什么

```text
Next.js 表单
-> HTTP POST 请求
-> Express 路由
-> JSON 解析中间件
-> 登录认证
-> 参数校验
-> 文章业务逻辑
-> pg 参数化查询
-> PostgreSQL articles 表
-> 201 响应
-> 管理后台显示成功
```

后面的章节，就是从上到下把每个节点讲清楚。

### 2. 学习顺序和代码执行顺序不同

代码执行时，请求从浏览器进入服务器，再进入数据库。

学习时需要先从底层建立地图：

```text
Node.js
-> HTTP
-> Express
-> 异步、错误和 API
-> SQL 和 PostgreSQL
-> 项目组织和 Next.js 联调
-> 数据关系、登录和测试
-> 部署
```

一句话：

```text
执行时从外到内，学习时从基础到组合。
```

## 每次动手只追踪一条链路

例如创建文章时，只回答这几个问题：

```text
1. 请求从哪个路由进入？
2. body 在哪里被解析和校验？
3. 哪个函数执行 SQL？
4. SQL 参数来自哪里？
5. 数据库返回什么？
6. 为什么返回 201？
7. 前端怎样显示成功或失败？
```

如果这些问题能回答，查文档、搜索函数名或让 AI 帮助写代码都没有问题。

---

## 完成标准

系统学习不是要求记住全部 API。

学完后应该能：

- 画出浏览器、Express 和 PostgreSQL 的关系。
- 区分 Node.js、Express 和数据库各自负责什么。
- 根据状态码判断问题大致发生在哪里。
- 从路由一路追到 SQL，再追回应答。
- 分清接口检查、产品界面和自动化测试。
- 看见陌生后端项目时知道先读什么。

---

## 小结

这套学习只围绕一条主线：

```text
让一篇文章可靠地从管理后台进入数据库，
再从数据库回到页面。
```

每学一层，都回来对照这条请求，后端就不会变成一堆孤立名词。
