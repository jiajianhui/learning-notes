# 00. 阅读导引：用同一条文章请求穿过整个后端

## 问题背景

后端初学者最容易遇到的问题不是概念太少，而是每个概念都单独学：

```text
今天学 Express
明天学 SQL
后天学 Cookie
```

最后知道很多名字，却不知道一次请求怎样经过这些技术。

这套文档固定使用同一条业务流程：

```text
在管理后台新建一篇文章。
```

Next.js、Node.js、HTTP、Express 和 CRUD 不在这里重复解释。数据库这条线先分清下面几个名字：

| 名词 | 现在先怎么理解 |
|---|---|
| PostgreSQL | 长期保存数据并执行 SQL 的数据库 |
| SQL | PostgreSQL 用来查询和修改数据的语言 |
| ORM | 把代码里的模型操作转换成 SQL；Prisma 属于这一类工具 |
| Prisma Schema | 定义模型、字段和数据库规则 |
| Prisma Client | 在 TypeScript 中提供查询和修改数据库的方法 |
| migration | 按顺序记录建表、加列等表结构变化 |
| Prisma Migrate | 生成并执行 migration |
| Postico 2 | 在 macOS 上查看 PostgreSQL 并亲手执行 SQL 的桌面工具 |
| `pg` | Node.js 连接 PostgreSQL 的数据库驱动 |
| pg adapter | 把 Prisma Client 和 `pg` 接起来的驱动适配器 |

对应请求：

```http
POST /api/articles
Content-Type: application/json

{
  "title": "我的第一篇文章",
  "slug": "my-first-article",
  "content": "正文"
}
```

功能不变，只逐层补上后端能力。

---

## 先看清请求主线和学习顺序

### 1. 一条请求会经过什么

```text
Next.js 表单
-> HTTP POST 请求
-> Express 接收请求
-> 后端检查输入并处理文章规则
-> PostgreSQL 保存文章
-> 返回创建结果
-> 管理后台显示成功
```

后面的章节，就是从上到下把每个节点讲清楚。

### 2. 学习顺序和代码执行顺序不同

代码执行时，请求从浏览器进入服务器，再进入数据库。

学习时需要先从底层建立地图：

```text
Node.js
-> HTTP
-> Express
-> 异步、错误和 API
-> 单表结构和 SQL CRUD
-> Docker 启动 PostgreSQL，Postico 2 手写 SQL，Prisma 7 跑通单表 CRUD
-> 校验请求并统一处理错误
-> 项目组织和 Next.js 联调
-> 需要标签时再学多表关系和事务
-> 登录和测试
-> 部署
```

一句话：

```text
执行时从外到内，学习时从基础到组合。
```

## 每次动手只追踪一条链路

例如创建文章时，只回答这几个问题：

```text
1. 请求从哪个路由进入？
2. 提交的文章数据在哪里被解析和校验？
3. 哪段代码把数据库操作交给数据访问工具？
4. 查询条件和写入数据来自哪里？
5. 数据库返回什么？
6. 为什么返回 201？
7. 前端怎样显示成功或失败？
```

如果这些问题能回答，查文档、搜索函数名或使用辅助工具帮助写代码都没有问题。

---

## 完成标准

系统学习不是要求记住全部 API。

学完后应该能：

- 画出浏览器、Express 和 PostgreSQL 的关系。
- 区分 Node.js、Express 和数据库各自负责什么。
- 根据状态码判断问题大致发生在哪里。
- 从路由一路追到数据库访问代码和 PostgreSQL，再追回应答。
- 分清接口检查、产品界面和自动化测试。
- 看见陌生后端项目时知道先读什么。

---

## 小结

这套学习只围绕一条主线：

```text
让一篇文章可靠地从管理后台进入数据库，
再从数据库回到页面。
```

每学一层，都回来对照这条请求，后端就不会变成一堆孤立名词。
