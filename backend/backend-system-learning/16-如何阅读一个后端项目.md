# 16. 如何阅读后端项目：沿着一次请求往里走

## 问题背景

打开陌生后端项目时，如果从 `src/` 第一行开始逐文件阅读，很容易被配置、工具函数和目录名淹没。

更有效的方法是固定追踪一条请求：

```text
它从哪里进入？
经过哪些中间件？
在哪里校验？
在哪里调用 Prisma Client 查询数据库？
怎样返回？
```

---

## 阅读顺序

### 1. 先看 `package.json`

重点看：

- `scripts`：怎样开发、构建、启动和测试。
- `dependencies`：应用运行时需要的包，例如 Express、Prisma Client、PostgreSQL 驱动适配器和 pg。
- `devDependencies`：只在开发、迁移、测试或构建时使用的工具，例如 Prisma CLI、TypeScript 和 Supertest。

先知道项目怎样运行，再读业务代码。

### 2. 找启动入口

常见文件：

```text
src/server.ts
src/index.ts
src/main.ts
```

重点看：

- 从哪里读取端口。
- 哪个 app 被启动。
- 启动前是否检查环境变量和数据库。

### 3. 找 Express app

常见线索：

```ts
const app = express();
app.use(...);
```

记录中间件顺序和路由前缀。

### 4. 找一条具体路由

例如：

```text
POST /api/articles
```

使用 `rg` 搜索：

```bash
rg 'articles' src
```

然后沿着调用继续看：

```text
route
-> controller
-> service
-> repository
-> Prisma Client 生成 SQL
-> PostgreSQL 执行 SQL
```

### 5. 回头看公共能力

理解一条业务请求后，再看：

- 错误处理中间件。
- 参数校验。
- 认证。
- 数据库连接。
- 日志。
- 测试和配置。

这时公共代码有了上下文，不再只是抽象函数。

---

## 阅读时画一张小图

```text
POST /api/articles
  -> requireAuth
  -> validateCreateArticle
  -> createArticleController
  -> createArticleService
  -> articleRepository.create
  -> Prisma Client
  -> PostgreSQL
  <- 201 { data: article }
```

图不需要漂亮，只要能说明文件和数据怎样移动。

---

## 判断项目用了什么技术，不要只看文件名

| 线索 | 可以判断什么 |
|---|---|
| `express` | Web 框架 |
| `prisma/schema.prisma` | 项目用 Prisma 定义数据库模型 |
| `@prisma/client` | 项目使用生成的 Prisma Client |
| `@prisma/adapter-pg` / `pg` | Prisma 7 通过 PostgreSQL 驱动适配器连接数据库 |
| `prisma/migrations` | Prisma Migrate 保存的迁移历史 |
| `compose.yaml` | 本地服务可能通过 Docker 启动 |
| `supertest` | HTTP 接口测试 |
| `cookie` | 认证线索 |
| migrations 目录 | 数据库结构变更方式 |

依赖只能说明“可能使用”，还要看代码入口和真实调用。

---

## 用同一条文章请求怎样练

每完成一个阶段，重新从 `POST /api/articles` 走一遍：

```text
阶段 1：route -> 内存数组
阶段 2：route -> Prisma Client -> SQL -> PostgreSQL -> articles
阶段 3：增加 validation / service / repository，并由 Next.js 发出请求
阶段 4：增加标签关系、nested write 和 $transaction
阶段 5：请求再经过 auth
阶段 6：由 Supertest 自动发出请求
```

同一路径越来越完整，可以清楚看到每一层解决了什么问题。

---

## 阅读项目时容易走偏的地方

- 从工具函数目录逐行读，看不到请求主线；先找启动入口和一条具体 route。
- 文件叫 controller 或 service，不代表它真的遵守这种职责；要看函数实际读取什么、调用什么。
- 目录名只能提供线索，真实关系要沿 import 和函数调用确认。
- 一开始研究所有配置容易被细节淹没；先知道项目怎样启动，再追踪核心请求。
- 阅读时区分 Express 自动调用的中间件和项目自己调用的业务函数，才能看清每一步是谁触发的。

---

## 小结

```text
先看 scripts
-> 找启动入口
-> 找 Express app
-> 选一条路由
-> 追到业务、Prisma Client 和 PostgreSQL
-> 再看认证、错误和测试
```

阅读后端项目最有效的线索不是文件顺序，而是请求的数据流。
