# 17. 后端术语表：先知道它属于哪一层

## 运行环境和工程

| 术语 | 先怎么理解 |
|---|---|
| Node.js | 让 JavaScript 在服务器等环境运行 |
| npm | 安装包、管理依赖、执行 scripts |
| TypeScript | 给 JavaScript 增加静态类型检查 |
| module | 可以导入和导出的代码单元 |
| environment variable | 随运行环境变化的配置 |
| build | 把源码转换成可运行产物 |
| runtime | 程序真正执行时的环境 |

## HTTP 和 API

| 术语 | 先怎么理解 |
|---|---|
| HTTP | 客户端和服务器交换请求、响应的协议 |
| request | 客户端发给服务器的信息 |
| response | 服务器返回给客户端的信息 |
| method | 请求意图，如 GET、POST、PATCH、DELETE |
| URL | 请求资源的位置 |
| header | 请求或响应的附加信息 |
| body | 请求或响应携带的主要数据 |
| status code | 用数字表示请求结果类型 |
| JSON | 常用的文本数据格式 |
| API | 软件之间约定好的调用入口 |
| REST | 一种围绕资源和 HTTP 语义组织 API 的风格 |
| endpoint | 一个具体 API 方法和路径组合 |
| contract | 请求、响应和错误结构的约定 |

## Express

| 术语 | 先怎么理解 |
|---|---|
| Express | Node.js Web 框架 |
| app | 整个 Express 应用对象 |
| route | HTTP 方法和路径对应的处理入口 |
| router | 一组相关路由 |
| handler | 真正处理一次请求的函数 |
| middleware | 请求到达 handler 前后经过的公共处理函数 |
| controller | 把 HTTP 输入输出和业务调用连接起来 |
| service | 组织业务规则和事务 |
| repository | 集中处理数据库查询 |

## Next.js 服务端能力

| 术语 | 先怎么理解 |
|---|---|
| Server Component | 在服务器渲染，并且可以直接读取服务端数据的 React 组件 |
| Server Action | 由 Next.js 页面触发、在服务器执行的数据修改函数 |
| Route Handler | 用 `route.ts` 提供 GET、POST 等公开 HTTP endpoint |
| Backend for Frontend | 主要为当前前端整理数据、保护密钥和统一接口的后端层 |
| Custom Server | 放弃默认启动方式，自行控制 Next.js HTTP server 的特殊方案 |

## 数据库

| 术语 | 先怎么理解 |
|---|---|
| PostgreSQL | 关系型数据库管理系统 |
| SQL | 查询和修改关系型数据的语言 |
| database | 一组被数据库服务管理的数据 |
| schema | database 内进一步组织对象的命名空间 |
| table | 保存同一类结构化数据 |
| row | 表中的一条记录 |
| column | 一类字段 |
| primary key | 稳定且唯一识别一行 |
| foreign key | 约束一张表对另一张表的引用 |
| unique constraint | 保证字段或字段组合不重复 |
| JOIN | 查询时按关系组合多张表 |
| transaction | 让一组操作一起成功或失败 |
| migration | 可追踪地修改数据库结构 |
| connection pool | 复用有限数量的数据库连接 |
| pg | Node.js 连接 PostgreSQL 的驱动 |
| ORM | 用对象和 API 抽象数据库操作的工具 |

## 登录和安全

| 术语 | 先怎么理解 |
|---|---|
| authentication | 确认用户是谁 |
| authorization | 判断用户能做什么 |
| password hash | 不保存明文密码的单向处理结果 |
| Cookie | 浏览器按规则保存并随请求携带的小段数据 |
| HttpOnly | 阻止浏览器 JavaScript 读取 Cookie 的属性 |
| session | 服务器维护或验证的一段登录状态 |
| token | 用来证明身份或权限的数据 |
| CORS | 浏览器跨来源请求的访问规则 |
| CSRF | 借用用户已登录状态伪造敏感请求的攻击 |
| SQL injection | 把恶意输入混入 SQL 结构的攻击 |

## 测试和运行

| 术语 | 先怎么理解 |
|---|---|
| unit test | 验证一个小函数或规则 |
| integration test | 验证多层代码是否正确配合 |
| end-to-end test | 从用户入口验证完整流程 |
| Vitest | JavaScript / TypeScript 测试运行工具 |
| Supertest | 对 Node HTTP 服务进行接口断言的工具 |
| health check | 判断服务是否可用的轻量接口 |
| log | 记录运行过程和错误上下文 |
| deployment | 把应用放到目标环境稳定运行 |
| backup | 为数据准备可恢复副本 |

## 小结

遇到陌生术语时先问：

```text
它属于运行、HTTP、框架、数据库、身份、安全、测试还是部署？
```

先放回技术地图，再学习具体写法。
