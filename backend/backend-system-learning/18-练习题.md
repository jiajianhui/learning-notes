## 八、实践节点

### 节点 1：最小服务器

- 跑通健康检查。
- 返回内存文章数组。
- 用 Apifox 检查 200 和 404。

### 节点 2：真实数据库

- 建立 `articles` 表。
- 用参数化 SQL 完成创建和查询。
- 重启服务器后数据仍存在。

### 节点 3：真实业务

- 增加标签关系。
- 增加草稿、发布和分页。
- 测试重复 slug 和不存在文章。

### 节点 4：身份和产品界面

- 增加管理员登录。
- Next.js 后台完成文章管理流程。
- 未登录时不能写入数据。

### 节点 5：可靠性

- 自动化测试覆盖核心边界。
- 环境变量和迁移可重复。
- README 能指导新环境启动。

## 九、Next.js 后端判断

分别为下面场景选择 Server Component、Server Action、Route Handler 或独立 Express，并说明原因：

1. 个人网站服务器渲染已发布文章列表。
2. 当前 Next.js 网站提交联系表单。
3. 支付平台向固定 URL 发送付款 webhook。
4. Web、iOS 和 Android 都要长期调用同一套内容 API。
5. 浏览器需要通过服务器隐藏第三方 API key。
6. 后端需要独立部署并运行长期任务。

再回答：

1. 为什么 Server Component 读取数据库时通常不必请求自己的 Route Handler？
2. Server Action 为什么仍然需要认证和参数校验？
3. 为什么 Mini CMS 第一轮选择独立 Express，而不是纯 Next.js 全栈？
4. 为什么通常不建议把 Express 作为 custom server 套进 Next.js？
