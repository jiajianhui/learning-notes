# 14. 运行和部署：在自己电脑能跑还不是终点

## 问题背景

开发环境中可以同时开两个终端：

```text
Next.js：localhost:3000
Express：localhost:3001
PostgreSQL：localhost:5432
```

线上环境还要考虑域名、HTTPS、构建、环境变量、数据迁移和日志。

这一章先建立地图，不要求第一轮立刻掌握所有运维工具。

---

## 核心解释

### 1. 开发和生产是两套运行方式

开发环境重视：

- 热更新。
- 调试信息。
- 本地数据库。
- 快速修改。

生产环境重视：

- 稳定启动。
- HTTPS。
- 密钥安全。
- 日志和故障定位。
- 数据备份和迁移。

不能直接把开发服务器当作线上运行方式。

### 2. 后端要有明确构建和启动命令

```text
npm run dev
-> 开发时运行 TypeScript

npm run build
-> 编译并检查

npm run start
-> 运行生产构建
```

README 要写清楚 Node.js、环境变量、数据库和启动顺序。

### 3. 数据库变更要可重复

线上不能依赖“我记得自己手动建过哪些表”。

需要保存：

- 建表或迁移文件。
- 执行顺序。
- 回滚或修复方式。
- 备份策略。

代码版本和数据库结构必须能够对应。

### 4. 健康检查只回答服务是否可用

```text
GET /api/health
```

可以检查应用是否运行，必要时增加数据库连通性信息，但不要返回密码和内部配置。

### 5. 日志帮助定位线上问题

至少记录：

- 请求方法和路径。
- 响应状态码。
- 请求耗时。
- 未知错误的内部细节。

不要在日志中记录密码、完整 Cookie 和敏感密钥。

---

## 常见部署关系

```text
浏览器
-> HTTPS 域名
-> Next.js 管理后台
-> HTTPS API 域名
-> Express
-> 托管 PostgreSQL
```

前端和后端可以分别部署，也可以由同一平台管理，但它们的职责和环境变量仍然分开。

---

## Mini CMS 第一轮做到什么程度

主体完成时先保证：

- `.env.example` 完整。
- 真实 `.env` 不提交。
- `build`、`start`、`test` 命令可用。
- SQL 迁移有记录。
- 有 `/api/health`。
- 有基础请求和错误日志。
- README 能指导新环境启动。
- 数据库知道怎样备份。

Docker、自动扩缩容、消息队列和复杂监控以后按需求学习。

---

## 常见误区

- 线上继续使用开发服务器。
- 手动改数据库，却没有迁移记录。
- 把 `.env` 和真实密码提交到 Git。
- 日志只写“失败了”，没有请求和错误上下文。
- 健康检查返回数据库密码或完整配置。
- 没有备份就执行破坏性数据变更。
- 一开始学习大量部署工具，却还没有稳定 API。

---

## 小结

```text
开发环境帮助快速写代码
生产构建负责稳定运行
环境变量隔离配置和密钥
迁移保证数据库结构可追踪
日志和健康检查帮助发现问题
备份保护真正重要的数据
```

部署不是把代码上传一次，而是让系统能够安全、稳定、可重复地运行。
