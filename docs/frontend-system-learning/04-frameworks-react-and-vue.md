# 04 React 与 Vue：UI 框架层

> 所属层级：**第三层：UI 框架层**。

## 问题背景

当页面交互变复杂，直接操作 DOM 成本高、易混乱，于是出现了 UI 框架。

## 核心解释

### 为什么会出现 React / Vue
它们都在解决：
- 界面拆分复用（组件化）
- 状态变化驱动界面变化（数据驱动视图）
- 复杂 UI 的可维护性

### 组件化是什么
把页面拆成可复用单元（按钮、列表、弹窗、表单段落），通过组合构建界面。

### 声明式 UI 是什么
你描述“结果是什么”，框架处理“如何更新 DOM”。

## React 与 Vue 的共同点/差异

| 维度 | React | Vue |
|---|---|---|
| 核心定位 | UI 库/生态框架中心 | 渐进式框架 |
| 模板方式 | JSX/TSX | SFC（`App.vue`）+ 模板 |
| 心智模型 | 函数组件 + Hooks | 响应式系统 + 组合式 API |
| 生态路由 | React Router | Vue Router |

## 迁移视角：Vue -> React

可迁移：
- 组件化思想
- 单向数据流意识
- 状态与视图关系

需重建：
- JSX 语法心智
- Hooks 组织方式
- React 生态常见约定

## 学习建议

- 先选一个主线框架深入，再横向对比另一个
- 不要把框架 API 记忆当目标，重点是 UI 抽象能力

## 小结

React/Vue 在第三层，职责是“组织 UI”。它们不负责工程构建全流程，也不等于应用框架。
